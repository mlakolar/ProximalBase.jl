Interface reference

For mathematical meaning, Julia calling conventions, and allocation/return behavior, see Operations on functions. The docstrings describe generic declarations as well as concrete methods; consult the concrete guides for supported storage/argument combinations.

ProximalBase — Module
ProximalBase

Sparse iterate storage and mathematical functions with values, gradients and proximal operators. Mutating oracles take their output first. The convention is prox_{γf}(x) = argmin_z f(z) + ‖z-x‖²/(2γ).

source
ProximalBase.AbstractFunction — Type
AbstractFunction

Abstract supertype for mathematical functions with callable values, gradients and proximal operators. Declare issmooth, isproximable, isseparable and isconvex for the function's type. Mutating oracles take their output first.

Shapes, real element types and parameters are checked before predictable output writes. SymmetricSparseIterate parameters must be exactly symmetric at the pairs the kernel reads; custom separable functions declare entry_parameters. A failure during numerical computation may leave the output changed.

source
ProximalBase.SeparableFunction — Type
SeparableFunction

The supertype of the separable functions f(x) = Σᵢ fᵢ(xᵢ), and the way to add one of your own. A subtype implements, for the entry with linear index i,

  • prox_block(f, v, i, γ): the proximal operator of γfᵢ at the scalar v;
  • value_entry(f, v, i): the value fᵢ(v).

From these it gets the value f(x), prox! and value_and_prox! on any array, including the three iterates. Declare iszeropreserving when fᵢ(0) = 0 and the proximal operator maps 0 to 0; then the value and the proximal operator on a sparse iterate touch only its stored entries. isseparable and isproximable are true; declare isconvex when it holds.

Example

struct WeightedSquare <: SeparableFunction            # Σᵢ wᵢ xᵢ² / 2
    w::Vector{Float64}
end
ProximalBase.value_entry(f::WeightedSquare, v, i) = f.w[i] * v^2 / 2
ProximalBase.prox_block(f::WeightedSquare, v, i, γ) = v / (1 + γ * f.w[i])
ProximalBase.iszeropreserving(::WeightedSquare) = true
ProximalBase.isconvex(::Type{WeightedSquare}) = true
ProximalBase.entry_parameters(f::WeightedSquare) = (:w => f.w,)
function ProximalBase.check_parameters(f::WeightedSquare, x)
  length(f.w) == prod(size(x)) || throw(DimensionMismatch("a parameter array has length $(length(f.w)) and the argument has $(prod(size(x))) entries"))
  nothing
end

The generic kernels call check_parameters before writing any output or updating a coordinate; a SymmetricSparseIterate has a size and no length. On a SymmetricSparseIterate, also declare ProximalBase.entry_parameters; public oracle overrides should call ProximalBase.check_symmetric_parameters before writing.

See Symmetric parameters for which arrays must be symmetric and which calls check them.

Capabilities

ProximalBase.issmooth — Function
issmooth(f)

Whether f provides a gradient and valueandgradient! on the interior of its domain. Declare the trait on its type; the instance query forwards to it.

source
ProximalBase.isproximable — Function
isproximable(f)

Whether f has an efficient proximal operator, computed by prox! and value_and_prox!.

source
ProximalBase.isseparable — Function
isseparable(f)

Whether f(x) = Σᵢ fᵢ(xᵢ) is a sum over the entries of x. A separable f has the scalar proximal operators prox_block, and kkt_violation needs only the gradient.

source
ProximalBase.isconvex — Function
isconvex(f)

Whether f is convex. For a nonconvex f, prox! returns one of the minimizers that define the proximal operator, and accelerated methods such as FISTA lose their guarantees.

source
ProximalBase.iszeropreserving — Function
iszeropreserving(f)

Whether the separable function f has fᵢ(0) = 0 and prox_block(f, 0, i, γ) = 0 for every entry i and every positive finite step γ. Then sparse-iterate kernels may skip unstored zeros. This promises no standalone value oracle. It is false for non-separable functions and unless a function declares it. Wrappers forward it only where it holds for every entry and every positive finite step.

The promise holds in exact arithmetic: for parameters or steps so extreme that dense computations overflow (for example, a scale beyond floatmax(Float32) with a Float32 argument), paths over stored entries return exact zeros where dense results can be NaN.

It is a property of the function instance and its parameters.

source

Values, gradients and proximal maps

ProximalBase.gradient — Function
gradient(f, x)

Allocating version of gradient!; array arguments get dense floating output. Supported symmetric-iterate gradients (SqrNormL2, LinearFunction and supported Scaled leaves) return a dense symmetric Matrix. ZeroFunction has symmetric-iterate value/prox but no symmetric-iterate gradient method. Traits do not supply missing operand methods.

source
ProximalBase.gradient! — Function
gradient!(g, f, x)

Store the gradient of f at x in g and return g. g must not be x unless the function documents otherwise; built-in functions throw an ArgumentError. A SymmetricSparseIterate g receives the symmetric part of the gradient, the derivative over symmetric matrices.

source
ProximalBase.value_and_gradient — Function
value_and_gradient(f, x)

Allocating version of value_and_gradient!: returns (f(x), ∇f(x)).

source
ProximalBase.value_and_gradient! — Function
value_and_gradient!(g, f, x)

Store the gradient of f at x in g and return f(x). Usually cheaper than calling f(x) and gradient! separately. g must not be x unless the function documents otherwise; built-in functions throw an ArgumentError.

source
ProximalBase.prox — Function
prox(f, x, γ = 1)

Allocating version of prox!. For a supported SymmetricSparseIterate x the result is an independent SymmetricSparseIterate of the float element type, and γ is a scalar.

source
ProximalBase.prox! — Function
prox!(y, f, x, γ = 1)

Store the proximal operator

prox_{γf}(x) = argmin_z  f(z) + ‖z - x‖² / (2γ)

in y and return y. For a nonconvex f the result is one of the minimizers.

The output may be the argument itself: prox!(x, f, x, γ) works for every function. A SymmetricSparseIterate output takes a scalar step γ, the Frobenius proximal operator of the symmetric matrix; an array or per-group step is an ArgumentError before anything is written (use Matrix(x) or matrixview(x) with a dense output). Any other sharing of memory between y and x is not supported and is not detected, even when the two cover the same entries: a call such as prox!(view(x, :), f, x, γ), or with a shifted or reversed view of x, can return wrong values without an error. Copy the argument first, as in prox!(y, f, copy(x), γ). Supported operand shapes depend on the concrete function.

source
ProximalBase.value_and_prox! — Function
value_and_prox!(y, f, x, γ=1)

Store the proximal point in y and return the value at that stored result. Exact input/output aliasing is supported. Other shared-memory views are not supported. Shape and parameter checks precede writes; failures during numerical computation may leave output changed.

source
ProximalBase.value_entry — Function
value_entry(f, v, i)

For a SeparableFunction f(x) = Σᵢ fᵢ(xᵢ), the value fᵢ(v) of the term of entry i at the scalar v. i is a linear index of the array, as in prox_block.

source
ProximalBase.prox_block — Function

proxblock(f, v::Real, i::Integer, γ::Real) proxblock(f, u::AbstractVector, k::Integer, γ::Real)

Compute a pure mathematical proximal point at an already constructed trial. Scalar methods use the underlying array's global linear entry index i; retained built-ins are NormL1, SqrNormL2, LinearFunction, ZeroFunction and supported Scaled leaves. Custom SeparableFunction subtypes implement this scalar method together with value_entry. No iterate or cache is updated.

The vector form allocates a plain floating Vector of length(u) and delegates to a custom prox_block! implementation. Its group index and compact vector order are defined by that extension; no built-in group penalty remains. The generic wrapper supplies no group, shape, parameter or overlap validation. Implementing a block hook does not add a full-array prox or capability trait.

For symmetric iterate coordinate k, convert (r,c)=tril_cartesian(p,k) to full-entry i=(c-1)p+r for a scalar hook and validate the original function with ProximalBase.checksymmetricparameters before using raw entry calls.

source
ProximalBase.prox_block! — Function
prox_block!(out, f, u, k, γ)

Pure compact-vector block proximal extension hook. A conforming custom method writes the proximal point of its selected block into out and returns out. Buffers follow that block's compact ordered indices. There is no retained built-in implementation; the allocating vector prox_block delegates here.

The extension validates one-based real vectors, group bounds, exact lengths, parameters and supported step before predictable writes. Exact out===u is supported; other overlap must be rejected by the extension. Failed reads, conversions or user arithmetic may leave partial numerical output.

Caller precondition: out is independent of iterate storage and solver/model caches, including activevalues, coordinates and blockview aliases. Ownership is not inferred from buffer types. Compute in independent scratch, then write public storage and update caller caches separately. No activation occurs here.

source

Coordinates, bounds and caches

ProximalBase.kkt_violation — Function

kktviolation(f, g, i) kktviolation(f, g, x, k)

Signed screen of a coordinate assumed zero in h+f, with full smooth-part gradient g=∇h(x). A positive value means zero violates its condition; a nonpositive value checks zero only, not stationarity of a nonzero coordinate. NormL1 returns abs(g[i])-λ0*w[i]. Retained scalar screens also cover ZeroFunction, LinearFunction, SqrNormL2 and supported Scaled leaves.

For SparseIterate and SymmetricSparseIterate, the four-argument form checks real types, coordinate bounds (BoundsError), then full gradient entry count (DimensionMismatch): length(x) or p², respectively. A flat or matrix-shaped gradient of that count is accepted. The symmetric iterate uses the symmetric gradient pair and checks parameter symmetry at the chosen independent coordinate; opposing infinities in that gradient pair throw ArgumentError.

For BlockIterate, k is a group and retained scalar-screen functions return the maximum screen over its ordered global entry indices. That path does not add the same explicit full-gradient extent preflight. Other array points add no coordinate/gradient extent check beyond function/indexing checks. Raw three-argument calls have no symmetric iterate on which to validate mirrored parameters.

source
ProximalBase.restrict — Function
restrict(f,S)

Restrict a retained function's entry parameters to the integer index vector S. NormL1 slices weights, centered SqrNormL2 slices its center, LinearFunction slices coefficients, QuadraticFunction selects its principal submatrix and linear term, vector-response LeastSquaresLoss selects design columns, and Scaled forwards. For least squares and quadratics, omitted coordinates are fixed at zero. Centered SqrNormL2 drops the omitted-coordinate constant λ*sum(y[j]^2)/2; when finite, it changes values but not restricted minimizers/gradients/prox. Add it back for full-value comparisons. A nonzero fixed point needs separately derived residual/linear terms. Raw restriction has no iterate on which to validate symmetric per-entry parameters; validate the original function before using the result in a coordinate routine.

source
ProximalBase.lipschitz — Function
lipschitz(f)

A global gradient Lipschitz bound for retained smooth functions. ZeroFunction and LinearFunction return zero; SqrNormL2 returns its level. QuadraticFunction uses a matrix operator-norm bound; LeastSquaresLoss bounds the squared design norm. Dense matrices use their full spectral norm; other matrices use a safe one/infinity norm bound. Scaled scales the inner bound. Unknown bounds throw. The separate opnorm2 estimate may miss a leading eigenspace and needs an independent bound or backtracking when choosing a step.

source
ProximalBase.opnorm2 — Function
opnorm2(X)

Estimate the squared spectral norm ‖X‖₂² by Lanczos iteration, using only products with X and its adjoint, without forming a Gram matrix or densifying a sparse matrix. The result has floating element type matching X.

This is a numerical estimate, not a certified upper bound: Lanczos can miss an eigenspace orthogonal to its deterministic starting vector. Algorithms requiring a guaranteed bound should use an independently known bound (for example opnorm(X, 1) * opnorm(X, Inf)) or a suitable line search.

source
ProximalBase.reset_cache! — Function
reset_cache!(f)

Invalidate data-dependent caches after changing entries of LeastSquaresLoss X or Y, or QuadraticFunction A, stored by reference. Array sizes must stay unchanged; construct a new function for different dimensions. The next proximal call rebuilds the decomposition. Values and gradients read data directly. Call this on the outermost Scaled wrapper. Functions without caches return themselves; custom functions with derived data should implement this hook.

Qualified extension validation

These supported names are public but not exported. Custom public-oracle overrides must implement their own checked boundary; declaring traits alone does not run validation. See extending.

ProximalBase.check_parameters — Function
ProximalBase.check_parameters(f, x)

Check that the parameters of f fit the argument x. Throw DimensionMismatch when they do not. The default for an AbstractFunction returns nothing. Define this method for a function with parameter arrays; the generic kernels call it before writing any output, including x when the output aliases it.

For a SeparableFunction WeightedSquare with a weight vector w:

function ProximalBase.check_parameters(f::WeightedSquare, x)
  length(f.w) == prod(size(x)) || throw(DimensionMismatch("a parameter array has length $(length(f.w)) and the argument has $(prod(size(x))) entries"))
  nothing
end
source
ProximalBase.entry_parameters — Function
ProximalBase.entry_parameters(f)

Declare the per-entry parameters of f as a tuple of name => value pairs, for example (:w => f.w,). Include arrays indexed like the argument; nothing and scalar numbers are skipped. Other values throw ArgumentError. Declare () when there are none. Each user SeparableFunction must supply this method to work on a SymmetricSparseIterate; its default is nothing (undeclared). The declaration must include every per-entry array. It describes only f itself, not the functions inside its wrappers.

The generic array and coordinate oracles check these parameters automatically. An override of a public oracle replaces that boundary and should call ProximalBase.check_symmetric_parameters when accepting a symmetric iterate. Built-in wrappers also check their inner functions before writing. Raw entry oracles and restrict have no iterate to check; validate the original function before using them.

See Symmetric parameters for which arrays must be symmetric and which calls check them.

source
ProximalBase.check_symmetric_parameters — Function
ProximalBase.check_symmetric_parameters(f,x)

Validate caller-supplied per-entry parameters on a symmetric iterate. Arrays must be exactly symmetric at off-diagonal pairs; malformed or undeclared custom separable parameter metadata throws ArgumentError. Built-in public oracles call their relevant checks before writes. Other iterates return true.
