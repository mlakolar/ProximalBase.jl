Interface reference

ProximalBase — Module
ProximalBase

Building blocks for proximal, coordinate-descent and active-set methods: functions with gradients and proximal operators, and sparse iterates.

A function f is callable, f(x) being its value, and its traits say what it provides: issmooth functions have gradient! and value_and_gradient!, isproximable ones prox! and value_and_prox!, and isseparable ones the scalar proximal operators prox_entry, with which prox_coordinate! updates one coordinate of an iterate. A function may be both smooth and proximable.

Proximal operators follow the convention

prox_{γf}(x) = argmin_z  f(z) + ‖z - x‖² / (2γ),

and mutating functions take their output first, as mul! does: prox!(y, f, x, γ), gradient!(g, f, x), prox_coordinate!(x, f, k, γ).

ProximalBase.AbstractFunction — Type
AbstractFunction

Abstract supertype of the functions of ProximalBase: losses, penalties and indicator functions. A function f is callable: f(x) is its value, Inf outside its domain. Its traits say which oracles it provides:

TraitOracles
issmoothgradient!, value_and_gradient!
isproximableprox!, value_and_prox!
isseparableprox_entry, and prox_coordinate! on every iterate

A function can have several roles: SqrNormL2, QuadraticFunction, LeastSquaresLoss and LogDetLoss are both smooth and proximable. isconvex tells a solver whether convex theory applies.

To add a function, subtype AbstractFunction, make it callable, declare its traits for its type, as in ProximalBase.issmooth(::Type{<:MyLoss}) = true, and implement the oracles of those traits.

ProximalBase.gradient_mapping — Function
gradient_mapping!(G, f, g, x, γ)
gradient_mapping(f, g, x, γ)

The gradient mapping G = (x - prox_{γg}(x - γ∇f(x))) / γ of the problem minimize f(x) + g(x), for a smooth f and a proximable g. When f and g are convex it is zero exactly at the minimizers, for every γ > 0; with g = 0 it is ∇f(x). Its norm is a stopping rule that needs neither the optimal value nor the structure of g, and a proximal gradient step from x is x - γG. G must not be x; gradient_mapping! allocates nothing beyond what gradient! and prox! do.

ProximalBase.isconvex — Method
isconvex(f)

Whether f is convex. For a nonconvex f, prox! returns one of the minimizers that define the proximal operator, and accelerated methods such as FISTA lose their guarantees.

ProximalBase.isproximable — Method
isproximable(f)

Whether f has an efficient proximal operator, computed by prox! and value_and_prox!.

source
ProximalBase.isseparable — Method
isseparable(f)

Whether f(x) = Σᵢ fᵢ(xᵢ) is a sum over the entries of x. A separable f has the scalar proximal operators prox_entry, with which prox_coordinate! updates a coordinate of any iterate, and kkt_violation needs only the gradient.

source
ProximalBase.issmooth — Method
issmooth(f)

Whether f is differentiable on the interior of its domain, with gradient! and value_and_gradient!. The gradient need not be globally Lipschitz: LogDetLoss is smooth on the positive definite matrices, and its value is Inf elsewhere.

source
ProximalBase.kkt_violation — Function
kkt_violation(f, g, i)
kkt_violation(f, g, x, k)

How much a coordinate at zero violates the optimality conditions of h + f, where g = ∇h(x) is the gradient of the smooth part: a positive value means that moving the coordinate away from zero decreases the objective, and a value ≤ 0 that zero is optimal. For NormL1 it is |gᵢ| - λ0 wᵢ.

For a separable f the condition involves only gᵢ, and the first form suffices. The second form takes a coordinate k of the point x: for a GroupNormL2, the condition of an index involves the rest of its group, and on an AtomIterate k is a group, whose violation is ‖g[Gₖ]‖₂ - λ0 wₖ (for a separable f, the largest over the group).

source
ProximalBase.lipschitz — Method
lipschitz(f)

A Lipschitz constant L of the gradient of the smooth function f, so that a gradient or proximal gradient step with step 1/L decreases the objective. It is exact for the closed forms (SqrNormL2(λ) gives λ); for a loss of a matrix it is the largest eigenvalue involved, such as ‖X‖₂² for LeastSquaresLoss, computed by the Lanczos process with products by X and X' only, to a relative accuracy of 1e-10 and from below. It is Inf for a smooth function whose gradient is not globally Lipschitz, such as LogDetLoss and PoissonLoss, which call for a line search, and an error for a function that is not smooth. Sums add the constants, Scaled scales them, and SeparableSum takes their maximum.

ProximalBase.prox! — Function
prox!(y, f, x, γ = 1)

Store the proximal operator

prox_{γf}(x) = argmin_z  f(z) + ‖z - x‖² / (2γ)

in y and return y. y may be x. For a nonconvex f the result is one of the minimizers.

source
ProximalBase.prox_coordinate! — Function
prox_coordinate!(x, f, k, γ)

Apply the proximal operator of γf to coordinate k of the iterate x in place, as in one step of coordinate descent, and return the new value of the coordinate. The coordinates of a SparseIterate are its entries, those of a SymmetricSparseIterate the entries of its lower triangle, and those of an AtomIterate its groups, for which prox_coordinate! returns a view of the group (see ncoordinates).

A separable f updates any coordinate through prox_entry; a group penalty such as GroupNormL2 updates a group of an AtomIterate that shares its groups. A coordinate that stays zero does not become stored or active; one that becomes nonzero does.

source
ProximalBase.prox_entry — Function
prox_entry(f, v, i, γ)

For a separable f(x) = Σᵢ fᵢ(xᵢ) (see isseparable), the proximal operator of γfᵢ at the scalar v: the value that a coordinate-descent step gives entry i when the gradient step lands at v. i is a linear index of the array, so that weights and bounds may depend on the entry; for a SymmetricSparseIterate, entry (r, c) has index (c - 1)p + r. It touches no iterate: prox_coordinate! updates a coordinate of one in place.

source
ProximalBase.restrict — Function
restrict(f, S)

The function of x[S] that f becomes on the vectors x supported on the coordinates S, as a function of the same kind: an active-set solver minimizes the restriction over the active coordinates S. At x[S] the restriction has the value f(x) and the gradient ∇f(x)[S], except that SqrNormL2 with a center y drops the constant Σⱼ∉S yⱼ².

value_and_gradient(f, x)

ProximalBase.value_and_prox! — Function
value_and_prox!(y, f, x, γ = 1)

Store prox_{γf}(x) in y, as prox! does, and return f(y), the value at the result. Many functions get the value from the computation of the proximal operator: a nuclear norm from the singular values that it thresholds, an indicator function as 0. This is then cheaper than prox! followed by f(y), and solvers that track the objective should call it.

Separable functions

ProximalBase.SeparableFunction — Type
SeparableFunction

The supertype of the separable functions f(x) = Σᵢ fᵢ(xᵢ), and the way to add one of your own. A subtype implements, for the entry with linear index i,

  • prox_entry(f, v, i, γ): the proximal operator of γfᵢ at the scalar v;
  • value_entry(f, v, i): the value fᵢ(v).

From these it gets the value f(x), prox! and value_and_prox! on any array, and prox_coordinate! on the three iterates. Declare iszeropreserving when fᵢ(0) = 0 and the proximal operator maps 0 to 0; then the value and the proximal operator on a sparse iterate touch only its stored entries. isseparable and isproximable are true; declare isconvex when it holds.

Example

struct WeightedSquare <: SeparableFunction            # Σᵢ wᵢ xᵢ² / 2
    w::Vector{Float64}
end
ProximalBase.value_entry(f::WeightedSquare, v, i) = f.w[i] * v^2 / 2
ProximalBase.prox_entry(f::WeightedSquare, v, i, γ) = v / (1 + γ * f.w[i])
ProximalBase.iszeropreserving(::WeightedSquare) = true
ProximalBase.isconvex(::Type{WeightedSquare}) = true

ProximalBase.value_entry — Function
value_entry(f, v, i)

For a SeparableFunction f(x) = Σᵢ fᵢ(xᵢ), the value fᵢ(v) of the term of entry i at the scalar v. i is a linear index of the array, as in prox_entry.

source
ProximalBase.iszeropreserving — Function
iszeropreserving(f)

Whether the separable function f has fᵢ(0) = 0 and maps 0 to 0 by its proximal operator, prox_entry(f, 0, i, γ) = 0, for every entry i and step γ, as norms and most penalties do. Then the value and the proximal operator on a sparse iterate touch only its stored entries. It is false unless a function declares it, and it is a property of the function, not of its type: the bounds of an IndBox may exclude zero.
