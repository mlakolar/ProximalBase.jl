Interface reference

For mathematical meaning, Julia calling conventions, and allocation/return behavior, see Operations on functions. The docstrings describe generic declarations as well as concrete methods; consult the concrete guides for supported storage/argument combinations.

ProximalBase — Module
ProximalBase

Sparse iterate storage and mathematical functions with values, gradients and proximal operators. Mutating oracles take their output first. The convention is prox_{γf}(x) = argmin_z f(z) + ‖z-x‖²/(2γ).

source
ProximalBase.AbstractFunction — Type
AbstractFunction

Supertype for mathematical functions with callable values, gradients and proximal operators. Declare capabilities with issmooth, isproximable, isseparable and isconvex. Mutating operations put the output first.

Built-in operations check supported real types, one-based axes, shapes and parameter extents before predictable writes. Numerical failures can leave partial output. Custom public methods must provide their own validation.

On a SymmetricSparseIterate, per-entry weights, centers and coefficients must be exactly symmetric. Oracles assume this model precondition; validate it with ProximalBase.check_symmetric_parameters. Custom separable functions declare their arrays with ProximalBase.entry_parameters.

See operations and array, precision and ownership conventions.

source
ProximalBase.SeparableFunction — Type
SeparableFunction

The supertype of the separable functions f(x) = Σᵢ fᵢ(xᵢ), and the way to add one of your own. A subtype implements, for the entry with linear index i,

  • prox_block(f, v, i, γ): the proximal operator of γfᵢ at the scalar v;
  • value_entry(f, v, i): the value fᵢ(v).

From these it gets the value f(x), prox! and value_and_prox! on any array, including the three iterates. Declare iszeropreserving when fᵢ(0) = 0 and the proximal operator maps 0 to 0; then the value and the proximal operator on a sparse iterate touch only its stored entries. isseparable and isproximable are true; declare isconvex when it holds.

Example

struct WeightedSquare <: SeparableFunction            # Σᵢ wᵢ xᵢ² / 2
    w::Vector{Float64}
end
ProximalBase.value_entry(f::WeightedSquare, v, i) = f.w[i] * v^2 / 2
ProximalBase.prox_block(f::WeightedSquare, v, i, γ) = v / (1 + γ * f.w[i])
ProximalBase.iszeropreserving(::WeightedSquare) = true
ProximalBase.isconvex(::Type{WeightedSquare}) = true
ProximalBase.entry_parameters(f::WeightedSquare) = (:w => f.w,)
function ProximalBase.check_parameters(f::WeightedSquare, x)
  length(f.w) == prod(size(x)) || throw(DimensionMismatch("a parameter array has length $(length(f.w)) and the argument has $(prod(size(x))) entries"))
  nothing
end

The generic kernels call check_parameters before writing any output or updating a coordinate; a SymmetricSparseIterate has a size and no length. On a SymmetricSparseIterate, the parameter arrays must be exactly symmetric, which the kernels assume and do not compare; also declare ProximalBase.entry_parameters, so that ProximalBase.check_symmetric_parameters can validate the model once, before the first oracle call.

See symmetric parameters for the required arrays and validation responsibilities.

Capabilities

ProximalBase.issmooth — Function
issmooth(f)

Whether f provides gradient and value_and_gradient! on the interior of its domain. Declare the trait on its type; the instance query forwards to it.

source
ProximalBase.isproximable — Function
isproximable(f)

Whether f has an efficient proximal operator, computed by prox! and value_and_prox!.

source
ProximalBase.isseparable — Function
isseparable(f)

Whether f(x) = Σᵢ fᵢ(xᵢ) is a sum over the entries of x. A separable f has the scalar proximal operators prox_block, and kkt_violation needs only the gradient.

source
ProximalBase.isconvex — Function
isconvex(f)

Whether f is convex. true means the type guarantees convexity for every instance that satisfies its documented preconditions. false means convexity is not guaranteed; some instances may still be convex, for example a QuadraticFunction with a positive semidefinite matrix. For a nonconvex f, prox! returns one of the minimizers that define the proximal operator, and accelerated methods such as FISTA lose their guarantees.

source
ProximalBase.iszeropreserving — Function
iszeropreserving(f)

Whether the separable function f has fᵢ(0) = 0 and prox_block(f, 0, i, γ) = 0 for every entry i and every positive finite step γ. Then sparse-iterate kernels may skip unstored zeros. This promises no standalone value oracle. It is false for non-separable functions and unless a function declares it. Wrappers forward it only where it holds for every entry and every positive finite step.

The promise holds in exact arithmetic: for parameters or steps so extreme that dense computations overflow (for example, a scale beyond floatmax(Float32) with a Float32 argument), paths over stored entries return exact zeros where dense results can be NaN.

It is a property of the function instance and its parameters.

Values, gradients and proximal maps

ProximalBase.gradient — Function
gradient(f, x)

Return a newly allocated gradient. Array inputs produce a dense floating-point array with the same shape; see gradient! to reuse an output buffer.

Supported symmetric-iterate gradients (SqrNormL2, LinearFunction and supported Scaled leaves) produce a dense symmetric matrix. ZeroFunction has no symmetric-iterate gradient method. A capability trait does not supply missing operand methods.

Examples

julia> Tuple(gradient(SqrNormL2(0.5), [2.0, -4.0]))
(1.0, -2.0)
source
ProximalBase.gradient! — Function
gradient!(g, f, x)

Write the gradient of f at x into g and return g.

Use a destination with the supported shape of x and independent storage. Built-in functions reject g === x with ArgumentError; other overlapping views are unsupported. Numerical failures can leave a partially written destination. For supported methods, a SymmetricSparseIterate destination receives the symmetric part of the gradient, the derivative over symmetric matrices.

See gradient for an allocating call and value_and_gradient! to obtain the value in the same call.

source
ProximalBase.value_and_gradient — Function
value_and_gradient(f, x)

Return (f(x), ∇f(x)), allocating the gradient as gradient does. To reuse a destination, call value_and_gradient!.

Examples

julia> value, grad = value_and_gradient(SqrNormL2(1.0), [2.0, -1.0]);

julia> (value, Tuple(grad))
(2.5, (2.0, -1.0))
source
ProximalBase.value_and_gradient! — Function
value_and_gradient!(g, f, x)

Write the gradient into g and return the value at the input x. The return value is a scalar, not (value, g).

The destination must be independent of the input and have its supported shape. Built-in functions reject g === x; other overlapping views are unsupported. As with gradient!, numerical failures can leave partial output.

Examples

julia> g = zeros(2); v = value_and_gradient!(g, SqrNormL2(1.0), [2.0, -1.0]);

julia> (v, Tuple(g))
(2.5, (2.0, -1.0))
source
ProximalBase.prox — Function
prox(f, x, γ = 1)

Return a newly allocated proximal point; see prox! for the definition and step restrictions. Array results use floating-point element types. Symmetric/Hermitian array wrappers produce a dense matrix. Supported SymmetricSparseIterate calls produce an independent symmetric iterate and require a scalar step.

Examples

julia> Tuple(prox(NormL1(0.5), [2.0, -1.0], 1.0))
(1.5, -0.5)
source
ProximalBase.prox! — Function
prox!(y, f, x, γ = 1)

Write the proximal point of f at x into y and return y. For γ > 0, this minimizes f(z) + ‖z-x‖²/(2γ) over z. A nonconvex function may have several minimizers; a supported method returns one.

y must have the supported shape of x. Exact in-place use, prox!(x, f, x, γ), is supported. Other overlapping inputs and outputs, including distinct views of the same entries, are unsupported and generally undetected; copy the input first. A supported symmetric-iterate destination uses the Frobenius metric and accepts only a scalar step; array or per-group steps throw ArgumentError before writes. To use array steps with a symmetric iterate, use a dense output and pass Matrix(x) or matrixview(x).

Use positive finite steps for the mathematical proximal map. Validation and zero/non-finite endpoints depend on the function; see the Numerical contract. For a new output use prox; for the value at the stored output use value_and_prox!.

source
ProximalBase.value_and_prox! — Function
value_and_prox!(y, f, x, γ = 1)

Write the proximal point into y and return f(y) at the stored output, including its rounding. The return value is a scalar, not (value, y).

Exact y === x is supported; other overlapping views are unsupported. Predictable shape and parameter checks precede writes, but a numerical failure can leave partial output. Step and storage restrictions are those of prox! and the concrete function.

Examples

julia> y = zeros(2); v = value_and_prox!(y, NormL1(0.5), [2.0, -1.0], 1.0);

julia> (v, Tuple(y))
(1.0, (1.5, -0.5))
source
ProximalBase.value_entry — Function
value_entry(f, v, i)

For a SeparableFunction f(x) = Σᵢ fᵢ(xᵢ), the value fᵢ(v) of the term of entry i at the scalar v. i is a linear index of the array, as in prox_block.

source
ProximalBase.prox_block — Function
prox_block(f, v::Real, i::Integer, γ::Real)
prox_block(f, u::AbstractVector, k::Integer, γ::Real)

Compute a proximal point for one entry or compact block at the supplied trial, without changing an iterate, active set or solver cache.

The scalar form uses the global linear entry index i to select parameters. It is implemented by NormL1, NormL1Nonneg, ElasticNet, SqrNormL2, LinearFunction, ZeroFunction and supported Scaled leaves. A custom SeparableFunction implements it together with value_entry.

The vector form allocates a plain floating Vector of length(u) and calls prox_block!. GroupNormL2 interprets k as its group number and u in that group's order. Custom methods define their own layout and must validate it; the allocating wrapper adds no group, shape, parameter or overlap checks. A block method alone does not supply full-array operations or traits.

For symmetric coordinate k, convert (r,c) = tril_cartesian(p,k) to the full-entry index i = (c-1)*p+r. Validate the original model with ProximalBase.check_symmetric_parameters before raw entry calls.

Examples

julia> prox_block(NormL1(0.5), 2.0, 1, 1.0)
1.5

See coordinate and block operations.

source
ProximalBase.prox_block! — Function
prox_block!(out, f, u, k, γ)

Write the proximal point of compact block k into out and return out. GroupNormL2 supplies the built-in implementation; custom functions can implement this hook. Buffers follow the selected group's ordered indices.

A conforming method validates real one-based vectors, group bounds, exact lengths, parameters and the supported step before predictable writes. Exact out === u is supported; other overlap must be rejected by the implementation. Failed reads, conversions or numerical computations may leave partial output.

Caller precondition: out must be independent of iterate storage and solver/model caches, including activevalues, coordinates and blockview aliases. Buffer types do not establish ownership. Compute in independent scratch, then commit with a public storage writer and update caches separately. This operation never activates an iterate coordinate.

See compact block buffers for the full extension contract.

Coordinates, bounds and caches

ProximalBase.kkt_violation — Function
kkt_violation(f, v, i)
kkt_violation(f, v, x, k)
kkt_violation(f, v, x)

Return a first-order optimality score of h + f from a vector v that the caller supplies, usually ∇h(x); v is not recomputed. The score is raw: no scaling, tolerance or stopping rule is applied, and it concerns stationarity, not global optimality.

  • kkt_violation(f, v, i) is the signed screen of coordinate i assumed zero. It reads no x. A positive value means that zero violates its condition.
  • kkt_violation(f, v, x, k) is the score of the actual coordinate k of x (group k of a BlockIterate): the signed margin at a zero coordinate, and a nonnegative mismatch of stationarity at a nonzero one. A positive mismatch is not an instruction to set the coordinate to zero. Since 0.6 this form reads x: at a nonzero coordinate it does not return the screen.
  • kkt_violation(f, v, x) is max(0, max_k score_k), nonnegative, and zero of the working type for an empty x.

With cᵢ = λ0*wᵢ (λ1*wᵢ for ElasticNet), the scores of entry i at xᵢ = 0 and at xᵢ ≠ 0 are, for the six functions that have all three forms:

  • NormL1: abs(vᵢ) - cᵢ and abs(vᵢ + cᵢ*sign(xᵢ)).
  • NormL1Nonneg: for finite inputs, -vᵢ - cᵢ at xᵢ = 0, and at xᵢ ≠ 0 abs(vᵢ + cᵢ) for xᵢ > 0 and Inf for xᵢ < 0, which is outside the domain x ≥ 0.
  • ElasticNet: abs(vᵢ) - cᵢ (-Inf for an infinite ridge level) and abs((vᵢ + λ2*xᵢ) + cᵢ*sign(xᵢ)).
  • ZeroFunction: abs(vᵢ) in both cases.
  • LinearFunction: abs(vᵢ + cᵢ) in both cases, with cᵢ its coefficient entry.
  • SqrNormL2: abs(vᵢ + dᵢ) in both cases, with dᵢ the entry λ*xᵢ or λ*(xᵢ - yᵢ) of the gradient at x, computed in the working type of the call. The screen kkt_violation(f, v, i) takes xᵢ = 0 and does not use it.

GroupNormL2 and NormL2 score a block G with c = λ*w_G (c = λ for NormL2, whose block is all of x): norm(v_G) - c at a zero block and norm(v_G + c*x_G/norm(x_G)) at a nonzero one. The block of the entry k of an array is its group (an entry in no group scores abs(vₖ)), and for a BlockIterate it is group k, whose layout must be that of f. The value of kkt_violation(f, v, x) is then a maximum of block 2-norms and of those entries, not a global ∞-norm. NormL2 has a full-point form, and its forms for an entry or a group, and those of GroupNormL2 at a SymmetricSparseIterate, throw an ArgumentError. At a nonzero block, in the ordinary range of the squares, the error is at most (n + 8)*u*(norm(v_G) + c) to first order in n*u, with n the size of the block and u = eps(W)/2 for the working type W of v and x; outside that range the sums are scaled by an exponent, which extends the range and not the precision.

Scaled with a finite positive factor α evaluates the existing score of its function (the functions above; NormL2 in the full-point form) on the lazy gradient v/α, with the rounding and range limits of that evaluation, and multiplies it by α; underflow, overflow and NaN are not recovered. For a chain of wrappers whose factors do not multiply to a normal number, the product is applied to the gradient of LinearFunction and SqrNormL2 (the three-argument form too), and folded into the level of the other functions where that gives a normal level. Where it does not, the three-argument form and a zero coordinate or group have a value, and a nonzero point and the full-point form throw an ArgumentError. So does an infinite factor at a nonzero point and in the full-point form. A function of this package without a score gives a MethodError under Scaled. A function defined outside this package gets its three-argument value at a zero coordinate and an ArgumentError at a nonzero one, unless it defines the method. Under Scaled it has its scaled three-argument value and that error also when it defines a four-argument method of its own, because PB does not know that its score scales with α: a method for Scaled{<:T} supplies the scaled forms.

Examples

julia> kkt_violation(NormL1(0.5), [0.75, 0.25], 1)
0.25

julia> g = NormL1(0.5); x = [0.0, 0.0, 2.0, -1.0]; v = [0.8, 0.2, 0.0, 0.5];

julia> kkt_violation(g, v, 3)  # the screen assumes x[3] = 0
-0.5

julia> kkt_violation(g, v, x, 3)  # x[3] = 2 is read: a mismatch
0.5

julia> kkt_violation(g, v, x)
0.5

Storage-specific checks, element types, non-finite values and the extension rules are in scoring a coordinate and the numerical contract.

ProximalBase.restrict — Function
restrict(f, S)

Restrict a retained function's entry parameters to the integer index vector S. NormL1, NormL1Nonneg and ElasticNet slice weights, centered SqrNormL2 slices its center, LinearFunction slices coefficients, QuadraticFunction selects its principal submatrix and linear term, vector-response LeastSquaresLoss selects design columns, and Scaled forwards. For least squares and quadratics, omitted coordinates are fixed at zero. Centered SqrNormL2 drops the omitted-coordinate constant λ*sum(y[j]^2)/2; when finite, it changes values but not restricted minimizers/gradients/prox. Add it back for full-value comparisons. A nonzero fixed point needs separately derived residual/linear terms. Raw restriction has no iterate on which to validate symmetric per-entry parameters; validate the original function before using the result in a coordinate routine.

source
ProximalBase.lipschitz — Function
lipschitz(f)

A global gradient Lipschitz bound for retained smooth functions. ZeroFunction and LinearFunction return zero; SqrNormL2 returns its level. QuadraticFunction uses a matrix operator-norm bound; LeastSquaresLoss bounds the squared design norm. Dense matrices use their full spectral norm; other matrices use a safe one/infinity norm bound. Scaled scales the inner bound. Unknown bounds throw. The separate opnorm2 estimate may miss a leading eigenspace and needs an independent bound or backtracking when choosing a step.

source
ProximalBase.opnorm2 — Function
opnorm2(X)

Estimate the squared spectral norm ‖X‖₂² by Lanczos iteration, using only products with X and its adjoint, without forming a Gram matrix or densifying a sparse matrix. The result has floating element type matching X.

This is a numerical estimate, not a certified upper bound: Lanczos can miss an eigenspace orthogonal to its deterministic starting vector. Algorithms requiring a guaranteed bound should use an independently known bound (for example opnorm(X, 1) * opnorm(X, Inf)) or a suitable line search.

source
ProximalBase.reset_cache! — Function
reset_cache!(f)

Invalidate data-dependent caches after changing entries of LeastSquaresLoss X or Y, or QuadraticFunction A, stored by reference. Array sizes must stay unchanged; construct a new function for different dimensions. The next proximal call rebuilds the decomposition. Values and gradients read data directly. Call this on the outermost Scaled wrapper. Functions without caches return themselves; custom functions with derived data should implement this hook.

Qualified extension validation

These supported names are public but not exported. Custom public-oracle overrides must implement their own checked boundary; declaring traits alone does not run validation. See extending.

ProximalBase.check_parameters — Function
ProximalBase.check_parameters(f, x)

Check that the parameters of f fit the argument x. Throw DimensionMismatch when they do not. The default for an AbstractFunction returns nothing. Define this method for a function with parameter arrays; the generic kernels call it before writing any output, including x when the output aliases it.

For a SeparableFunction WeightedSquare with a weight vector w:

function ProximalBase.check_parameters(f::WeightedSquare, x)
  length(f.w) == prod(size(x)) || throw(DimensionMismatch("a parameter array has length $(length(f.w)) and the argument has $(prod(size(x))) entries"))
  nothing
end
source
ProximalBase.entry_parameters — Function
ProximalBase.entry_parameters(f)

Declare the per-entry parameters of f as a tuple of name => value pairs, for example (:w => f.w,). Include arrays indexed like the argument; nothing and scalar numbers are skipped. Other values throw ArgumentError. Declare () when there are none. Each user SeparableFunction must supply this method to work on a SymmetricSparseIterate; its default is nothing (undeclared). The declaration must include every per-entry array. It describes only f itself, not the functions inside its wrappers.

Within ProximalBase, only ProximalBase.check_symmetric_parameters reads this declaration. The numerical oracles do not compare mirrored entries of these arrays: the caller or solver validates the model, and an oracle given asymmetric parameters has no guaranteed numerical meaning. Built-in wrappers expose their inner function's arrays to the checker. Raw entry oracles and restrict have no iterate; validate the original function before using them.

See symmetric parameters for the arrays to declare and the model validation boundary.

source
ProximalBase.check_symmetric_parameters — Function
ProximalBase.check_symmetric_parameters(f, x)

Validate caller-supplied per-entry parameters on a symmetric iterate. Every declared array must be exactly symmetric at every off-diagonal pair, including pairs the iterate does not store, recursively through Scaled; an asymmetric array, or malformed or undeclared custom separable parameter metadata, throws ArgumentError. Arrays symmetric by type, such as Symmetric(W, :L), pass. Other iterates return true.

The numerical oracles never call this check: validate the model at the solve or workspace boundary, and again after changing a parameter array. A successful check is not recorded anywhere and is not a replacement for check_parameters or the shape checks of the oracles.
