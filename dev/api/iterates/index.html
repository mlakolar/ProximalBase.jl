Iterate and utility reference

The storage overview distinguishes entries, independent symmetric variables, groups and active slots. The product domain table documents supported Base/LinearAlgebra methods in addition to the named operations below.

Storage types

ProximalBase.SparseIterate — Type
SparseIterate([T = Float64,] n)
SparseIterate([T = Float64,] n, m)
SparseIterate(x::Union{SparseVector, SparseMatrixCSC, Array})

A real vector or matrix with a working set of explicitly stored coordinates. Each coordinate is a Julia linear entry index. Reading or writing an entry costs O(1); reserved storage costs O(length(x)), even when few entries are active.

A nonzero write activates its coordinate. A zero write preserves existing activity; activate! stores an explicit zero and dropzeros!(::Union{SparseIterate, SymmetricSparseIterate}) removes active zeros. nactive counts stored coordinates, including zeros. coordinates exposes all entries, while activecoordinates and activevalues expose the working set.

Examples

julia> x = SparseIterate(4); x[2] = 3; activate!(x, 4);

julia> (ncoordinates(x), nactive(x), x[4])
(4, 2, 0.0)

julia> x[2] = 0; dropzeros!(x); nactive(x)
0

Write semantics

  • copyto!(x, y) replaces working-set state when y is a same-size SparseIterate; ordinary array copies and broadcasts write values.
  • Direct bulk writes reject known complex source types before writing. Views, indexed writes and per-element conversions can fail after partial writes. See write validation.
  • Only documented product methods traverse active entries; views use ordinary array operations.

See the storage guide for copies, operation costs and writing from an orthogonal factor.

source
ProximalBase.SymmetricSparseIterate — Type
SymmetricSparseIterate([T = Float64,] p)
SymmetricSparseIterate(A::AbstractMatrix)

Store the $p(p+1)/2$ independent variables of a real symmetric $p × p$ matrix, with O(1) access and O(p²) reserved storage.

This object is not an AbstractArray. Read or write a matrix entry with x[i,j]; both triangles address the same variable. Use coordinates for a writable lower-triangle vector in column-major order, matrixview for a read-only live matrix, or Matrix(x) for an independent dense copy. size(x) is (p,p); there is no length, axes, iteration, broadcasting or one-index x[k] access.

Nonzero writes activate a coordinate; zero writes retain existing activity. activate! stores an explicit zero, nactive counts active independent variables, and dropzeros!(::Union{SparseIterate, SymmetricSparseIterate}) removes active zeros.

Examples

julia> x = SymmetricSparseIterate(2); x[2, 1] = 3;

julia> (ncoordinates(x), nactive(x), x[1, 2])
(3, 1, 3.0)

julia> Matrix(x) == [0.0 3.0; 3.0 0.0]
true

Copies and imports

  • copy(x) and same-kind copyto! preserve values, active zeros and order; similar(x) creates empty storage of the same dimension.
  • A matrix import must be real, one-based and exactly symmetric before conversion. It replaces activity with converted nonzeros. Use Symmetric(A, :L) to select one triangle deliberately.
  • copyto!(x, A) rejects a source sharing memory with x. Shape, symmetry and alias checks precede writes; a failing conversion can occur after the old active state has been cleared, leaving a partially imported state.

See the symmetric-iterate guide for comparisons, matrix geometry and supported operations, and ProximalBase.check_symmetric_parameters for model validation.

source
ProximalBase.BlockIterate — Type
BlockIterate([T = Float64,] p, groups)
BlockIterate(x::AbstractVector, groups)
BlockIterate([T = Float64,] p, num_groups::Integer)
BlockIterate(x::AbstractVector, num_groups::Integer)
BlockIterate([T = Float64,] p, f::GroupNormL2)
BlockIterate(x::AbstractVector, f::GroupNormL2)
BlockIterate([T = Float64,] p, f::GroupNormLinf)
BlockIterate(x::AbstractVector, f::GroupNormLinf)
BlockIterate([T = Float64,] p, f::GroupMCP)
BlockIterate(x::AbstractVector, f::GroupMCP)

A real vector whose optimization coordinates are ordered groups of entries. The nonempty, disjoint groups must partition 1:p; ranges and reordered index vectors are supported. An integer group count divides the entries into equal contiguous groups and must be positive and divide the entry length.

x[j] indexes an entry; ncoordinates gives the group count, nactive counts active groups, and activate!, isactive and activecoordinates use group IDs. A nonzero entry activates its group. Zero writes preserve activity; dropzeros!(::BlockIterate) removes all-zero active groups. blockview gives a writable alias in stored group order, and blockindices gives its read-only indices. Entry access and group activation cost O(1); storage costs O(p + length(groups)).

Examples

julia> x = BlockIterate(4, [[3, 1], [4, 2]]);

julia> copyto!(blockview(x, 1), [2.0, 0.0]);

julia> (x[3], ncoordinates(x), nactive(x))
(2.0, 2, 1)

Ownership and writes

  • High-level constructors copy values and group lists. copy and similar own mutable value/activity storage but share layout data, which must not be mutated. Low-level construction requires independent mutable storage.
  • Same-layout copyto! replaces active state. Ordinary array copies and broadcasts never deactivate groups, though nonzero writes can activate them.
  • Direct bulk writes preflight known complex source types. Views, indexed writes and per-element conversions may fail after partial writes. See write validation.

See the block guide for group-penalty constructors, copying and the ownership contract.

Working sets and views

ProximalBase.ncoordinates — Function
ncoordinates(x)

The number of independent coordinates of the iterate x that a solver updates: the entries of a SparseIterate, the entries of the lower triangle of a SymmetricSparseIterate, the groups of an BlockIterate.

source
ProximalBase.nactive — Function
nactive(x)

The number of active coordinates of x: the stored entries of a SparseIterate or SymmetricSparseIterate, the active groups of a BlockIterate. Active-set solvers use them as the active set.

source
ProximalBase.coordinates — Function
coordinates(x)

A vector view of the coordinates of x (see ncoordinates): the entries of a SparseIterate in linear order, whatever its shape, and the entries of the lower triangle for a SymmetricSparseIterate. The view is an AbstractVector of length ncoordinates(x) indexed by coordinate, live (a later write to x shows through it) and writable, and building it copies nothing. It is never x itself.

The view is an ordinary vector of the element type of x. A write through it is a value write: it activates the coordinates it makes nonzero and removes none, and converts the value as a write into a plain vector does, so a complex value throws an InexactError, possibly after part of x has been written; the view has no complex check of its own. Its products and reductions are those of an ordinary vector (IEEE, O(length(x))): for the sparse product use x itself, as in dot(v, x). copyto!(coordinates(x), coordinates(y)) is a value write, while copyto!(x, y) is the state copy. A copyto!, copy! or broadcast that takes both x and coordinates(x) copies the source once first, so that its result is that of copying the source before writing; other calls, such as mul! with the view as both output and input, behave as they do on an aliased plain vector.

source
ProximalBase.activecoordinates — Function
activecoordinates(x)

A read-only AbstractVector{Int} of the active coordinates of x (see nactive), in the order in which they became active, except that dropzeros! moves the last ones into the places of those it removes. It is a handle on the internal list, not a snapshot: nothing is copied, and it does not grow when coordinates become active, so call activecoordinates again after changing the active set: after an activation, after dropzeros!, and after a whole-state replacement such as copyto!(x, y), which can reorder the list even when the active set and nactive(x) stay the same. Writing through it throws an ArgumentError, because the list and the iterate's reverse map must stay in agreement; write values through activevalues (or blockview(x, k) for a BlockIterate).

source
ProximalBase.activevalues — Function
activevalues(x::Union{SparseIterate, SymmetricSparseIterate})

A writable vector view of the values of the active coordinates of x, in the order of activecoordinates: entry a is the value of coordinate activecoordinates(x)[a]. Writing zero through it keeps the coordinate active; use dropzeros! to remove it. The view has the length nactive had when it was taken and does not grow, so, like activecoordinates, take it again after a coordinate becomes active, after dropzeros! or after a whole-state replacement such as copyto!(x, y), each of which can reorder the active list. Nothing is copied.

source
ProximalBase.isactive — Function
isactive(x, k)

Whether coordinate k of x is active (see nactive).

source
ProximalBase.activate! — Function
activate!(x::SparseIterate, i)
activate!(x::SymmetricSparseIterate, k)
activate!(x::BlockIterate, k)

Make a coordinate active and return x, without changing its value. An absent scalar coordinate is stored as an explicit zero. For a BlockIterate, k is a group ID and the group's entries are kept. For a SymmetricSparseIterate, k is an independent lower-triangle coordinate number such as tril_index(p, r, c), not a matrix linear index. An already active coordinate is unchanged.

Assigning zero to an absent coordinate does not activate it. Use this operation to retain zero coordinates for a solver's next sweep; dropzeros!(::Union{SparseIterate, SymmetricSparseIterate}) or dropzeros!(::BlockIterate) removes them when they are no longer needed.

Examples

julia> x = SparseIterate(3); activate!(x, 2);

julia> (x[2], isactive(x, 2), nactive(x))
(0.0, true, 1)
source
ProximalBase.matrixview — Function
matrixview(x::SymmetricSparseIterate)

A live, read-only p × p matrix view of x: ordinary matrix indexing, both triangles, no copy of the data. Later writes to x show through it. Nothing can be written through the view or through a wrapper derived from it (view, reshape, transpose, Symmetric): the write is refused and x is unchanged. A generic allocating operation on the view (A .+ 1, similar(A), collect(A)) returns an ordinary writable dense array. mul! of the view and a dense vector costs O(p + nactive(x)); other generic matrix operations on the view read all p² entries. Use Matrix(x) for an independent dense copy.

Non-finite vectors

A coefficient of x that is zero contributes nothing to the product, whether it is absent or an explicitly stored zero: a non-finite entry of v that meets only zero coefficients does not reach the result, and mul!(y, matrixview(x), v) is the same before and after dropzeros!(x), up to the order of the finite summation. A NaN coefficient is not zero and gives NaN.

Entries (r, c) and (c, r) are one variable of x; a coordinate of x is reached through coordinates, not through this view, so matrixview(x)[4] is a matrix linear index.

source
ProximalBase.blockview — Function
blockview(x::BlockIterate, k)

Return a writable view of group k in its stored index order. The view aliases x: nonzero writes activate the group, and zero writes preserve activity. Use dropzeros!(::BlockIterate) to remove an all-zero active group.

For a trial proximal step, compute prox_block!(out, f, u, k, γ) in independent numerical buffers, then commit with copyto!(blockview(x, k), out). Copying into a block view follows ordinary value-copy semantics, including possible partial writes on conversion failure.

norm and dot read the underlying storage directly, using BLAS for contiguous groups; other BLAS routines use generic paths. See blockindices and the block guide.

source
ProximalBase.blockindices — Function
blockindices(x::BlockIterate, k::Integer)

Return the global entry indices of group k, in stored order, as a read-only AbstractVector{<:Integer}. A stored range retains its range and integer types; a vector group is exposed through a read-only wrapper of element type Int. Use collect for an independent writable vector.

The result takes O(1) time without allocation or copying and stays valid for x's lifetime. Value writes and active-set changes do not change the layout. k must be in 1:ncoordinates(x); invalid IDs, including Bool, throw BoundsError. Writes through the wrapper throw ArgumentError.

Use the result to index other arrays, for example view(g, blockindices(x, k)). Never modify private layout fields, wrapper fields or parentindices(blockview(x, k)); doing so bypasses validation.

Examples

julia> x = BlockIterate(6, [[1, 4], [2, 5], [3, 6]]);

julia> blockindices(x, 2) == [2, 5]
true

julia> blockindices(BlockIterate(6, 3), 2) === 3:4
true

See blockview for values and the block guide for ordered layouts.

source
ProximalBase.samegroups — Function
ProximalBase.samegroups(a::BlockIterate, b::BlockIterate)

Whether two block iterates have the same block layout. Group arrays must not be mutated after construction. A successful comparison may cache the layout identity in an iterate; concurrent comparisons on the same iterate require external synchronization. This function is public but not exported.

Compaction and sparse-array binding

There is no nnz method for iterates. Count activity or mathematical nonzeros explicitly as explained in the guide.

SparseArrays.dropzeros! — Method
dropzeros!(x::Union{SparseIterate, SymmetricSparseIterate})

Remove active zero coordinates and return x, preserving numerical values under == for finite entries. For a SymmetricSparseIterate, coordinates are independent lower-triangle variables. Signed zeros, including stored -0.0, are removed; an absent coordinate reads +0.0 afterward. Thus isequal can distinguish the old active -0.0 from the absent coordinate. NaN and infinities are kept.

Compaction may reorder active slots. Reacquire activecoordinates and activevalues afterward. Old handles are live, fixed-length views: after compaction they can expose stale or reordered entries, not a snapshot. The cost is O(nactive(x)), counted before compaction.

Examples

julia> x = SparseIterate([0.0, 3.0]); activate!(x, 1);

julia> nactive(x)
2

julia> dropzeros!(x); (nactive(x), x[2])
(1, 3.0)
source
SparseArrays.dropzeros! — Method
dropzeros!(x::BlockIterate)

Deactivate all-zero active groups and return x, preserving entry values. Signed zeros count as zero; a group containing NaN or an infinity stays active. Compaction may reorder active slots, so reacquire activecoordinates afterward.

Examples

julia> x = BlockIterate([0.0, 0.0, 2.0, 0.0], 2); activate!(x, 1);

julia> nactive(x)
2

julia> dropzeros!(x); (nactive(x), isactive(x, 2))
(1, true)
source
SparseArrays.nnz — Function
nnz(A)

Re-export of SparseArrays.nnz for standard sparse arrays. ProximalBase does not define an nnz method for its iterates. Use nactive to count active coordinates, including explicitly stored zeros; use count(!iszero, activevalues(x)) to count nonzero entries of a SparseIterate.

Numerical utilities

The triangular helpers assume valid lower-triangle inputs and do not promise bounds validation; norm_diff supports p=2 or Inf, not arbitrary norm orders.

ProximalBase.shrink — Function
shrink(v, c)

Soft thresholding: sign(v) ⋅ max(|v| - c, 0) for a threshold c ≥ 0, the proximal operator of c|⋅|. A NaN in v propagates.

‖A - B‖ without allocating A - B: the Euclidean (Frobenius) norm for p = 2, the largest absolute entry for p = Inf. Both arrays must have real entries.

Selected three-factor product docstrings

These methods require matching Float32/Float64 and Symmetric wrappers of strided factors for their direct numerical guarantee. Mixed/generic methods have the narrower guarantees described under three-factor products and numerics.

Base.:* — Method
*(A::Symmetric{T}, X::SparseIterate{T, 2}, B::Symmetric{T}) where {T<:Union{Float32, Float64}}

Return the dense matrix A * X * B by summing terms for nonzero entries of X. The direct method requires Symmetric wrappers of strided matrices, with all three operands of the same Float32 or Float64 element type and compatible dimensions. For X of size m × n, it costs O(nactive(X) * m * n) operations and O(m * n) memory.

A zero coefficient of X, stored or absent, contributes nothing even against NaN or infinity in the factors. Nonzero coefficients always contribute; zeros in A and B keep ordinary IEEE behavior. The result can therefore differ from A * Matrix(X) * B on non-finite inputs.

Finite three-factor terms avoid spurious intermediate overflow or underflow, without promising correct rounding. Terms are summed in storage order; a non-finite sum is recomputed only when all contributing factors are finite. See three-factor products for the precise rounding, range-boundary and cancellation guarantees. Mixed and generic product methods do not inherit that guarantee.

source
Base.:* — Method
*(A::Symmetric{T}, X::SymmetricSparseIterate{T}, B::Symmetric{T}) where {T<:Union{Float32, Float64}}

Return the dense matrix A * X * B using the nonzero independent coordinates of X. A diagonal coordinate contributes one matrix term; an off-diagonal coordinate contributes its two mirrored terms. The cost is O(nactive(X) * p²) operations and O(p²) memory for a p × p symmetric iterate.

This direct method requires Symmetric wrappers of strided matrices, with all three operands of the same Float32 or Float64 element type and compatible dimensions. Stored and absent zeros of X contribute nothing, even against non-finite factors. Nonzero coefficients always contribute, and zeros in A and B keep ordinary IEEE behavior. Thus the result can differ from A * Matrix(X) * B on non-finite inputs.

The finite-term range recovery and conditional recomputation of non-finite sums follow the three-factor product contract. Terms are summed in storage order, (r,c) before (c,r) for a mirrored pair. Correct rounding is not promised; mixed and generic methods do not inherit the direct method's guarantee.
