Iterate and utility reference

ProximalBase.SparseIterate — Type
SparseIterate([T = Float64,] n)
SparseIterate([T = Float64,] n, m)
SparseIterate(x::Union{SparseVector, SparseMatrixCSC, Array})

A vector or matrix that stores its nonzero entries in a compact list, so that reading or writing any entry is O(1) and multiplying by it costs O(nnz). Intended for coordinate-descent and active-set iterates that stay sparse. Its coordinates (see ncoordinates) are its entries, in linear order.

Setting an entry to zero keeps it in the list; call dropzeros! to remove stored zeros. The stored entries are the active coordinates (activecoordinates).

ProximalBase.SymmetricSparseIterate — Type
SymmetricSparseIterate([T = Float64,] p)
SymmetricSparseIterate(X::AbstractMatrix)

A sparse symmetric p × p matrix that stores only its lower triangle, with the same O(1) access as SparseIterate. It is an ordinary p × p matrix: x[r, c] and x[c, r] are the same entry, and linear indices, length(x) = p² and iteration follow the dense matrix, so that an off-diagonal entry is visited twice.

Writing x[r, c] writes x[c, r] too. The functions that write a matrix into x (the constructor, copyto!, copy!, broadcasting into x, map!, axpy! and axpby!) take a value with the axes of x that is exactly symmetric: entries (r, c) and (c, r) are equal, with NaN equal to NaN, compared before conversion to the element type of x. Otherwise they throw a DimensionMismatch or an ArgumentError before writing anything. To store one triangle of a matrix A that is not symmetric, write Symmetric(A, :L) or Symmetric(A, :U). These functions write each entry of the lower triangle once. A broadcast whose arguments do not show that its value is symmetric is first evaluated at both positions of each off-diagonal entry, so a function with side effects runs more often and may give a value that is not symmetric. copyto! with offsets or index ranges and the indexed axpy! throw an ArgumentError. fill!, rmul! and lmul! by a number keep x symmetric. replace and replace! visit each entry of the lower triangle once, and their count counts those entries, column by column.

Other functions update the entries of x one position at a time and are not checked: mul! into x, indexed and view assignment such as x[:, :] = A, copyto! from an iterator, transpose!, permutedims!, reverse!, triu!, tril!, and scaling by a Diagonal. They can update an off-diagonal entry twice or store one of two different values. Functions that build a result that is not symmetric in similar(x), such as cumsum or circshift, need Matrix(x). triu, tril and sparse return a SparseMatrixCSC.

Its coordinates are the p(p+1)/2 entries of the lower triangle, numbered column by column (tril_index): prox_coordinate! updates them, ncoordinates counts them, activecoordinates lists the stored ones and coordinates is a vector view of them.

ProximalBase.activate! — Method
activate!(x::SparseIterate, i)
activate!(x::SymmetricSparseIterate, k)
activate!(x::AtomIterate, k)

Make coordinate i of x active, storing it as an explicit zero if it is not stored already, and return x. Assigning a zero does not store an entry, so this is how a coordinate joins the active set of an active-set solver; dropzeros! removes it again while it is zero. For an AtomIterate, make group k active, keeping its entries.

source
ProximalBase.activecoordinates — Function
activecoordinates(x)

A vector of the active coordinates of x (see nactive), in the order in which they became active, except that dropzeros! moves the last ones into the places of those it removes. The vector is a view of the internal list: it does not grow when coordinates become active, so call activecoordinates again after changing the active set.

source
ProximalBase.coordinates — Function
coordinates(x)

A vector view of the coordinates of x (see ncoordinates): x itself for a SparseIterate, whose coordinates are its entries in linear order, and the entries of the lower triangle for a SymmetricSparseIterate. Writing through the view writes x.

source
ProximalBase.isactive — Function
isactive(x, k)

Whether coordinate k of x is active (see nactive).

ProximalBase.nactive — Function
nactive(x)

The number of active coordinates of x: the stored entries of a SparseIterate or SymmetricSparseIterate, the active groups of an AtomIterate. Active-set solvers use them as the active set.

ProximalBase.ncoordinates — Function
ncoordinates(x)

The number of coordinates of the iterate x that prox_coordinate! updates: the entries of a SparseIterate, the entries of the lower triangle of a SymmetricSparseIterate, the groups of an AtomIterate.

ProximalBase.AtomIterate — Type
AtomIterate([T = Float64,] p, groups)
AtomIterate(x::AbstractVector, groups)
AtomIterate([T = Float64,] p, num_groups::Integer)
AtomIterate(x::AbstractVector, num_groups::Integer)

A vector of length p whose coordinates, for coordinate descent, are the groups ("atoms") x.groups[k], which partition 1:p. The groups are ranges such as 1:5 or vectors of indices such as [2, 7, 9], of any sizes; AtomIterate(p, num_groups) and AtomIterate(x, num_groups) split 1:p into num_groups equal contiguous groups.

As the stored entries of a SparseIterate do, a set of active groups serves as the active set of a solver, and the entries of the other groups are zero. Writing a nonzero entry activates its group, activate! activates a group, and dropzeros! deactivates the active groups whose entries are all zero; an iterate built from a vector x starts with the groups that hold a nonzero entry. Reading or writing an entry is O(1), and so is activating or deactivating a group. ncoordinates is the number of groups, nactive, activecoordinates and isactive give the active groups, and atom is a view of the entries of a group.

ProximalBase.atom — Method
atom(x::AtomIterate, k)

A view of the entries of group k of x. Writing through it does not activate the group; see activate!.

ProximalBase.norm_diff — Function
norm_diff(A, B, p = 2)

‖A - B‖ without allocating A - B: the Euclidean (Frobenius) norm for p = 2, the largest absolute entry for p = Inf. The result is real, also for complex arrays.

source
ProximalBase.opnorm2 — Method
opnorm2(X)

Estimate the squared spectral norm ‖X‖₂² by Lanczos iteration, using only products with X and its adjoint, without forming a Gram matrix or densifying a sparse matrix. The result has floating element type matching X.

This is a numerical estimate, not a certified upper bound: Lanczos can miss an eigenspace orthogonal to its deterministic starting vector. Algorithms requiring a guaranteed bound should use an independently known bound (for example opnorm(X, 1) * opnorm(X, Inf)) or a suitable line search.

source
ProximalBase.shrink — Method
shrink(v, c)

Soft thresholding: sign(v) ⋅ max(|v| - c, 0) for a threshold c ≥ 0, the proximal operator of c|⋅|. A NaN in v propagates.

ProximalBase.tril_cartesian — Method
tril_cartesian(p, k)

The entry (r, c), r ≥ c, of the lower triangle of a p × p matrix with linear index k, numbered column by column. Inverse of tril_index.

source
ProximalBase.tril_index — Method
tril_index(p, r, c)

The linear index of entry (r, c), r ≥ c, of the lower triangle of a p × p matrix, numbered column by column: the coordinate of a SymmetricSparseIterate that holds the entry. Inverse of tril_cartesian.

SparseArrays.nnz — Method
nnz(x::Union{SparseIterate, SymmetricSparseIterate})

The number of stored coordinates of x, including stored zeros. On a SymmetricSparseIterate, count the stored coordinates of the lower triangle, so each off-diagonal pair counts once. Use dropzeros! to remove stored zeros.

source
SparseArrays.nonzeros — Method
nonzeros(x::SparseIterate)

The stored values of x, including stored zeros, in storage order. Entry k pairs with activecoordinates(x)[k]. The returned view aliases x: writing through it changes x. The view is invalidated when the stored set changes.

source
SparseArrays.findnz — Method
findnz(x::SparseIterate)

The stored indices and values of x, including stored zeros, as copies. Return (I, V) sorted by index for a vector, or (I, J, V) in column-major order for a matrix. Changing the returned arrays does not change x.

source
SparseArrays.dropzeros! — Method
dropzeros!(x::Union{SparseIterate, SymmetricSparseIterate})

Remove stored zero coordinates from x and return x. On a SymmetricSparseIterate, these are coordinates of the lower triangle. The last stored coordinate moves into the place of each removed one, so the order of activecoordinates can change. The entries of x do not change.

source
SparseArrays.dropzeros! — Method
dropzeros!(x::AtomIterate)

Deactivate the active groups of x whose entries are all zero and return x. The last active group moves into the place of each removed one, so the order of activecoordinates can change. The entries of x do not change.
