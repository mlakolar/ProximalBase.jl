Iterate and utility reference

ProximalBase.SparseIterate — Type
SparseIterate([T = Float64,] n)
SparseIterate([T = Float64,] n, m)
SparseIterate(x::Union{SparseVector, SparseMatrixCSC, Array})

A vector or matrix that stores its nonzero entries in a compact list, so that reading or writing any entry is O(1) and multiplying by it costs O(nnz). Intended for coordinate-descent and active-set iterates that stay sparse. Its coordinates (see ncoordinates) are its entries, in linear order.

Setting an entry to zero keeps it in the list; call dropzeros! to remove stored zeros. The stored entries are the active coordinates (activecoordinates).

Its entries are real. The constructors, two-argument copyto! from an array (for a matrix also from a UniformScaling or an orthogonal factor), copy!, broadcasting into x and fill! throw an ArgumentError for a source or value of complex type, even with a zero imaginary part, before anything is written. For a vector x, vec(x) and reshape(x, length(x)) are x itself and are checked too. copy! from a source of another size throws Base's error first, unless the source is a SparseIterate or an AtomIterate: one of the same length is copied by value in linear order, and one of another length throws a DimensionMismatch. The check reads types: a tuple, a generator or an array of abstract element type such as Vector{Any} passes it, and its values are converted one by one. Other writes also convert values one by one, as writes into a plain Array of the element type of x do: writes through a view, through coordinates(x), through vec of a matrix or a reshape to another shape, indexed assignment such as x[i] = v or x[:] = c, copyto! with offsets or index ranges, and map!. A complex value converted one by one throws an InexactError, possibly after part of x has been written.

ProximalBase.SymmetricSparseIterate — Type
SymmetricSparseIterate([T = Float64,] p)
SymmetricSparseIterate(X::AbstractMatrix)

A sparse symmetric p × p matrix that stores only its lower triangle, with the same O(1) access as SparseIterate. It is an ordinary p × p matrix: x[r, c] and x[c, r] are the same entry, and linear indices, length(x) = p² and iteration follow the dense matrix, so that an off-diagonal entry is visited twice.

Read and write entries through the lower triangle, r ≥ c, for example with for c in 1:p, r in c:p. The position x[c, r] is the same entry as x[r, c], so writing either position writes both. Code that writes every position writes each off-diagonal entry twice, and the second write wins.

Whole-value writes are checked: the constructor, copyto!, copy!, broadcasting into x, map!, axpy!, axpby!, transpose!, adjoint!, permutedims! and mul!. The checks also cover indexed array assignment of every position in order (x[:, :] = A, x[:] = v), and broadcasting, fill!, copyto! and copy! into full, in-order views and reshapes (x[:, :] .= A, vec(x) .= v, copyto!(view(x, :, :), A)). The covered wrappers are views whose parent is x, reshapes whose parent is x, and views of those reshapes; Base makes a view of such a view a view of x, and a reshape of a reshape a reshape of x. Use : or integer vectors matching each axis in order for a full two-index assignment or a full matrix view. A full single-index assignment accepts :, the integers 1:length(x) in order, or CartesianIndices(x) with its shape. copyto!(x, Q) from an orthogonal factor is checked too, as is copyto! from one into a full matrix view or reshape.

Matrix values must have the axes of x and be exactly symmetric: entries (r, c) and (c, r) are equal, with NaN equal to NaN, compared before conversion to the element type of x. Linear full writes reshape their values in column-major order for this check; x[:] = v requires p² values. copyto! into a full view or reshape reads its source in linear order, as Base does, so the source needs p² values and not the axes of x: copyto!(view(x, :, :), vec(A)) writes the symmetric A, while copyto!(x, vec(A)) throws. If the axes differ or symmetry fails, the checked writers throw a DimensionMismatch or an ArgumentError before writing anything. To store one triangle of a matrix A that is not symmetric, write Symmetric(A, :L) or Symmetric(A, :U). These functions write each entry of the lower triangle once. A broadcast whose arguments do not show that its value is symmetric is first evaluated at both positions of each off-diagonal entry, so a function with side effects runs more often and may give a value that is not symmetric.

With two array operands, mul! into x checks the unscaled product for exact symmetry in a buffer promoted from the destination and operand types, applies scalars and conversion at the final write, and leaves the product out when α = 0, as LinearAlgebra does. For mul! by a number, the array operand must have the axes of x. The seven-argument mul!(x, tA, tB, A, B, α, β), when available, uses the same checks with flags 'N', 'T' and 'C' for unchanged, transposed and adjoint operands; other flags throw before writing. fillband!(x, v, l, u) checks that v is real and writes a symmetric band (l == -u) through the lower triangle once. An empty band (l > u) returns x unchanged.

Indexed array assignment, broadcasting and fill! into part of x, such as a row, a column, a block or a partial mask, throw an ArgumentError before writing. copyto! and copy! into such a part through a view throw before writing too. Logical-mask indexed assignment is rejected even for an all-true mask. copyto! with offsets or index ranges (including transpose flags), copy_transpose! and copy_adjoint! with index ranges, copyto! from a tuple, a generator or a number, and the indexed axpy! also throw before writing, as does copyto! with offsets into a view or reshape. Out-of-bounds indices still throw a BoundsError.

The position-wise writers reverse!, sort!, accumulate!, kron! and copytrito! (when available) throw an ArgumentError before writing. This also rejects reverse(x) with or without dims, cumsum!, cumprod!, and allocating cumsum, cumprod and accumulate with dims. circshift! and circshift of a nonempty x by a nonempty shift throw too. triu!(x, k) and tril!(x, k) return x unchanged only when every position is kept: k ≤ 1 - p for triu!, k ≥ p - 1 for tril!, or any k when p = 0. Otherwise they throw an ArgumentError before writing.

lmul!, rmul!, ldiv! and rdiv! by a matrix, a factorization, an orthogonal factor or a rotation throw an ArgumentError before writing, as does ldiv!(x, A, B) for such an operator A. Reductions into x (sum!, prod!, maximum!, minimum!, count!, all!, any!, extrema!, findmax! and findmin! with x as either destination), in-place factorizations (lu!, qr!, cholesky! and bunchkaufman!), get! and sortperm! also throw before writing. So do fillband! with a nonempty band that is not symmetric, and read!, readbytes! and hex2bytes!, which do not consume their input. Use Matrix(x) for these operations, or compute into a dense matrix and copyto! a symmetric result.

fill!, and rmul!, lmul!, rdiv! and ldiv! by a number or a UniformScaling, keep x symmetric. replace and replace! visit each entry of the lower triangle once, and their count counts those entries, column by column. triu, tril and sparse return a SparseMatrixCSC. sort(x; dims) and accumulate(op, x) without dims keep their dense results. Allocating lu, qr, cholesky and bunchkaufman use dense copies.

Other functions that write an arbitrary array position by position are not checked; apply them to Matrix(x). Scalar-write loops over every position stay unchecked. Other writes through a view or reshape stay unchecked too: indexed assignment such as view(x, :, :)[:, :] = A, scalar writes through a view, copyto! with index ranges, and copyto! from a tuple, a generator, a number or another non-array iterator. The checks do not extend to other nested wrappers, such as vec(view(x, :, :)) or a view of it, including broadcasts, fills and copies through them. Two-argument copyto!(x, itr) from other non-array iterators is unchecked. A Base function can write part of x before reaching a check. rand! and randn! give a symmetric matrix but draw each off-diagonal entry twice. shuffle! and shuffle give wrong values; use Matrix(x) instead.

Its coordinates are the p(p+1)/2 entries of the lower triangle, numbered column by column (tril_index): prox_coordinate! updates them, ncoordinates counts them, activecoordinates lists the stored ones and coordinates is a vector view of them.

See Symmetric parameters for which arrays must be symmetric and which calls check them.

ProximalBase.activate! — Method
activate!(x::SparseIterate, i)
activate!(x::SymmetricSparseIterate, k)
activate!(x::AtomIterate, k)

Make coordinate i of x active, storing it as an explicit zero if it is not stored already, and return x. Assigning a zero does not store an entry, so this is how a coordinate joins the active set of an active-set solver; dropzeros! removes it again while it is zero. For an AtomIterate, make group k active, keeping its entries.

ProximalBase.activecoordinates — Function
activecoordinates(x)

A read-only AbstractVector{Int} of the active coordinates of x (see nactive), in the order in which they became active, except that dropzeros! moves the last ones into the places of those it removes. It is a handle on the internal list, not a snapshot: nothing is copied, and it does not grow when coordinates become active, so call activecoordinates again after changing the active set: after an activation, after dropzeros!, and after a whole-state replacement such as copyto!(x, y), which can reorder the list even when the active set and nactive(x) stay the same. Writing through it throws an ArgumentError, because the list and the iterate's reverse map must stay in agreement; write values through activevalues (or atom(x, k) for an AtomIterate).

source
ProximalBase.activevalues — Function
activevalues(x::Union{SparseIterate, SymmetricSparseIterate})

A writable vector view of the values of the active coordinates of x, in the order of activecoordinates: entry a is the value of coordinate activecoordinates(x)[a]. Writing zero through it keeps the coordinate active; use dropzeros! to remove it. The view has the length nactive had when it was taken and does not grow, so, like activecoordinates, take it again after a coordinate becomes active, after dropzeros! or after a whole-state replacement such as copyto!(x, y), each of which can reorder the active list. Nothing is copied.

ProximalBase.coordinates — Function
coordinates(x)

A vector view of the coordinates of x (see ncoordinates): the entries of a SparseIterate in linear order, whatever its shape, and the entries of the lower triangle for a SymmetricSparseIterate. The view is an AbstractVector of length ncoordinates(x) indexed by coordinate, live (a later write to x shows through it) and writable, and building it copies nothing. It is never x itself.

The view is an ordinary vector of the element type of x. A write through it is a value write: it activates the coordinates it makes nonzero and removes none, and converts the value as a write into a plain vector does, so a complex value throws an InexactError, possibly after part of x has been written; the view has no complex check of its own. Its products and reductions are those of an ordinary vector (IEEE, O(length(x))): for the sparse product use x itself, as in dot(v, x). copyto!(coordinates(x), coordinates(y)) is a value write, while copyto!(x, y) is the state copy. A copyto!, copy! or broadcast that takes both x and coordinates(x) copies the source once first, so that its result is that of copying the source before writing; other calls, such as mul! with the view as both output and input, behave as they do on an aliased plain vector.

ProximalBase.matrixview — Method
matrixview(x::SymmetricSparseIterate)

A live, read-only p × p matrix view of x: ordinary matrix indexing, both triangles, no copy of the data. Later writes to x show through it. Nothing can be written through the view or through a wrapper derived from it (view, reshape, transpose, Symmetric): the write is refused and x is unchanged. A generic allocating operation on the view (A .+ 1, similar(A), collect(A)) returns an ordinary writable dense array. mul! of the view and a dense vector costs O(p + nactive(x)); other generic matrix operations on the view read all p² entries. Use Matrix(x) for an independent dense copy.

Non-finite vectors

The product skips absent coordinates but multiplies by stored ones, an explicit stored zero included. With a non-finite v, a stored zero gives 0 * Inf = NaN where an absent coordinate gives 0, so dropzeros!(x) can change mul!(y, matrixview(x), v) although the matrix does not. This does not yet satisfy the rule of the 0.6 contract (the same result, or the same error, before and after dropzeros!); it is to be settled with the 0.6 owner.

Entries (r, c) and (c, r) are one variable of x; a coordinate of x is reached through coordinates, not through this view, so matrixview(x)[4] is a matrix linear index.

ProximalBase.AtomIterate — Type
AtomIterate([T = Float64,] p, groups)
AtomIterate(x::AbstractVector, groups)
AtomIterate([T = Float64,] p, num_groups::Integer)
AtomIterate(x::AbstractVector, num_groups::Integer)

A vector of length p whose coordinates, for coordinate descent, are the groups ("atoms") x.groups[k], which partition 1:p. The groups are ranges such as 1:5 or vectors of indices such as [2, 7, 9], of any sizes; AtomIterate(p, num_groups) and AtomIterate(x, num_groups) split 1:p into num_groups equal contiguous groups.

As the stored entries of a SparseIterate do, a set of active groups serves as the active set of a solver, and the entries of the other groups are zero. Writing a nonzero entry activates its group, activate! activates a group, and dropzeros! deactivates the active groups whose entries are all zero; an iterate built from a vector x starts with the groups that hold a nonzero entry. Reading or writing an entry is O(1), and so is activating or deactivating a group. ncoordinates is the number of groups, nactive, activecoordinates and isactive give the active groups, and atom is a view of x at the entries of a group. Writing through this view follows the same activation rule as writing to x.

Its entries are real. The constructors, two-argument copyto! from an array, copy!, broadcasting into x and fill! throw an ArgumentError for a source or value of complex type, even with a zero imaginary part, before anything is written. vec(x) and reshape(x, length(x)) are x itself and are checked too. copy! from a source of another length throws Base's error first, unless the source is an AtomIterate or a SparseIterate, which throws a DimensionMismatch. The check reads types: a tuple, a generator or an array of abstract element type such as Vector{Any} passes it, and its values are converted one by one. Other writes also convert values one by one, as writes into a plain Vector of the element type of x do: writes through atom(x, k) or another view, indexed assignment such as x[i] = v or x[:] = c, copyto! with offsets or index ranges, and map!. A complex value converted one by one throws an InexactError, possibly after part of x has been written.

ProximalBase.atom — Method
atom(x::AtomIterate, k)

A view of the entries of group k. It is a view of x itself, so it aliases x. Writing through it follows the rule of x[i] = v: a nonzero entry activates the group and a zero never deactivates it (see dropzeros!). To take a proximal step at a trial point without activating the group first, use prox_coordinate!(x, f, k, u, γ). norm and dot of the view read the storage directly (BLAS for contiguous groups), while other BLAS routines take generic paths for it.

ProximalBase.atomindices — Method
atomindices(x::AtomIterate, k::Integer)

The indices of the entries of group k, in the order in which x stores them, as a read-only AbstractVector{<:Integer}. A group stored as a range is returned as that range, whatever its index type: a group stored as UnitRange{Int32} is returned as a UnitRange{Int32}. A group stored as a vector is returned as a read-only wrapper of the stored vector whose element type is Int. A write through the wrapper (h[i] = v, fill!, copyto!, h .= v, sort! and the like) throws an ArgumentError and leaves the groups unchanged.

Constructing the result takes constant time and does not allocate or copy, and it stays valid for as long as x: the groups of an iterate never change, and activating groups, dropzeros!, copyto! and the other writes of values do not affect it. k must be in 1:ncoordinates(x), or a BoundsError is thrown (a Bool is not a group index).

The result can index any array: view(g, atomindices(x, k)) is the part of g that belongs to group k. The fields of x and of the wrapper (h.ids) are internal, and so is the array that parentindices(atom(x, k)) returns: reading or changing them is not supported, and is not blocked.

Examples

x = AtomIterate(6, [[1, 4], [2, 5], [3, 6]])
atomindices(x, 2) == [2, 5]                 # a read-only vector of Int
atomindices(AtomIterate(6, 3), 2) === 3:4   # the stored range

ProximalBase.opnorm2 — Method
opnorm2(X)

Estimate the squared spectral norm ‖X‖₂² by Lanczos iteration, using only products with X and its adjoint, without forming a Gram matrix or densifying a sparse matrix. The result has floating element type matching X.

This is a numerical estimate, not a certified upper bound: Lanczos can miss an eigenspace orthogonal to its deterministic starting vector. Algorithms requiring a guaranteed bound should use an independently known bound (for example opnorm(X, 1) * opnorm(X, Inf)) or a suitable line search.

ProximalBase.samegroups — Function
ProximalBase.samegroups(a, b)

Whether a and b have equal groups: the same number of groups, and the same indices in the same order in every group (1:2 and [1, 2] are equal, [2, 1] is not). a and b are two AtomIterates, or an AtomIterate and a group penalty (any ProximalBase.AbstractGroupPenalty, such as GroupNormL2 or GroupMCP) or an IndBallGroupL0, in either order. It is the check that prox_coordinate! makes before it writes and that the four-argument kkt_violation(f, g, x, k) makes before it computes (each throws a DimensionMismatch when it fails), that value and prox! of a group function make to take the active-group paths, and that copyto! between two iterates makes to copy only the active groups. samegroups is public but not exported.

An iterate remembers one group array that it has found equal to its own. The answer takes constant time when a and b share their group array, or both remember the same one, or one remembers the other's. Otherwise the two are compared in full, which takes time proportional to the total size of the groups. If they are equal, the iterate x (a when both are iterates) remembers the group array of the other, so that asking again takes constant time. The one slot is replaced each time, so alternating between two equal group arrays that are different objects compares at every call; a comparison that finds the groups unequal remembers nothing and leaves the remembered array in place. Neither the cache nor the comparison allocates. The groups of penalties and iterates must not be mutated (see AtomIterate). Because the answer is remembered in the iterate, calling samegroups on one iterate from several threads at once is a data race, as it is for the other operations on an iterate (the stored value is always an equal layout).
