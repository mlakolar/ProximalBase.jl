The iterate family in 0.6: compatibility and acceptance

The target 0.6 design and acceptance plan, signed off on 2026-11-01 (FD-16 decided on 2026-11-06: the direct product), not documentation of a registered release. This plan explains how callers move to the contract and how an implementer proves conformance. It links to the contract's requirement IDs (FS, FC, FW, FX, FL, FN, FA, FP, FF) and decisions (FD-n) and restates none of the rules. Implementation is in progress on master. The issues linked in §7 track each item's status, and #527 tracks the downstream migration. The audit in §1 records the state at the audited commit, and the sign-off decisions stand as recorded. Code blocks are illustrative. Those that use an API or rule not yet implemented are future examples, and none is a doctest.

FC-11 amendment (2026-11-09). SparseIterate no longer specializes nnz, nonzeros, findnz or issparse. Use nactive, activevalues and paired activecoordinates/activevalues; sort copied entries explicitly when needed. dropzeros! remains. The conformance matrix below reflects this amendment; the earlier audit and sign-off record describe the prior API. Ordinary SparseVector and SparseMatrixCSC methods are unchanged.

3.3 Group trials in src/cd/groups.jl

The trial point goes into the model's buffer and through the five-argument form (FA-7); x is written only by prox_coordinate!.

# 0.6 (future); the QuadModel method changes the same way, with old - buf[i] / L
function _groupstep!(m::LSModel{T}, g::AbstractFunction, x::AtomIterate{T}, k::Int, scaled::Bool) where {T}
  G = atomindices(x, k)
  n = length(G)
  buf = _groupbuffer!(m, 2n)
  for (i, j) in enumerate(G)
    a, b = _column_dot(m, j)
    m.a[j] = a
    buf[i] = b
  end
  L = _groupcurvature!(m, x, k)
  for (i, j) in enumerate(G)
    old = x[j]
    buf[n + i] = old
    buf[i] = iszero(L) ? old : old + m.s * buf[i] / L      # the trial point, not written into x
  end
  prox_coordinate!(x, g, k, view(buf, 1:n), iszero(L) ? floatmax(T) : inv(L))
  maxh = zero(T)
  for (i, j) in enumerate(G)
    h = x[j] - buf[n + i]
    iszero(h) && continue
    _residual_axpy!(m, j, h)
    maxh = max(maxh, _scaledchange(m, x, j, h, scaled))
  end
  maxh
end

view(buf, 1:n) is a strided Float32/Float64 vector, so the group-norm kernels take the staging loop of src/interface.jl:484–493; buf is the model's (src/cd/leastsquares.jl:636) and does not alias x.

The workspace site. At 0.5.x, fill!(xs, 0) empties the working set and the loop then writes the nonzeros of ws.x in linear order, so the working set is the support of ws.x in increasing ID order for a SparseIterate, and for an AtomIterate the groups in the order in which the loop first meets a nonzero entry of each. The branch runs only when xs !== ws.x, that is, when the caller passed a Vector{T} with T <: AbstractFloat: _workspace_iterate (ProximalSolvers src/workspaces.jl:93–95) returns an iterate unchanged and otherwise builds xs from a copy of the vector (SparseIterate(x), src/sparse_iterate.jl:513–521; AtomIterate(x, groups), src/atom_iterate.jl:56–59), with the same element type. Keeping the loop after dropzeros!(fill!(xs, zero(eltype(xs)))) is equivalent. A cyclic coordinate descent from either follows the 0.5.x trajectory.

Failure guarantee. Neither recipe touches x when a check fails. The staged replace also leaves x unchanged if staging throws, because x is written only by the final state copy, whose element types agree: a failed read or conversion throws inside the loop (ran: into xj = SparseIterate(Int, 2); xj[2] = 5 from [1.0, 1.5], it throws InexactError and xj stays [0, 5] with working set [2]). Its cost is one similar(x), O(n) memory and time. The cheap shorthand has no failure guarantee past the checks: it clears first, so a failure after the clear loses the old state (ran: the same xi and source leave [1, 0] with working set [1]).

Why the checks and the separate indices. Without the element-type check a complex-typed source with zero imaginary parts passes: the staged loop and the cheap recipe both turn ComplexF64[1, 2, 3, 4] into [1.0, 2.0, 3.0, 4.0] today (ran), where FX-4's checked bulk write rejects it. A joint eachindex(t, A) asks for common indices, and on the IndexCartesian path equal axes: for x = SparseIterate(4) and A = view(reshape(1:4, 2, 2), [2, 1], :) it throws DimensionMismatch, while the separate traversal gives [2.0, 1.0, 4.0, 3.0] with working set [1, 2, 3, 4] (ran). eachindex(A) of an IndexCartesian source is column-major, which is linear order. The length check stays explicit, because zip truncates.

Why the cheap shorthand needs its conditions. A same-kind source dispatches to the state copy and brings its explicit zeros: with y = SparseIterate(4); y[4] = 2.; activate!(y, 1) the shorthand gives [4, 1] and the staged replace [4] (ran). An overlapping source is read after the clear: copyto!(dropzeros!(fill!(x, 0)), view(x, 2:-1:1)) of x = SparseIterate([1., 2.]) gives [0.0, 0.0], while the staged replace gives [2.0, 1.0] (ran). The shorter dropzeros!(copyto!(x, A)) gives the same set in another slot order (ran: [3, 2, 9] against [2, 3, 9]), which changes the trajectory of a cyclic active pass.

Baseline. Record the baseline at a pinned 0.5.x commit before any FD is implemented, additive ones included: master with the two groups added and no FD merged. Each FD pull request then reports its cases against that baseline in the same session, with benchmark/compare.py.

Gate and review thresholds (numerics C3). A repeatable slowdown above 5% on a representative case is investigated and reported on the implementing pull request, and merging it needs the maintainer's recorded approval (FP-6). A cost above 10% paid only by narrow types needs the maintainer's approval; machinery that only narrow types need leaves Float64 timings within the harness's noise.

What a benchmark can and cannot show. A flat curve over a factor of 100 in n is a regression alarm, not a proof of O(1); the proof is the code (a direct index table and no growth), a review item. Single runs are exploratory. A benchmark does not show correctness: every case is checked first, and FT01–FT23 carry the guarantees.
