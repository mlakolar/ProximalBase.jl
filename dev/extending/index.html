Writing your own function

A function is a subtype of AbstractFunction that declares its traits and implements the oracles they promise. Solvers written against the interface then accept it like the built-in functions.

Any function

TraitImplementYou get
alwaysthe value, (f::MyF)(x), Inf outside the domain
isproximableprox!(y, f, x, γ); y may be xprox, and value_and_prox! as prox! then f(y)
issmoothvalue_and_gradient!(g, f, x)gradient!, gradient, value_and_gradient
isconvex

Override value_and_prox! when the proximal computation gives the value more cheaply, and define lipschitz when a smooth function's constant is known. The traits are defined on the type:

using ProximalBase, LinearAlgebra

# the indicator of the box [-1, 1]ⁿ intersected with the hyperplane Σᵢ xᵢ = 0
struct CenteredBox <: AbstractFunction end
ProximalBase.isproximable(::Type{CenteredBox}) = true
ProximalBase.isconvex(::Type{CenteredBox}) = true
(::CenteredBox)(x) = all(abs.(x) .<= 1 + 1e-12) && abs(sum(x)) <= 1e-9 ? 0.0 : Inf

# the projection: x = clamp.(v .- τ, -1, 1), with τ chosen by bisection so that Σᵢ xᵢ = 0
function ProximalBase.prox!(y::AbstractVector, ::CenteredBox, v::AbstractVector, ::Real)
    lo, hi = minimum(v) - 1, maximum(v) + 1
    for _ in 1:100
        τ = (lo + hi) / 2
        sum(t -> clamp(t - τ, -1, 1), v) > 0 ? (lo = τ) : (hi = τ)
    end
    y .= clamp.(v .- (lo + hi) / 2, -1, 1)
end

y = prox(CenteredBox(), [3.0, 0.2, -0.4, 0.1], 1.0)
(y, sum(y))
([1.0, -0.10000000000000003, -0.7000000000000001, -0.20000000000000004], -1.942890293094024e-16)

The projection uses the same idea as the projection onto the simplex: the constraint $\sum_i x_i = 0$ has a multiplier $\tau$, and for a fixed $\tau$ the box projection is separable. Here a bisection on $\tau$ replaces Condat's exact search.

Separable functions

A separable function $f(x) = \sum_i f_i(x_i)$ subtypes SeparableFunction and implements two scalar functions:

  • value_entry(f, v, i), the value $f_i(v)$;
  • prox_entry(f, v, i, γ), the proximal operator of $\gamma f_i$ at $v$.

Here $i$ is the linear index of the entry, which lets parameters such as weights depend on it. The value, prox! and value_and_prox! then work on any array and on the three iterates, and prox_coordinate! works on the iterates. Declare iszeropreserving when $f_i(0) = 0$ and the proximal operator maps $0$ to $0$. Then the value and the proximal operator on a sparse iterate touch only its stored entries.

# Σᵢ wᵢ xᵢ² / 2: separable, with weights
struct WeightedSquare <: SeparableFunction
    w::Vector{Float64}
end
ProximalBase.value_entry(f::WeightedSquare, v, i) = f.w[i] * v^2 / 2
ProximalBase.prox_entry(f::WeightedSquare, v, i, γ) = v / (1 + γ * f.w[i])
ProximalBase.iszeropreserving(::WeightedSquare) = true
ProximalBase.isconvex(::Type{WeightedSquare}) = true
ProximalBase.check_parameters(f::WeightedSquare, x) =
  length(f.w) == length(x) || throw(DimensionMismatch("a parameter array has length $(length(f.w)) and the argument has length $(length(x))"))

f = WeightedSquare([1.0, 2.0, 4.0])
x = [1.0, 1.0, 1.0]
(f(x), prox(f, x, 0.5))
(3.5, [0.6666666666666666, 0.5, 0.3333333333333333])

The optional ProximalBase.check_parameters method checks that the weights fit the argument. The generic methods call it before writing any output, so a mismatched argument leaves outputs and iterates untouched. Before writing any output, SeparableSum, SliceSum and FiberSum check all blocks, slices or fibers, including functions inside wrappers, against the checks their own oracles run before writing. Earlier outputs can still be written if a failure occurs during computation, if a check depends on the step (such as MoreauEnvelope's sum of its parameter and step), or if a user-defined function's oracles reject an argument that its check_parameters accepts. A few nested wrappers and structured matrices whose checks are not yet complete, such as a box constraint inside another one, can also leave them written.

xs = SparseIterate(3)                          # a coordinate step on a sparse iterate
xs[2] = 1.0
prox_coordinate!(xs, f, 2, 0.5), nnz(xs)
(0.5, 1)

On a SymmetricSparseIterate, the index $i$ of entry $(r, c)$ is $(c - 1)p + r$. A function whose parameters depend on the entry must give $(r, c)$ and $(c, r)$ the same parameters, so that its value and its proximal operator are those of a symmetric matrix. Active-set solvers can also use kkt_violation and restrict, which you define for your type when it has the structure they need.

Testing a new function

ProximalBase.Testing has the checks that the package's own test suite runs on every built-in function. They are defined once the Test standard library is loaded, and they run @test inside your @testset:

  • test_prox: prox, prox! (also in place) and value_and_prox! agree, and the result is optimal (the subgradient inequality for a convex function, and no nearby point with a smaller proximal objective);
  • test_gradient: the gradient against central finite differences;
  • test_separable: prox_entry against prox!, value_entry against the value, coordinate steps on the three iterates, and the O(nnz) paths when the function preserves zero;
  • test_conjugate and test_kkt: Moreau's decomposition and the Fenchel–Young equality, and kkt_violation against the proximal operator;
  • allocations: the bytes a hot call allocates, measured inside a function after a warm-up call. The built-in allocation tests check these calls on Float32 and Float64 CPU arrays after warm-up. Check the methods and inputs you use on Julia 1.10 and on the current release, whose counts can differ.
using Test
const PT = ProximalBase.Testing
@testset "WeightedSquare" begin
    PT.test_traits(f; proximable = true, separable = true, convex = true)
    PT.test_prox(f, randn(3), 0.5)
    PT.test_separable(f, randn(3), 0.5)
    @test PT.allocations(prox!, similar(x), f, x, 0.5) == 0
end

brute_force_prox is a reference for a scalar proximal operator, convex or not.

Running the package suite

From the package checkout, run julia scripts/test.jl after adding or changing an implementation. This calls Pkg.test() with array bounds checking enabled and installs the dependencies needed for the package tests. No clones of other packages are required.
