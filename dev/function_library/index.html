Function library: choose a mathematical object

ProximalBase includes losses, regularizers, constraint indicators and functions composed from other functions. They are mathematical objects with a common AbstractFunction interface. Choose one by the objective you want to express; then consult Operations on functions to see what computations your algorithm can request.

The detailed pages below retain their formulas, proximal mappings, exceptions and algorithmic notes. This catalog is an entry point, not a complete list of supported signatures or a guarantee of every oracle for every function and argument type.

Smooth functions and losses

FamilySelected functionsTypical use
Elementary functionsZeroFunction, LinearFunction, SqrNormL2Constants, linear objectives, squared norms
Quadratic modelsQuadraticFunction, KronQuadraticQuadratic objectives on vectors or matrices
Statistical lossesLeastSquaresLoss, LogisticLoss, PoissonLoss, HuberLossRegression, classification and robust estimation
Matrix and other lossesLogDetLoss, BernoulliLossLikelihood and matrix estimation

Read Smooth functions for mathematical definitions, curvature and example uses. Some functions that provide a gradient also have a proximal map; check the capability and operand domain rather than relying solely on this classification.

Constraints as indicator functions

An indicator function returns 0 on its feasible set and Inf outside. For supported indicator functions, the proximal operation is a projection.

FamilySelected functions
Coordinate and norm boundsIndBox, IndNonnegative, IndBallL1, IndBallL2, IndSimplex
Linear constraintsIndHyperplane, IndHalfspace, IndHyperslab, IndAffine, IndPolyhedron
Cones and matrix constraintsIndSOC, IndPSD, IndBallRank, IndStiefel
Structure, intersections and cardinalityIndPattern, IndToeplitz, IndIntersection, IndBallL0, IndBallGroupL0

See Sets for the full supported constraint catalog, formulas, projection algorithms and numerical caveats. Some projections are computed iteratively; a returned result or value of zero does not necessarily certify exact feasibility.

Read Functions built from functions for the exact algebraic identities and which oracles propagate. Wrapper operations are not automatic for every combination of functions and types.

A small example

using ProximalBase

g = NormL1(0.5)
x = [2.0, -1.0]
@assert isproximable(g)
@assert prox(g, x, 1.0) ≈ [1.5, -0.5]
(family = typeof(g), value = g(x), proximal_point = prox(g, x, 1.0))
(family = NormL1{Float64, Nothing}, value = 1.5, proximal_point = [1.5, -0.5])
