ProximalBase.jl

Mathematical function objects and working-set storage for optimization in Julia.

Many statistical estimation problems take the form

\[\min_{x\in\mathbb R^p} F(x)=f(x)+g(x),\]

where $f$ is a smooth data-fitting loss and $g$ is a penalty. For example, least squares measures prediction error, while an $\ell_1$ penalty encourages zero coefficients. An algorithm needs to evaluate these functions, differentiate the loss and apply the penalty's proximal map:

\[\nabla f(x),\qquad \operatorname{prox}_{\gamma g}(v)=\operatorname*{argmin}_z \left\{g(z)+\frac{\|z-v\|^2}{2\gamma}\right\},\quad\gamma>0.\]

using ProximalBase
f = SqrNormL2(1.0)       # f(x) = ||x||²/2
g = NormL1(0.5)          # g(x) = ||x||₁/2
x = [2.0, -1.0]
@assert f(x) == 2.5
@assert gradient(f, x) == x
@assert prox(g, x, 1.0) == [1.5, -0.5]
(value = f(x), gradient = gradient(f, x), proximal_point = prox(g, x))
(value = 2.5, gradient = [2.0, -1.0], proximal_point = [1.5, -0.5])

ProximalBase supplies these mathematical operations and storage for iterates. A solver chooses the steps, update order, stopping criterion and working set. ProximalSolvers.jl implements optimization algorithms using such operations.

For convex $f$ and $g$, optimality is characterized by $0\in\nabla f(x)+\partial g(x)$. Coordinate methods apply this condition to individual entries or blocks. A working set records which coordinates a solver currently visits; it can include zeros deliberately retained for the next sweep. The coordinate guide connects these conditions to prox_block and kkt_violation.
