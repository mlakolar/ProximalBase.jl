Sparse iterates

ProximalBase provides three iterate types for coordinate descent and active-set procedures. We separate the choice of storage from the update formulas, which are derived in Coordinate descent.

IterateArray representedOne coordinate
SparseIterateA sparse vector or matrixOne entry
SymmetricSparseIterateA sparse symmetric matrixOne lower-triangular entry and its symmetric counterpart
AtomIterateA vector partitioned into groupsOne group of entries

Choosing an iterate

Choose the representation by the variable your algorithm updates rather than by whether the mathematical solution happens to contain zeros.

Problem / updateUseIndex spaces and behavior
Entrywise coordinate descent on vectors or general matricesSparseIterateOne coordinate per entry; x[k] and coordinates(x)[k] address the same value; ordinary array behavior
Optimization over real symmetric matricesSymmetricSparseIterateOne coordinate per independent lower-triangular variable; X[i,j] is symmetric, X[k] is intentionally unsupported
Group or block coordinate descent on a partitioned vectorAtomIterateOne coordinate per group; x[j] still indexes an entry; atom(x,k) accesses the group

All three keep a working set distinct from the mathematical nonzero support. Construction reserves storage proportional to the number of logical entries or groups; these types optimize inexpensive activation and active-set traversal, not compressed-sparse memory usage. Choose Julia's SparseVector/SparseMatrixCSC when compact storage is the priority. For matrix functions and Frobenius objectives, do not replace a symmetric owner with its independent-coordinate vector without accounting for the two matrix entries represented by an off-diagonal variable.

using ProximalBase

v = SparseIterate(4)
v[2] = 2.0
@assert ncoordinates(v) == 4 && nactive(v) == 1

X = SymmetricSparseIterate(3)
coordinates(X)[2] = 3.0
@assert X[2, 1] == X[1, 2] == 3.0 && ncoordinates(X) == 6

g = AtomIterate(6, [1:2, 3:4, 5:6])
g[2] = 1.0
@assert ncoordinates(g) == 3 && nactive(g) == 1
@assert collect(atom(g, 1)) == [0.0, 1.0]

The iterate determines the optimization coordinate, not the mathematical function being optimized. The same function may support multiple iterate representations, with different index spaces and active-set semantics. For quick examples and operation costs, use the type-specific guides before writing a solver.

Real-valued inputs and conversion

The entries of an iterate are real. A complex element type, or a complex operand of an iterate product, raises an ArgumentError; see Precision. Writing a complex source or value into a SparseIterate or an AtomIterate with the constructor, copyto!, copy!, a broadcast or fill! raises it too, before anything is written, even when the imaginary part is zero. A broadcast is checked for its leaves and for its result: a result known to be complex from the types is rejected, and a result of another non-real type (a Union with a complex member, Any, Number) is evaluated before writing and rejected if an element is complex. A write into either of them through a view, through vec of a matrix or a reshape to another shape, or through atom converts each value as a plain array would, so a complex value raises an InexactError, possibly after part of the iterate has been written. A SymmetricSparseIterate refuses a complex source or element type with an ArgumentError, and a complex value written to one of its entries raises an InexactError.

Entries and coordinates

prox_entry(g, v, i, γ) computes the scalar proximal operator of entry $i$ without writing the iterate. In contrast, prox_coordinate!(x, g, k, γ) reads coordinate $k$ of the iterate, applies its proximal operator and writes the result. The calling procedure must supply the gradient step before applying this proximal operation.

The two calls index different spaces:

  • prox_entry takes an entry $i$ of the array, the index of the weights and bounds.
  • prox_coordinate! takes a coordinate $k$ of the iterate.

The two coincide for a SparseIterate. A coordinate is a variable, an entry of the lower triangle, for a SymmetricSparseIterate, and a group for an AtomIterate.

Tracking an active set

The active coordinates form a stored working set, which can contain entries or groups that have returned to zero. We keep them during a sweep so that the set being traversed does not change.

OperationMeaning
ncoordinates(x)Number of possible coordinates
nactive(x)Number of stored active coordinates
activecoordinates(x)Read-only list of the indices of the active coordinates
activevalues(x)Writable view of their values, in the same order (SparseIterate and SymmetricSparseIterate)
isactive(x, k)Whether coordinate k is active
activate!(x, k)Add a coordinate to the active set
dropzeros!(x)Remove stored zero entries or zero groups

Scaling a SparseIterate by a number is a value write like x .*= s: with a finite multiplier or a finite nonzero divisor it touches only the stored entries. When the scalar maps zero to a nonzero value, every entry is written, and entries that become nonzero join the working set.

Use kkt_violation to test excluded zero coordinates and restrict to construct a supported restricted problem. The Coordinate descent chapter explains the full optimality checks that must accompany these storage operations.

What an oracle leaves in an iterate

After prox!, value_and_prox!, gradient!, mul! or prox_coordinate! writes a SparseIterate or an AtomIterate, the values of the iterate are the result, and every coordinate with a nonzero result is active. Which zero coordinates stay active is unspecified: it can depend on the function and on the type of the argument. Call dropzeros! to make the working set the support. prox_coordinate! follows the stricter rules of Steps on one coordinate.

In this example, group 1 of the destination is inactive and becomes nonzero, and group 2 is active and becomes zero.

using ProximalBase, LinearAlgebra

v = [3.0, 0.0, 0.0, 0.0]
oracles = [
    (y -> prox!(y, NormL1(1.0), v, 1.0), [2.0, 0.0, 0.0, 0.0]),
    (y -> value_and_prox!(y, NormL1(1.0), v, 1.0), [2.0, 0.0, 0.0, 0.0]),
    (y -> gradient!(y, SqrNormL2(1.0), v), [3.0, 0.0, 0.0, 0.0]),
    (y -> mul!(y, Matrix(2.0I, 4, 4), v), [6.0, 0.0, 0.0, 0.0]),
]
for (oracle!, result) in oracles
    a = AtomIterate(4, [1:2, 3:4])
    a[3] = 1.0                                      # group 2 active, group 1 inactive
    oracle!(a)
    @assert Vector(a) == result
    @assert isactive(a, 1)                          # the group with a nonzero result
    dropzeros!(a)
    @assert collect(activecoordinates(a)) == [1]    # the support
end

Counting coordinates

Four counts describe an iterate, and each has its own spelling.

CountSparseIterateAtomIterate
Coordinatesncoordinates(x) == length(x)ncoordinates(x), the number of groups
Active coordinates, stored zeros includednactive(x)nactive(x), the active groups
Nonzeroscount(!iszero, activevalues(x))entries: sum(k -> count(!iszero, atom(x, k)), activecoordinates(x); init = 0); groups: count(k -> any(!iszero, atom(x, k)), activecoordinates(x))
Capacitya slot for each of the length(x) entrieslength(x) values and a slot for each group

In 0.6, SparseIterate intentionally does not specialize nnz, nonzeros, findnz or issparse. Use nactive(x) to count stored entries (including explicit zeros), and pair activecoordinates(x) with activevalues(x) to traverse them in active-slot order. Sort a copied list of IDs if sorted output is needed. The size of a model is the number of nonzeros, count(!iszero, activevalues(x)), or nactive(x) after dropzeros!.

An AtomIterate has no nnz, nonzeros, findnz or activevalues; calling them throws a MethodError. Loop over its active entries with for k in activecoordinates(x), j in atomindices(x, k), reading or writing x[j].

The slots of both iterates are reserved at construction, so activating a coordinate does not change the size of the arrays that the iterate stores.

A SymmetricSparseIterate has no nnz. nactive(x) counts the active variables of the lower triangle, active zeros included; ncoordinates(x) is $p(p+1)/2$. Because an off-diagonal variable counts once, and an active zero counts too, nactive(x) can differ from the number of nonzero entries of Matrix(x); for that number count Matrix(x) or sparse(matrixview(x)). Its other counts are tracked in #391.

using ProximalBase, SparseArrays

y = SparseIterate(5)
y[4] = 1.0
activate!(y, 2)                                     # an explicit zero
@assert nactive(y) == length(activevalues(y)) == 2
@assert collect(activecoordinates(y)) == [4, 2] && activevalues(y) == [1.0, 0.0]
@assert sort(collect(zip(activecoordinates(y), activevalues(y))); by = first) == [(2, 0.0), (4, 1.0)]
@assert count(!iszero, activevalues(y)) == 1        # the model size
dropzeros!(y)
@assert nactive(y) == 1

a = AtomIterate(6, [1:2, 3:4, 5:6])
a[1] = 1.0
a[4] = -2.0
activate!(a, 3)                                     # an active group of zeros
entries = sum(k -> count(!iszero, atom(a, k)), activecoordinates(a); init = 0)
groups = count(k -> any(!iszero, atom(a, k)), activecoordinates(a))
@assert (ncoordinates(a), nactive(a), groups, entries) == (3, 3, 2, 2)
@assert sum(a[j]^2 for k in activecoordinates(a) for j in atomindices(a, k)) == 5.0
try
    nnz(a)
    error("expected a MethodError")
catch e
    @assert e isa MethodError
end

m = SymmetricSparseIterate(3)
m[2, 1] = 3.0
@assert nactive(m) == 1 && count(!iszero, Matrix(m)) == 2
@assert nnz(sparse(matrixview(m))) == 2             # the entries of the matrix, counted by position
try
    nnz(m)
    error("expected a MethodError")
catch e
    @assert e isa MethodError
end
