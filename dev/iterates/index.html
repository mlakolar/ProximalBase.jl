Overview and working sets

Assumes: vectors, matrices and basic optimization iterations · You will learn: when to use specialized storage and what active coordinates mean.

For full-vector methods such as ordinary proximal gradient, a plain Julia Vector (or Matrix) is often all the storage you need. Use SparseIterate, BlockIterate or SymmetricSparseIterate when an algorithm repeatedly visits only a selected working set of coordinates, groups or independent symmetric-matrix entries. These types make working-set access and updates convenient, but they are not compressed-memory sparse matrices.

An iterate stores the current optimization variable. A coordinate is active here when it is explicitly stored or chosen for visits, not when an inequality constraint holds with equality as in standard KKT terminology. A zero coordinate may remain active so a solver checks it on its next sweep.

These provide sparse work, with direct lookup tables and reserved slots; they are not compressed sparse formats for avoiding memory proportional to the full coordinate domain. For an algorithm that updates every coordinate at each step, a regular array is often simpler.

Entries, coordinates and active slots

For SparseIterate, coordinates are Julia linear entry indices. For symmetric matrix storage, coordinates number the independent lower triangle, while matrix indices include both mirrored entries. For BlockIterate, x[j] still indexes an entry, but coordinate k names a group. An active slot is the position in a packed list of coordinate IDs. It is not a coordinate ID and can move on compaction.

The exported nnz is SparseArrays' binding for standard sparse arrays. There is no nnz, nonzeros or findnz method for these iterates. Count a SparseIterate's nonzeros using count(!iszero,activevalues(x)); for a symmetric iterate that counts independent nonzeros, not full-matrix entries. For blocks, sum count(!iszero,blockview(x,k)) over active group IDs.

Active coordinates are deliberate state

Writing a nonzero converted value activates its coordinate. Writing zero to an absent coordinate leaves it absent; writing zero to an active coordinate keeps it active. activate!(x,k) explicitly retains a zero coordinate, and dropzeros!(x) removes zero coordinates/all-zero groups. NaN/Inf are nonzero for this rule; signed zeros are zero.

using ProximalBase
x = SparseIterate(4)
activate!(x,3)
x[1] = 2
x[1] = 0
@assert nactive(x) == 2 && count(!iszero,activevalues(x)) == 0
saved_ids = collect(activecoordinates(x))
dropzeros!(x)
@assert nactive(x) == 0 && saved_ids == [3,1]
nactive(x)
0

Acquire activecoordinates and activevalues again after any activation, compaction or whole-state replacement. Handles retain their old extent and refer to live slots; they are not snapshots. Coordinate and matrix views keep their stable index mapping for the iterate's lifetime. Never modify private metadata through fields or a view's parent indices.

Copies and mathematical operations

copy(x) copies values and working-set state independently. similar(x) is empty storage of the same kind/shape/layout. Same-kind state copies replace the destination's active set when shapes/layouts match. Ordinary array writes, broadcasts and most mathematical proximal writes preserve already active coordinates. A fresh allocating prox can omit the source's active zeros. ZeroFunction is a copying exception: its distinct array-iterate output uses copyto!, replacing state for matching SparseIterate shapes/BlockIterate layouts. Its symmetric-iterate route instead uses coordinate value writes.

For BlockIterate, same-layout copyto! replaces state; different layouts of the same entry length copy by value. A symmetric iterate's copyto!(x,A) is a checked import, replacing state with nonzero coordinates in increasing order. See the individual guides for validation and failure behavior.

Supported products

The following sparse-aware operations are available for these iterate types. Real types and compatible dimensions are required. Other Julia fallbacks can be dense, slower, or absent. Use independent product destinations: ordinary mul! does not permit arbitrary aliasing. The symmetric iterate methods explicitly reject overlapping output/input storage.

Specialized products skip zero iterate coefficients, including stored zeros, even against NaN/Inf in the other operand. This differs from an ordinary dense IEEE 0*Inf. A coordinate view has ordinary vector products and does not inherit sparse work or strong-zero semantics. See array conventions.
