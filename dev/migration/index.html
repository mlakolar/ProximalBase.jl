Compatibility and migration

For terms used in the current manual, see the Glossary.

This manual describes the minimal core after merged PR #850, based on 2b373c54. The full post-#848 implementation and its documentation are preserved at eff21b6d7d33c622313122f46c6ee71693c101ee and legacy/full. Those archives are historical references, not a second live API. This development reduction is not a release announcement.

Retained and removed scope

The function library is exhaustive. Norms and group penalties other than NormL1, NormL2, NormLinf, GroupNormL2, GroupNormLinf and SparseGroupNormL2, nonconvex penalties, robust-loss families, Poisson families other than PoissonLoss, constraints and indicators other than IndNonnegative, IndBox, IndBallLinf, IndBallL1, IndBallL2 and IndBallL0, spectral/nuclear families, generic composition/sum wrappers, LMO, second-order frameworks and GPU extensions were removed. They have no replacement capability implied by this manual. BlockIterate retains grouped storage; the group-lasso penalty GroupNormL2 and the norm NormL2 were restored separately (#900), and the norm NormLinf (#946) and the group norm GroupNormLinf (#956). The restored indicators are IndNonnegative (#948), IndBox (#949), IndBallLinf (#954), IndBallL1 (#955) and IndBallL2 (#950). IndBallL0(s; diagonal = true) (#1084) is restored for dense vectors and matrices, SparseIterate, dense Symmetric, and SymmetricSparseIterate with Float32 or Float64.

Keep two function objects for f(x)+g(x); no generic function-object sum is retained. Compute mathematical gradient mappings in caller code. Coordinate curvatures and residual/working-set policies are algorithm responsibilities. ProximalSolvers migration is separate; this documentation does not change it.

Sparse group lasso

SparseGroupNormL2 is available with the 0.6 array and compact-block interfaces. Both penalty terms still apply to the union of the groups. Convert a per-group update to prox_block!(out, f, u, k, γ) with an independent compact buffer and one scalar step. With a matching BlockIterate, commit the result separately using copyto!(blockview(x, k), out). For full-array calls, pass a single scalar step. The former hierarchy, per-group step arrays, prox_coordinate! and restrict are absent.

Call kkt_violation(f, v, x, k) with the actual point. It gives a signed screen at a zero group and measures the block subgradient distance at an active group. A full-point call reduces these scores together with the uncovered entries. A stored infinite constraint projects onto its domain at zero step, and negative or NaN steps fail before writing. See the numerical endpoints.

Logistic regression

LogisticLoss(y, X; weights, offset) is available as a standalone smooth loss. It requires finite responses in [0, 1], including on zero-weight rows. The archived logistic constructor did not validate the response domain. The current constructor uses homogeneous strided Float32 or Float64 vectors and accepts a strided or CSC design. See logistic regression.

Poisson regression

PoissonLoss(y, X) is available as a standalone smooth loss for dense Float64 data. It takes the sum over observations of exp(ηᵢ) - yᵢηᵢ at η = X*β, requires finite nonnegative responses, and has no weight or offset argument. A caller who forms η = X*β + offset evaluates the offset model through the predictor oracles. It does not restore the archived scalar ProximalBase.Poisson() loss or the archived GLMLoss wrapper, and it has no second-order interface. See Poisson regression.

Removed scalar-loss interface (0.6, breaking)

ProximalBase 0.6 removes the qualified-public ProximalBase.ScalarLoss and ProximalBase.Squared types and their scalar derivative interface (ProximalBase.deriv, ProximalBase.deriv2, ProximalBase.curvature, ProximalBase.value_and_deriv) (#916). No retained loss in ProximalBase used them, and the names were not exported. A qualified reference such as ProximalBase.deriv, a subtype declaration <: ProximalBase.ScalarLoss, and a qualified method definition such as ProximalBase.deriv(ℓ::MyLoss, η, y) = … raise UndefVarError. What import or using of these names reports, and what a later unqualified method definition does, depends on the Julia version and the form used. For least squares, use LeastSquaresLoss and its predictor/residual operations (ProximalBase.value_from_predictor, ProximalBase.value_and_gradient_from_predictor!, ProximalBase.value_from_residual, ProximalBase.leastsquares_data; see Least squares at a caller-held predictor or residual). For squared-norm regularization, use SqrNormL2. Code that relied on this interface can implement the operations it needs through the AbstractFunction interface, or keep its own scalar-loss types and functions.

Mixed-type range in squared and absolute norms (0.6)

SqrNormL2, NormL1, and NormL1Nonneg use the ordinary conversions described in the numerical contract when the affected mixed-type calls narrow a center or level. For example, gradient(SqrNormL2(2.0^160), Float32[2f0^-80]) gives Float32[Inf] because the level rounds to Inf32. The previous development path produced a finite result by multiplying in the wider type. Use homogeneous Float64 inputs if a center or level needs its range. See #1010.

Scaled built-in indicators are the indicators (0.6, breaking)

For IndBallL0, IndBallL1, IndBallL2, IndBox (including IndBallLinf) and IndNonnegative, Scaled(f, α), α * f and f * α return f itself for any nonnegative α, including 0, -0.0 and Inf, and nested scalings of f return f (#1080). The explicitly parametric constructor Scaled{F, T}(f, α) does the same, with the usual constraints f isa F and α isa T. Negative, NaN and -Inf factors throw ArgumentError. Before 0.6 these calls with a positive scale went through a Scaled wrapper whose step arithmetic, validation and errors could differ from the indicator's; code that relied on them, or on isa Scaled, .f or .α of the result, must be updated. A call on the result is a call on the indicator:

  • prox(Inf * IndBallL0(1), [3.0, -1.0], 1.0) projects to [3.0, 0.0].
  • prox(2 * IndBallL0(1), [3.0, -1.0], typemax(Int)) projects to [3.0, 0.0], and prox(2 * IndBallL0(1), [3.0, -1.0], -typemax(Int)) throws ArgumentError.
  • A complex step to prox! on 2 * IndBallL0(1) throws ArgumentError.
  • value_and_gradient!(x, 2 * IndNonnegative(), x) with the same array as input and output throws MethodError, because the orthant has no gradient method.
  • IndBallL0 accepts the step Inf; the projection does not depend on the step. A negative or NaN step is refused before writing. Calls that reach the step check raise ArgumentError with a message that begins "the step of IndBallL0 must be nonnegative"; for an otherwise supported input and output pairing, a wrong output extent raises DimensionMismatch first.
  • A negative or NaN scalar step makes prox, prox! and value_and_prox! of α * IndBox(...), α * IndBallLinf(...) and α * IndNonnegative() throw ArgumentError before writing; another check (argument axes, shape or type) can raise its error first. prox_block of the box and of the orthant ignores the step.
  • iszeropreserving(Inf * f) is that of f: true for the orthant and for a box whose every interval contains zero.
  • 0 * (Inf * f) and Scaled(Scaled(f, Inf), 0) return f.
  • check_parameters, entry_parameters, value_entry and the SeparableFunction dispatch see the indicator. For example, check_parameters(2 * IndBox([0.0, 0.0], [1.0, 1.0]), x) throws DimensionMismatch for a one-based x whose length differs from that of the bound arrays.
  • An unsupported kkt_violation form raises the MethodError of the indicator when the other checks of the call pass. Among these indicators only IndNonnegative has a three-argument screen.
  • typeof, .f and .α, isa Scaled, ==, hash and show of the result are those of the indicator.

The four-argument kkt_violation reads the point (0.6, breaking)

Before 0.6, for NormL1, ElasticNet, ZeroFunction, LinearFunction and SqrNormL2, kkt_violation(g,v,x,k) returned the screen of coordinate k assumed zero, also when x[k] was nonzero. In 0.6 it evaluates the actual coordinate or group: at a zero coordinate it is the signed screen as before, and at a nonzero coordinate it is a nonnegative stationarity mismatch. The three-argument form kkt_violation(g,v,i) is unchanged. With g = NormL1(0.5), x = [0, 0, 2, -1] and v = [0.8, 0.2, 0, 0.5] (values to rounding):

A new full-point form gives kkt_violation(g,v,x) = 0.5 here, the nonnegative $\max(0,\max_k s_k)$. A positive score at a nonzero coordinate is a stationarity mismatch and not an instruction to set the coordinate to zero.

GroupNormL2 follows the same rule for a group. With g = GroupNormL2(1.0, [[1, 2], [3, 4]], [1.0, 1.0]), x = [3, 4, 0, 0] and v = [-0.6, -0.8, 0.3, 0.4], the vector v is stationary on the first group. Before 0.6 the call at entry 1 returned a surrogate that is not a score of the group (the entry of v, or the group screen, or an ArgumentError, according to the version); in 0.6 it returns the block mismatch $\lVert v_G+c\,x_G/\lVert x_G\rVert_2\rVert_2$, which is zero up to rounding (of the order of 1e-16 in Float64), and the zero group scores $\lVert v_G\rVert_2-c=-0.5$:

3, 4zero-0.5

The full-point value is the maximum of 0 and of the positive block scores, here about 0; it is a maximum of block 2-norms, not an $\ell_\infty$ distance. NormL2 and NormLinf have the full-point form and no other.

What did not change, for the unscaled functions and for a single wrapper with a finite positive factor (nested wrappers with a product of factors that is not a normal number, and infinite factors, have the changes listed below):

  • Three-argument calls kkt_violation(g,v,i), except the screen of a nested wrapper around LinearFunction and a centered SqrNormL2 (corrected below) and of NormL2 and NormLinf (an ArgumentError below).
  • Four-argument calls at zero coordinates, when x, v and the function's parameters (levels, weights, centers and coefficients) are Float32 or Float64 arrays and values of one type, v is finite and the function is not a SqrNormL2 with an infinite level: they return the same values as before. A working-set solver that ranks the inactive coordinates of a SparseIterate with the four-argument form in that case is unaffected in the values it receives, although each call of the four-argument form does more work than a call of the screen (see scoring a coordinate). Outside that case the arithmetic is in the working type of the call, which can differ: for f = SqrNormL2(0.1, Float32[1]), v = Float32[1] and x = Float32[0] the value was the Float64 0.9 before 0.6 and is the Float32 0.9f0 in 0.6. The same applies to GroupNormL2 at a zero group, whose result type was that of v alone.
  • The group screen of GroupNormL2 at a zero group (on an array point, for an entry of a zero group), and its value abs(v[i]) for an entry in no group, for x, v and the parameters of one floating type and a finite v. One value of a zero group differs from the screen of earlier versions: an infinite entry of v with an infinite coefficient is +Inf, where the screen was NaN (Inf - Inf).
  • Scaled over GroupNormL2: the screen at a zero group, and the value for an entry in no group (kkt_violation(Scaled(GroupNormL2(1.0, [[1]], [1.0]), 2.0), [0.0, 3.0], [0.0, 1.0], 2) is 3.0), for a single wrapper with a finite positive factor and under the same conditions.

What changed besides the values of the table:

  • GroupNormL2 at a group with a nonzero entry, on a BlockIterate or on an array point, has the block mismatch (see above), and so has Scaled over GroupNormL2 and, at a nonzero coordinate, Scaled over NormL1, ElasticNet, ZeroFunction, LinearFunction or SqrNormL2 (the score evaluated on v/α, times α). A malformed parameter at the selected entry raises its own error first.
  • The result type of the point-aware forms of the unscaled functions is W = float(promote_type(eltype(v), eltype(x))) (with the element type of a parameter array for LinearFunction and a centered SqrNormL2). A single Scaled wrapper also promotes with the type of the reciprocal factor, and a smooth chain includes the type of its factors: kkt_violation(2 * NormL1(0.5f0), Float32[1], Float32[1], 1) is a Float64. A Float32 gradient with a Float64 iterate, such as the default BlockIterate(p, f), gives a Float64 score for GroupNormL2, where earlier versions gave the type of v. The branches of the scaled forms are in the numerical contract.
  • NormL2 has the full-point form kkt_violation(f,v,x). Its three-argument and four-argument forms, which were a MethodError, throw an ArgumentError that names the full-point form.
  • NormLinf has the full-point form kkt_violation(f,v,x): the Euclidean distance from -v to the subdifferential of λ*maximum(abs, x) at x, with the face of the largest entries decided by equality after conversion to the working type (see the ℓ∞ norm). In 0.5.4 the three-argument and four-argument calls were a MethodError; a call on a positive Scaled was forwarded to the inner function, so that the error named NormLinf, and there was no full-point form of any function. Now the full-point form has the value, also under Scaled with the limits of the scaling guide, and the three-argument and four-argument forms throw an ArgumentError that names the full-point form; the full-point form at a SymmetricSparseIterate throws an ArgumentError.
  • LeastSquaresLoss and QuadraticFunction now support kkt_violation(f,v,x), the infinity norm of the computed stationarity residual. Coordinate, group and symmetric-iterate point forms throw ArgumentError. The new call uses function-owned scratch and can allocate a coefficient buffer on its first use with a loss. See smooth stationarity scores for the ownership rules and the caller-supplied gradient recipe.
  • Nested Scaled wrappers whose product of factors is not a normal number: around LinearFunction and a centered SqrNormL2 the three-argument screen returned the screen of the function at the unscaled v and omitted the product; it now applies the product to the gradient entry of the function (Scaled(Scaled(LinearFunction([1.0]), 1e-200), 1e-200) at v = [0.25] was 1.25 and is 0.25). Around NormL1, ElasticNet, GroupNormL2, NormL2 and NormLinf whose level folds (to a nonzero finite level that its type accepts: a normal one, or a subnormal one for a Float32 or Float64 level), a GroupNormL2, NormL2 or NormLinf chain now scores with the folded level (for NormLinf the full-point form, which is its one form) (a GroupNormL2 chain at a zero group was computed from v divided by the product, which overflows for an ordinary v). Where the level does not fold, the three-argument screen of NormL1 and ElasticNet and the four-argument form of NormL1, ElasticNet and GroupNormL2 at a zero coordinate or group have the value of the definition at finite entries of v (NaN and infinite entries as the scaling guide states), computed from the coefficient a·λ·w, with the exponents of the three applied in one last step for a positive finite λ and w (a zero weight gives the coefficient 0, an infinite weight or level gives Inf, and an ElasticNet with an infinite λ2 gives -Inf) (Scaled(Scaled(NormL1(1.0), 2.0^-600), 2.0^-600) at v = [0.25] was Inf and is 0.25). NormLinf has no screen: around a chain whose level does not fold it was a MethodError in the three-argument form and at a zero coordinate, and it is now an ArgumentError there and in the full-point form. A nonzero coordinate or group and the full-point form throw an ArgumentError, as does an infinite factor (see the scaling guide). A stack that nests an infinite factor with another Scaled wrapper is built by a direct call of the parameterized constructor Scaled{F,T}(f, α) (Scaled(f, α) and α * f merge the factors): its three-argument and zero-coordinate values are unspecified and can differ from 0.5, and the nonzero and full-point forms throw an ArgumentError.
  • GroupNormLinf has the margin ‖v_G‖₁ - λ0 w of its dual norm at a zero group and, at a nonzero group, the Euclidean distance from -v_G to the subdifferential of λ0 w ‖·‖∞ at x_G; its full-point form is the maximum of zero, of abs(v[i]) for the entries in no group and of the distance of every group, where a zero group has its distance to the ℓ₁ ball of radius λ0 w and not its margin. The three-argument form throws an ArgumentError. Before 0.6 (the legacy implementation) it returned the margin for a group of a BlockIterate, also where the group was nonzero, and abs(v[i]) at an entry of a nonzero group of an array point, neither of which is a score of the nonzero group; the Euclidean screen of GroupNormL2 is not used for it (#634). Scaled over it has the routes of GroupNormL2 (the scaling guide).
  • Scaled over a function of the package without a score (for example SqrtLeastSquaresLoss, in the four-argument and full-point forms) throws a MethodError for the call on the Scaled function; the MethodError named the inner function and a private array type before. For the built-in indicators see the note on scaled built-in indicators above (#1080).
  • A function defined outside the package gets its three-argument method's value at a zero coordinate and an ArgumentError at a nonzero one, on arrays, a BlockIterate and a SymmetricSparseIterate, unless it defines the four-argument method; see Writing your own function. Under Scaled, a function that has a four-argument method of its own was scaled through that method at a nonzero coordinate too; it now gives its scaled three-argument screen at a zero coordinate and an ArgumentError at a nonzero one, unless the methods for Scaled{<:TheirType} are defined.
  • On a SymmetricSparseIterate the four-argument form reads the stored value of the coordinate, and its score is in matrix-entry units. The full-point form throws an ArgumentError there.
  • For arrays and BlockIterate, length(v) must equal length(x) (DimensionMismatch).

If code relied on the old value at a nonzero coordinate, call the three-argument form kkt_violation(g,v,i), which is the screen of the coordinate assumed zero.

A symmetric A need not be positive semidefinite. The check applies to a singular positive semidefinite A whose computed λmin is slightly negative from rounding, at steps with γT·(-λmin) ≥ 1 (about γ ≥ 1/|λmin|); at those steps the earlier kernel divided by a computed denominator 1 + γT·λmin ≤ 0. A matrix with λmin ≥ 0, and a negative step, are not checked and behave as before. For a nonnegative finite γT and finite cached eigenvalues, the check accepts exactly when every computed denominator 1 + γT·λi is positive. In exact arithmetic and for γ > 0, the proximal subproblem has a unique minimizer if and only if 1 + γ λmin(A) > 0 for the true smallest eigenvalue, so near that boundary the check can accept a step for which the true I + γA is not positive definite, and reject one for which it is.

A caller that knows A ⪰ 0 and relies on convexity asserts it at its own model boundary, and does so again after changing A. A successful prox does not establish convexity.
