Operations on functions

This is the user-facing catalog of operations that ProximalBase exposes for function objects. Choose an operation by the question your algorithm needs answered, then check the corresponding function's supported traits, operand types, and documentation. The API reference provides complete method docstrings; this page explains the roles and how the operations fit together.

The central convention is output first for mutating oracles: write gradient!(out, f, x) or prox!(out, f, x, γ). Allocating variants, when available, create and return an output. An exclamation mark alone does not guarantee zero allocations; see Array and numerical conventions.

Function values and first derivatives

OperationInputs / resultUse
f(x)Scalar value at xEvaluate an objective, loss, penalty or indicator; Inf can denote infeasibility
value_entry(f, v, i)Entry valueEvaluate entry i of a supported separable function, using scalar v
gradient!(out, f, x)Writes gradient into out; returns outUse in a smooth first-order algorithm
gradient(f, x)Allocated gradientConvenience form of gradient!
value_and_gradient!(out, f, x)Writes gradient; returns f(x)Reuse shared work between value and gradient
value_and_gradient(f, x)Allocated pair (f(x), gradient)Convenience combined form
lipschitz(f)Known gradient-Lipschitz bound, possibly InfStep-size selection for supported smooth functions
opnorm2(X)Operator-norm estimate for a matrix, not a function oracleLarge matrix norm estimation; an estimate is not automatically a valid upper bound

A true issmooth(f) trait provides differentiability and a gradient, but does not promise that lipschitz(f) is finite. Use a line search or appropriate theory when the known bound is infinite or not available.

Proximal operators and projections

OperationInputs / resultUse
prox!(out, g, x, γ)Stores proximal point in out; returns outRegularization, proximal gradient and projection
prox(g, x, γ)Allocated proximal pointConvenience form
value_and_prox!(out, g, x, γ)Writes proximal point; returns the function value at the resulting pointAvoid separate evaluation when available
prox_entry(g, v, i, γ)Scalar proximal point at entry iCoordinate descent with a separable penalty
shrink(v, c)Soft-thresholded scalar or supported inputLow-level shrinkage utility, not a generic function oracle

For a set indicator g = IndBox(l, u) or another proximable indicator, prox! computes a projection in the supported domain. For a penalty such as NormL1, it computes shrinkage. Not every function with a proximal map supports array-valued steps or every backend; consult the specific docstring. The return value of value_and_prox! is not automatically a feasibility certificate for an inexact projection.

using ProximalBase

f = SqrNormL2(1.0)
g = NormL1(0.5)
x = [2.0, -1.0]

grad = similar(x)
value_at_x = value_and_gradient!(grad, f, x)
@assert value_at_x ≈ f(x) && grad ≈ gradient(f, x)

out = similar(x)
value_at_prox = value_and_prox!(out, g, x, 1.0)
@assert out ≈ prox(g, x, 1.0)
@assert value_at_prox ≈ g(out)
(value_at_x = value_at_x, grad = grad, prox = out, value_at_prox = value_at_prox)
(value_at_x = 2.5, grad = [2.0, -1.0], prox = [1.5, -0.5], value_at_prox = 1.0)

For mathematical derivations and step-size geometry, read The interface.

Coordinate descent, restrictions, and optimality

OperationUse
prox_coordinate!(x, g, k, γ)Proximal step on coordinate k of an iterate, using its current value
prox_coordinate!(x, g, k, u, γ)Step at a supplied scalar/group trial point u without writing the trial first
coordinate_lipschitz(f, k)Coordinate curvature bound when defined by the smooth loss
coordinate_lipschitz!(out, f)Fill supported per-coordinate bounds in a caller-provided output
kkt_violation(g, grad, i)Screen entry i at zero against the smooth-part gradient
kkt_violation(g, grad, x, k)Screen coordinate k of the supplied iterate; group and symmetric geometry matter
restrict(f, S)Construct the supported restriction of a function to selected coordinates
gradient_mapping(f, g, x, γ)Allocate a proximal-gradient optimality residual for f+g
gradient_mapping!(out, f, g, x, γ)Write the residual into out

The curvature, restriction and screening methods are not available for arbitrary functions merely because they subtype AbstractFunction. gradient_mapping is for an AbstractArray point, not the non-array symmetric owner. prox_coordinate! acts on optimization coordinates: entries, independent symmetric variables, or groups depending on the iterate. For the actual active-set and trial-point rules see Coordinate oracles and Coordinate descent.

Second-order and model operations

OperationUse
hashessian(f)Ask whether the second-order interface is provided
hessian_vec!(out, f, x, v)Hessian-vector product, writing into out
hessian_vec(f, x, v)Allocating Hessian-vector product
quadratic_model(f, x)Construct a quadratic model of a supported function around x
quadratic_model!(model, f, x)Refresh/update a compatible model

These are specialized mathematical computations, not generic automatic differentiation. A Hessian trait is a capability declaration, not a promise that arbitrary functions or devices have second-order kernels. Consult the second-order API reference.

Linear minimization and compact atoms

OperationUse
haslmo(C)Check whether a particular set instance has a supported linear minimization oracle
lmo!(out, C, g)Solve the supported linear minimization subproblem over C, writing the minimizer
lmo(C, g)Allocating linear minimization oracle
lmo_atom(C, g)Return a compact atom in the supported cases, rather than a full dense minimizer
VertexAtom, LowRankAtomRepresent compact vector and low-rank atoms used by certain linear minimization oracles

This is useful for Frank–Wolfe / conditional-gradient methods. haslmo depends on the instance, for example whether a set has finite bounds. The atom form is specialized to sets with a meaningful compact representation; it is not guaranteed for every set supporting lmo!.

Local linear approximation for nonconvex penalties

OperationUse
lla_weight(f, v, i)Scalar reweighting coefficient of a supported penalty
lla_weights!(out, f, x)Compute reweighting coefficients into supplied storage
lla_weights(f, x)Allocated weights

These operations support locally linearized or reweighted algorithms for selected penalties, not an automatic nonconvex solver. See the penalty catalog for supported functions.

Capability and state queries

OperationMeaning
issmooth, isproximable, isseparable, isconvexDifferentiability, proximal capability, separability, convexity
hashessian, haslmo, iszeropreservingSecond-order capability, instance-specific linear minimization, zero-preservation
reset_cache!(f)Invalidate supported function-owned cached state after relevant external data mutation

Traits and their qualifications are described in Function objects and capabilities. Avoid equating a capability with specialized support for every possible argument type.

Where the remaining public API belongs

Other exports do not represent mathematical-function oracles. SparseIterate, SymmetricSparseIterate and AtomIterate, together with ncoordinates, coordinates, nactive, activecoordinates, activevalues, matrixview, isactive, activate!, atom, atomindices and dropzeros!, belong to the Iterates and iterate API reference. nnz is re-exported for ordinary sparse arrays; it does not define the number of active coordinates of an iterate.

norm_diff, tril_index and tril_cartesian are general or indexing utilities, described in the API reference. PrecisionError represents a numerical issue, discussed in Array and numerical conventions. SeparableFunction is a function subtype for authors of custom functions; see Writing your own function.
