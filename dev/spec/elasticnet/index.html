Supported arguments

The retained parenthetical “above” refers to the two-part value recomputation now described in Range clauses.

The array w has one weight per entry of the argument, paired by Julia's linear index, and is stored by reference. ElasticNet accepts real dense vectors and matrices (views included), SparseIterate, BlockIterate and SymmetricSparseIterate, with a scalar step or, except as noted below, an array of per-entry steps. On a SparseIterate or a SymmetricSparseIterate the value reads the stored entries only, and so does the proximal operator from such an iterate into an iterate of the same kind; with a dense destination it writes, and reads the weights of, every entry. This is the traversal of the entries: a value whose two parts are recomputed together (above) also reads every entry of a weight array whose element type is not concrete, such as a Vector{Real}, to choose the type of its accumulator. An entry stored in an iterate destination stays stored, possibly as a zero, and a zero result does not activate an absent entry. On a SymmetricSparseIterate the weights are a p × p matrix read at both positions of an off-diagonal coordinate, and the value counts such a coordinate twice, as the matrix it represents does. The weights must then be exactly symmetric, a precondition that the oracles assume and check_symmetric_parameters validates (see Symmetric parameters).

Not supported: an array of steps with a SymmetricSparseIterate destination (an ArgumentError before any write), or with a dense destination and a SymmetricSparseIterate argument (a MethodError); the vector form of prox_block; complex arguments or weights.

Range clauses

In the retained text below, “the recovery above” refers to the shared Range guarantees. Existing implementation details remain alongside the stated bounds; this move does not assign them a clause status.

ElasticNet values are the value of the ℓ₁ part, computed as NormL1 computes it, plus the value of the ridge part, computed as SqrNormL2 computes it, each with the recovery above, then one addition; on sparse and symmetric iterates both parts read the stored entries only, and on a BlockIterate its storage. On a dense Float32 or Float64 Array with parameters of its type, a single pass over the entries is returned instead when a test on its sum bounds its relative error by (n + 2) eps(T) for n ≤ 1/(2 eps(T)) - 2 entries; the bound is proved in a comment next to the code (src/functions/elasticnet.jl). With both levels positive and finite, a sum of the two parts below 2 floatmin(T) (each part rounded on its own) is recomputed: the terms of both parts are added in one exponent-sum accumulator, as the NormL1 recomputation adds its terms, and the sum is rounded once. For N nonzero terms (λ1*w[i]*abs(x[i]) and λ2*x[i]^2/2, up to two per entry and three per off-diagonal coordinate of a symmetric iterate), with u half the epsilon of the accumulator (Float64 for Float32 data) and N u < 1, the hypothesis of the summation bound used, the result is within (γ_3 + (γ_{N-1}^2 + N 2^-1070)(1 + γ_2)) V of the exact value V plus half a spacing of T at the result (γ_m = m u/(1 - m u)), as proved next to the code, which is below the worst case of the separate parts. On Julia 1.10 ldexp returns 0 for a Float64 result in [δ/2, δ), δ the smallest subnormal (#896), and the final term of the bound is a whole spacing; ElasticNet(2.0^-538, 1.0)([2.0^-537]) is 2.0^-1074. Only a value whose stored entries are all zero keeps its sum. Under Scaled, the value of an ElasticNet is recovered as for any function with levels. For a finite positive factor, where that gives no finite value, or 0 at a point where the function is not exactly 0, the scaled values of the ℓ₁ part and of the ridge part, each rounded on its own, are added; the sum replaces that result if it is finite after conversion to its type, and the first result is kept otherwise. Where one part dominates, the test can pass although the other part alone would be recomputed (ℓ₁ terms below floatmin(T) beside a normal ridge part, or squares below floatmin(T) beside a normal ℓ₁ part). Its proximal point soft thresholds by the threshold of the NormL1 kernel and multiplies by the ridge factor 1/(1 + γλ2) of the SqrNormL2 kernel, both formed from the unrounded factors, so a factor γλ2 outside the range still acts on a representable result.

Endpoint clauses

prox, prox! and value_and_prox! throw an ArgumentError for a negative or NaN scalar step before anything is written. The entries of an array of steps are not checked: they must be nonnegative, a documented precondition. prox_block does not check its step, and Scaled keeps its own step rule.

The optimized array-step loop and the general loop store the same results, bit for bit. See the implementation notes for branch-selection conditions and the reason array-step validation remains a caller precondition.

y = [7.0, 7.0, 7.0]
refused = try prox!(y, h, x, -1.0); false catch e; e isa ArgumentError end
@assert refused && y == [7.0, 7.0, 7.0]

An infinite ridge level makes g the indicator of $\{0\}$: at every step $\gamma\geq0$, $\gamma=0$ included, each entry of the proximal point is +0, also for NaN and ±Inf inputs; the value is 0 at the zero vector, NaN if an entry is NaN, and Inf otherwise; and the screen kkt_violation(g, v, i) is -Inf, as is kkt_violation(g, v, x, i) at a zero entry of x with a finite v[i], while that form is Inf at a nonzero entry of x with finite v[i]. An infinite λ1 and infinite weights follow the ℓ₁ endpoint rules, and a threshold that overflows from finite factors keeps their documented limitation for infinite inputs.

hard = ElasticNet(1.0, Inf)
@assert prox(hard, [3.0, NaN], 0.0) == [0.0, 0.0]
@assert hard([0.0, 0.0]) == 0 && hard([0.0, 1e-300]) == Inf
@assert kkt_violation(hard, [5.0], 1) == -Inf
@assert kkt_violation(hard, [5.0], [0.0], 1) == -Inf
@assert kkt_violation(hard, [5.0], [1.0], 1) == Inf

Limitations and non-guarantees

The shared comparison of NormL1, NormL1Nonneg and ElasticNet under Scaled remains with its conditions and preceding example in the shared range guarantees. The dedicated retained limitation follows.

A known limitation (#567): for Scaled(ElasticNet(λ1, λ2, w), α) with finite levels, a finite positive α and a positive finite scalar step γ whose product αγ is above floatmax, prox, prox!, prox_block and value_and_prox! can return 0 where the exact result is representable. A representable result does not need a representable coefficient. With λ1 = 0, α = γ = 2.0^600 and x = [2.0^1000], the coefficient αγλ2 is 2^1300 for λ2 = 2.0^100, above floatmax, while the quotient x/(1 + αγλ2), about 2^-300, is representable, and the result is 0. For λ2 = 2.0^-1000 and x = [4.0] the coefficient is 2^200 and the result is the representable 4/(1 + 2^200). Scaled(SqrNormL2(λ2), α) also returns 0 in the first case. In some cases the same step passed as an array of steps gives the representable result, for example in the first case and in its Float32 analogue (λ2 = 2.0f0^80, α = γ = 2.0f0^80, x = [2.0f0^127]); for λ2 = 2.0^880 and x = [2.0^1023], with the same α and γ, both steps give 0 where the result is 2^-1057:

s = Scaled(ElasticNet(0.0, 2.0^100), 2.0^600)
prox(s, [2.0^1000], 2.0^600)      # [0.0]
prox(s, [2.0^1000], [2.0^600])    # [4.909093465297727e-91], about 2^-300
t = Scaled(ElasticNet(0.0, 2.0^880), 2.0^600)
prox(t, [2.0^1023], 2.0^600)      # [0.0]
prox(t, [2.0^1023], [2.0^600])    # [0.0]; the result is 2^-1057
