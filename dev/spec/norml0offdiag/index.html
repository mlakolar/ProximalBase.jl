NormL0(λ; diagonal = false) numerical contract

Identity

NormL0(λ; diagonal = false) is the nonconvex cardinality penalty on the off-diagonal entries of a square matrix, with its proximal map. It returns an internal type, not a NormL0. NormL0(λ) and NormL0(λ; diagonal = true) are the all-entry penalty with its full set of arguments and are not described on this page. The implementation is in src/functions/norml0offdiag.jl. It is not a SeparableFunction; it takes the scalar keep-or-drop decision from NormL0.

Definition and domain

NormL0(λ; diagonal = false) takes a finite real level $\lambda\geq0$. For a square matrix $X$ it is

\[g(X)=\lambda\,\#\{(i,j):i\neq j,\ X_{ij}\neq0\}.\]

For a symmetric $X$, a pair $X_{ij}=X_{ji}\neq0$ with $i<j$ contributes $2\lambda$; the diagonal contributes nothing. Both signed zeros count as zero.

The oracles accept a one-based, strided $p\times p$ matrix of Float32 or Float64 ($p=0$ is allowed) with finite entries, under the storage preconditions of the supported-argument section. The step $\gamma$ is a finite positive real number. Symmetry of the matrix under == is the caller's precondition for the symmetric interpretation on this page; it is not checked, and asymmetry alone causes no refusal. A pair (+0.0, -0.0) is symmetric. For a finite $V$ that is symmetric under ==, when the comparison of the ordinary-path clauses is exact, the proximal map solves

\[\min_{Z=Z^\top}\ g(Z)+\frac{\|Z-V\|_F^2}{2\gamma}.\]

For a pair $i<j$ the objective is $2\lambda\mathbf 1\{z\neq0\}+2(z-v)^2/(2\gamma)$. Dividing by two gives the scalar NormL0 problem, so the threshold $2\gamma\lambda$ is unchanged. The diagonal term $(z-v)^2/(2\gamma)$ is minimized by $z=v$.

Traits

isproximable is true. isconvex, issmooth and isseparable are false.

Supported arguments

X and the output Y are StridedMatrix values with the same element type, Float32 or Float64, that Base can both read and write. Dense matrices, strided views and reshapes, and strided reinterpreted arrays that Base can both read and write are accepted, provided that distinct entries of Y, and of X when Y === X, occupy distinct memory. A destination that repeats a storage position, such as a zero-stride view, is unsupported and may go undetected, as in Base.mightalias; the statements of this page do not apply to it. The step is a scalar Real. Choosing diagonal = false changes the penalty and narrows the arguments: the vectors, sparse matrices, SparseIterate and SymmetricSparseIterate values and array steps that NormL0(λ) accepts are refused here; the failure section states how. prox_block, prox_block!, restrict and kkt_violation are not provided.

Preconditions

Exact input/output identity Y === X is supported when distinct entries of X occupy distinct memory (see the supported arguments). A different output Y for which Base.mightalias(Y, X) is true is refused. Other ownership rules follow the array and precision conventions. Symmetry is the caller's precondition for the symmetric interpretation; asymmetry alone causes no refusal.

For a scale α that Scaled accepts, the step passed to this function, the value and the fused value of Scaled(NormL0(λ; diagonal = false), α) follow the rules of Scaled, including its rounding in the exceptional range (see Scaling a function). They can differ from the ordinary products α * γ and $\alpha g(X)$, the fused value need not equal the value of Scaled at the stored output, and a step that is not finite and positive after this computation is refused.

Results

prox returns similar(X, T), a Matrix for Base arrays, prox! returns the destination, and a direct call of value_and_prox! returns the value at the stored output. The value has the element type T of the matrix. With $k$ the number of nonzero entries off the diagonal, it is zero(T) when $k=0$ or $\lambda=0$, and otherwise convert(T, R(λ) * R(k)) with R = promote_type(T, float(typeof(λ))), so a Float64 level is not rounded to Float32 before the product.

Ordinary-path clauses

Under the storage preconditions of the supported arguments, the diagonal is copied bit for bit, including -0.0. Each entry $(i,j)$ with $i\neq j$ is the $(i,j)$ entry of prox(NormL0(λ), V, γ), computed from $V_{ij}$ alone and not mirrored from $V_{ji}$. For $\lambda>0$ the entry is kept when the scalar comparison of NormL0 on the converted operands finds its square above $2\gamma\lambda$, and is positive zero otherwise, so a tie of the converted operands gives zero; when the comparison is exact as described below, a mathematical tie gives zero. Otherwise a mathematical tie can be kept: a pair of ones at λ = 1//3 and γ = 3//2 is kept. At $\lambda=0$ the map is the identity, and a pair (+0.0, -0.0) stays as it is. At $\lambda>0$ the same pair becomes (+0.0, +0.0). The output is symmetric under == when the input is.

For an asymmetric input the same rule is applied to each entry, so neither triangle is selected. The output is then the entrywise map, which need not be the proximal point over symmetric matrices, and the value counts every nonzero off-diagonal entry of the given matrix.

The comparison is exact when λ and γ convert exactly to a Float32 or Float64 working type. NormL0 converts the entry, λ and γ to the working type and compares the square of the entry with $2\gamma\lambda$. Other levels and steps, for example a Rational or an Int above $2^{53}$, are rounded to that type first. With a BigFloat working type the converted entry, its square and the product $2\gamma\lambda$ can each be rounded at the current precision: at a precision of two bits, λ = BigFloat(0.5) and γ = 1.0 give the exact threshold one, and a pair of 1.25 is dropped because the entry converts to 1.0. The decision is then made with the converted and rounded values, as for NormL0.

Range clauses

Each proximal entry is the entry of V or positive zero, so its magnitude does not increase. The comparison follows the NormL0 rules for thresholds near the ends of the floating-point range. The value is the product of the level and the entry count formed in R and then rounded to T, and can overflow to Inf when the product rounds beyond floatmax(T).

Failure behavior

These statements describe direct calls of the value, prox, prox! and value_and_prox!.

  • Every refusal happens before any write, so X and Y are unchanged by a refused call.
  • A call in which exactly one of the following conditions fails throws ArgumentError: offset axes; an argument of one of these storage kinds (a vector, a tuple, a sparse or other non-strided matrix such as Symmetric, Adjoint or matrixview, a SparseIterate, a SymmetricSparseIterate or a BlockIterate); an array step; an element type other than Float32 and Float64, or different element types of X and Y; a reinterpreted array that Base cannot both read and write; a different Y with Base.mightalias(Y, X) true; a real scalar step that is nonpositive or non-finite; a non-finite entry of X.
  • A call in which the only failing condition is a non-square X, or a Y of another size, throws DimensionMismatch.
  • When several conditions fail, which exception is thrown is not specified.
  • Arguments outside these families, for example a number as X or a step that is neither real nor an array, can give MethodError.
  • Called on this function directly with the argument counts of their generic forms, prox_block, prox_block!, restrict and kkt_violation throw ArgumentError.

Asymmetry alone causes no refusal: an asymmetric X with a non-finite entry is refused because the entry is non-finite. The tests pin the current order of the checks; that order is not part of this contract.

Through Scaled, the unsupported arguments above are refused before any write, with an exception from the preprocessing of Scaled, the checks of this function or dispatch, for example ArgumentError, DimensionMismatch, MethodError or OverflowError, and Scaled may read such arguments before the refusal.

Limitations and non-guarantees

The output is not promised to be positive definite, and no solver convergence is promised. Weighted levels, groups, sparse and symmetric-iterate representations, restrict, prox_block and kkt_violation are not provided. The proximal map is not provided at steps 0 and Inf, at non-finite input or for array steps, and these calls are refused as the supported-argument, endpoint and failure sections state. A zero-stride view as Y is not detected as self-aliased, as in Base.mightalias.

Implementation notes

These notes describe the current code and are not guarantees; they can change.

  • The scalar decision is prox_block(NormL0(λ), v, 1, γ). When λ, γ and the element type are the same float type and the matrix has at least 64 entries, the implementation uses the certified magnitude cutoff of the dense NormL0 kernel instead when a cutoff can be certified, behind a function barrier.
  • The finiteness check reads the entries before the first write. For a Matrix it sums x - x over the entries in one pass in linear index order, which gives +0.0 when every entry is finite and NaN otherwise. For other strided matrices it counts the non-finite entries column by column, and each column sum is an integer of the entry width (Int32 for Float32, Int64 for Float64).
  • The write loop uses @simd without ivdep, because on Julia 1.10 the loop with ivdep gave wrong entries for a reinterpreted Float32 matrix over Float64 or ComplexF32 storage. Y === X has its own single-array loop.
  • The benchmark notes record measured time ratios to the NormL0 oracles. They describe one machine and Julia version.

Evidence

test/norml0offdiag.jl compares the proximal map with an exact Rational{BigInt} minimization over the keep and drop patterns of the pairs, and with NormL0 off the diagonal for mixed level and step types. It covers ties, signed zeros, the diagonal, the refusals listed in the failure section, with an unchanged sentinel output where the caller passes one, the entrywise result for an asymmetric input, the ArgumentError refusals of non-matrix arguments, strided views, reshapes and reinterpreted matrices as input and output, and strided views and reinterpreted matrices in place, Scaled, and zero allocation on both routes. It also checks that NormL0(λ) and NormL0(λ; diagonal = true) are the same object, with bit-identical values and proximal outputs. The penalty guide contains an executable example, and benchmark/norml0offdiag.jl times the oracles against NormL0.

History

The feature issue and its pull request record the choice of a separate type, later replaced by the diagonal keyword of NormL0 with an internal type, and the probe of the all-entry prox with a positive-definiteness check, which accepted smaller steps at levels of two and above and with different variable scales.
