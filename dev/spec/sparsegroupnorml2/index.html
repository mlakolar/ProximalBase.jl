SparseGroupNormL2 numerical contract

This page gathers the existing numerical rules for SparseGroupNormL2. Read How to read the numerical contracts for authority and ownership.

Identity

SparseGroupNormL2 combines an ℓ₁ penalty on the covered entries with weighted ℓ₂ penalties on the groups. See the SparseGroupNormL2 API, implementation and API coverage matrix.

Definition and domain

The function guide gives the penalty formula and defines its index set U.

Entries outside $U$ are free in both terms and retain their values in the proximal output. A zero weight removes the group ℓ₂ term while the ℓ₁ term still acts on that group. The constructor keeps the order of the groups and indices and copies the supplied groups and weights. The levels and weights are converted to one promoted floating type and checked for nonnegativity and NaN.

Default group weights

The default is $w_k=\sqrt{|G_k|}$.

Empty group collection

With no groups, the value is zero and the proximal map is the identity.

Traits

SparseGroupNormL2 is convex and proximable. See the SparseGroupNormL2 API for traits and signatures.

Supported arguments

Proximal results and stored value

prox allocates, prox! accepts exact in-place use, and value_and_prox! returns the value at the stored destination.

Array storage and conversions

Array oracles accept real one-based CPU arrays, including SparseIterate and BlockIterate. Groups index matrices linearly. Full-array partial overlap is unsupported. Full-array writes can change output iterate activity. When copying free or identity entries into a floating-point SparseIterate, the array oracle stores negative zeros that would otherwise be read as positive. Absent positive zeros stay inactive. The soft-thresholded intermediate is written in the destination type before the group shrink. An explicit integer buffer can fail conversion here even when the final exact result is integral. Allocating prox uses floating storage for integer input. See the endpoint rules for zero or infinite steps, nonfinite entries and infinite parameters.

Preconditions

Compact buffers and exact in-place use

prox_block!(out, f, u, k, γ) uses compact vectors in groups[k] order, returns out and accepts out === u.

Buffer validation and storage

It checks the group, lengths, one-based real buffers, step and detected nonidentical overlap before writing. The caller supplies an output buffer independent of iterate storage. prox_block(f, u, k, γ) allocates that buffer. To store the result, the caller writes it into the matching block as a separate step.

Results

The scoring derivation gives the finite-data score formulas.

On an ordinary array k is an entry index and selects its group. An uncovered index has score abs(v[k]). On a BlockIterate, k is a group number and the selected ordered layout must agree. The full-point kkt_violation(f, v, x) checks the full block layout and returns the maximum across zero, the block scores and the uncovered-entry magnitudes. The result measures the worst block or free-coordinate mismatch.

Assumed-zero score rejection

The three-argument assumed-zero form with an integer index throws ArgumentError.

Ordinary-path clauses

For ordinary calls with finite levels and weights and a positive finite step, the proximal map soft-thresholds the entries of each group and shrinks the result. The ordinary point-aware group score is a signed margin at a zero group and a residual norm at a nonzero group.

See the proximal formula and example, compact group example, and scoring derivation.

Range clauses

See supported precision and oracle agreement and the shared range guarantees for the precision and limits referenced below. The endpoint table gives the precedence of the proximal cases.

The entrywise threshold at a finite step propagates NaN at the corresponding entry when the ℓ₁ term is positive. When finite γλ1 overflows in the working type, a coupled group retains genuine infinite inputs. An ℓ₁-only group follows the NormL1 endpoint rule and returns NaN at such an entry. The group shrink distinguishes a product of finite factors outside the working range from a stored infinite parameter. The supported homogeneous precision and general range limits above apply. For mixed-width calls, the stored intermediate and destination conversions can change the result. The fused value uses the stored destination.

Endpoint clauses

Invalid-step validation precedes the group rules below.

The following rules apply to each covered group in the array and compact proximal methods, in the order shown. Uncovered entries pass through the array prox and are ignored by the value.

ConditionProximal result
Infinite stored ℓ₁ level, infinite weight, or infinite stored ℓ₂ level with positive weightFill the group with +0, including at a zero step and with NaN or infinite inputs
Zero step or zero penalty after the hard constraintsIdentity
Infinite step and positive penalty after the hard constraintsFill the group with +0
Finite positive step and a positive group ℓ₂ term, with a NaN inputNaN throughout the group
Finite positive step and a positive group ℓ₂ term, with an infinite input and no NaNKeep the entrywise soft-threshold result without a further group shrink
Other finite positive stepsApply the entrywise soft threshold. A zero group term leaves that result in place. A positive group term then applies the group shrink.

A zero group has value zero under a hard constraint. An entry outside the hard domain gives an infinite value unless a penalized entry yields NaN. Zero penalty terms contribute zero. NaN from a penalized entry takes precedence over infinite contributions.

Point-aware score classification

The point-aware KKT methods classify the gradient and point entries read by a group after conversion to the working type. NaN among those entries gives NaN. Otherwise an infinite entry gives +Inf. For finite converted entries, a hard-constrained zero group gives -Inf and an active group outside the hard domain gives +Inf. An active group whose finite group-level product rounds to infinity also gives +Inf in the working type. At a zero group the signed screen retains the finite factors for range recovery. The full-point maximum propagates NaN across groups and includes the magnitudes of the gradient entries at uncovered coordinates. See the sparse group lasso guide for the finite-data scores.

Failure behavior

See preconditions and predictable failures and partial writes.

Invalid proximal steps

For direct public array and compact proximal calls with otherwise valid arguments, a negative or NaN step throws ArgumentError before writes. Array calls check the step even with an empty group collection.

Limitations and non-guarantees

BlockIterate(p, f), BlockIterate(T, p, f) and BlockIterate(x, f) require the groups to partition the iterate.

The family has no scalar entry prox, step vectors, or restrict. Positive finite Scaled supports generic array value and prox with the scale applied to the step. A scaled product outside the working range can round before the sparse-group oracle sees it. For example, a tiny negative step can round to -0.0 in the wrapper before the leaf validates the step. A zero scale throws ArgumentError through the generic constructor. Scaled compact-block and KKT calls are unsupported.

Symmetric iterate arguments

SymmetricSparseIterate is unsupported as a proximal input or destination, or as a directly supplied gradient or point in a point-aware KKT call.

Empty-group regression

The executable check uses a nonempty input and verifies the destination after each rejected mutating call in Float32 and Float64.

Point-aware KKT regressions

The dispatch check uses a symmetric iterate directly as the gradient. The working-type check characterizes a call with a Float16 gradient and a finite integer point whose entry converts to infinity. The supported precision policy sets the supported configurations.
