# Measurement summaries

Each CSV is generated by `benchmark/audit860/analyze.py`, with raw sample and
provenance validation, median paired ratios and seeded round-bootstrap intervals.
All allocation fields are Julia heap observations. No campaign is pooled.

| Prefix | Raw campaign | Rounds | Comparison |
|:--|:--|--:|:--|
| `diagnosis` | `diagnosis7-v2` | 7 | current frozen baseline / original cached views |
| `diagnosis-AA` | same | 7 | baseline A/A |
| `discovery-bulk` | `final7` | 7 | inlined bulk / baseline, earlier fixture preparation |
| `discovery-AA`, `discovery-bulkAA` | same | 7 | baseline and bulk A/A |
| `placement-singleton`, `placement-outlined` | `placement7` | 7 | each candidate / baseline with placement controls |
| `placement-AA` | same | 7 | baseline A/A |
| `confirmation-singleton`, `confirmation-outlined`, `confirmation-bulk` | `confirmation21` | 21 | each candidate / baseline, fresh seeds/processes |
| `confirmation-AA` | same | 21 | baseline A/A |

`regression-ledger.csv` retains the union of all >5% discovery/confirmation flags,
including those that do not repeat, diagnostic cases and uncertain intervals.
Regenerate it after producing the summaries:

```sh
python3 benchmark/audit860/ledger.py docs/audit/block-updates-860/results /tmp/pb860-ledger.csv
```

The earlier discovery constructs the high-penalty fixture after warming the
normal workload. Placement-controlled broad/confirmation construct both before
numerical warmup, explicitly preserve seeded allocation padding and record
fixture addresses. This preparation change is visible; cross-context changes
are not assigned solely to the source algorithm. All final source contrasts
use the same placement-controlled context.
