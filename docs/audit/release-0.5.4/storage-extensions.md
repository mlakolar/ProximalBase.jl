## Architecture relationships verified directly

- SparseIterate directly subtypes `AbstractArray{T,N}`; SymmetricSparseIterate subtypes `AbstractMatrix{T}`; AtomIterate subtypes `AbstractVector{T}`. None subtypes `AbstractFunction`.
- Sparse and symmetric storage share `_StoredIterate`, a union alias and shared kernels, rather than a new abstract parent. SymmetricCoordinates is a vector view containing the symmetric iterate; its coordinate indexing maps to the stored lower triangle.
- `prox_coordinate!` dispatches on iterate and function. Scalar kernels use a full linear entry index; symmetric lower-triangle coordinates are translated before `prox_entry`. Group penalties dispatch on matching AtomIterate groups.
- LAPACK, QR, PartialSVDWorkspace, PartialEigenWorkspace and Scratch are owned internal numerical state. Functions use concrete type/size checks on untyped cached fields. They require per-thread function ownership where mutable workspaces are present.
- Adapt plus GPUArraysCore loads the GPU extension. Generic separable CPU loops are replaced by broadcasts/reductions. Adapted grouped functions contain a device layout with padded size-class blocks and scatter group ids. Host functions used with GPU arrays rebuild that layout per call.
- GPU GLM evaluation/gradients call `_linear_predictor!`, per-observation broadcast/reduction and transpose design-matrix multiplication; higher order GLM routines remain CPU-only. Device least-squares gradients/Hessian products use generic mul! and broadcasts, while its prox explicitly rejects the LAPACK device path.
- Loading Test supplies the Testing method implementations through the separate Test extension; test helper declarations remain discoverable in the base module.

## Final device consistency followup

ST07 (P2 confirmed): device value reductions for direct zero-level NormL1, NormL1Nonneg, ElasticNet, GroupNormL2 and sparse-group terms could form `0 * Inf` after a finite input's intermediate reduction overflowed. Fused grouped zero-level calls could return NaN despite an identity proximal point. Repairs test zero coefficients before the reductions or before multiplying an absent component, retain NormL1Nonneg's domain check, and preserve identity output. Grouped weighted value functors also skip exact zero weights. New shared GPU regressions use finite Float32/64 `floatmax` inputs, separate and aliased outputs, zero-weight group identities, a preserved nonnegative-domain violation, and ElasticNet's absent quadratic term.

The installed GPUArrays source versions inspected at `src/host/linalg.jl` already normalize Euclidean norms by the maximum magnitude when the unscaled square sum overflows or underflows. The package therefore retains the generic `_norm2_scaled(x) = norm(x)` fallback for supported GPUArrays backends rather than adding a duplicate implementation. Shared device tests now exercise finite representable huge/tiny NormL2 values, NormL2 proximal shrinkage and IndBallL2 projection independently of the package CPU reference. Root owns execution and receipts; physical GPU behavior remains unverified.

The first LTS run exposed a further CHOLMOD dispatch detail: the element-type union of its matched `copyto!` method is narrower in Julia 1.10 (Float64/ComplexF64) than in 1.13 (also Float32/ComplexF32). A hardcoded four-type union therefore left an LTS ambiguity. The final method uses `SparseArrays.CHOLMOD.VTypes`, the actual scalar union used by those library signatures, giving the exact version-independent intersection. Matching and mixed-type CHOLMOD regressions are retained. The earlier failed LTS outcome is retained in the report; its temporary log was lost in the restart. Final full suites, storage checks and Aqua passed on both versions; durable receipts are in validation/.
