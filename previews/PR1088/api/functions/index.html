Function reference

The function library gives dimensions, errors, numerical examples and capability limits for the available concrete function types.

Smooth array functions

ProximalBase.LeastSquaresLoss — Type
LeastSquaresLoss(Y, X)

Least-squares loss f(β) = ‖Y-Xβ‖²/2 with gradient X'*(X*β-Y). X is an n × p design matrix. A length-n response Y uses length-p coefficients; an n × k response uses p × k coefficients and the Frobenius norm. Data and arguments must be real and one-based.

The loss is smooth, convex and proximable. Dense arrays, SparseIterate and BlockIterate use their supported array products. The first proximal call caches a thin SVD; later calls reuse it for different steps, including when p > n.

Examples

julia> f = LeastSquaresLoss([1.0, -1.0], [1.0 0.0; 0.0 1.0]);

julia> f([3.0, 1.0])
4.0

julia> gradient(f, [3.0, 1.0])
2-element Vector{Float64}:
 2.0
 2.0

Edge cases

  • X and Y are retained by reference. After same-shape changes, call reset_cache! before another prox; reconstruct after dimension changes.
  • Values, gradients, prox and full-point kkt_violation reuse private scratch. Synchronize concurrent calls on one loss. Supplied-predictor oracles have separate ownership rules.
  • No symmetric-iterate or scalar-coordinate prox is provided.
  • Value range recovery does not guarantee recovery of matrix products or SVDs.

See least-squares operations and supplied-predictor oracles.

ProximalBase.LogDetLoss — Type
LogDetLoss(S, w = 1)

The loss w * (tr(S * X) - logdet(X)) on symmetric positive-definite matrices. The constructor copies a finite, nonempty square matrix S with exact symmetry. Use Symmetric(S, :L) or Symmetric(S, :U) to select a triangle explicitly. The weight must be finite and strictly positive. S may be indefinite.

Use one-based matrices and a common Float32 or Float64 type for data, weight, scalar step, and output buffers. Integer weights and steps are also accepted. Treat the stored coefficients as read-only. Scratch is local to each call.

A NaN entry in X gives a NaN value. Other points outside the domain give Inf. The gradient is w * (S - inv(X)) on the domain and all NaN outside it. The proximal map at a positive finite step accepts finite nonsymmetric and indefinite inputs. A zero step copies the input. Negative, infinite and NaN steps throw ArgumentError.

Allocating oracles return full dense matrices. Mutating oracles accept writable strided matrices, including row-strided views. A SymmetricSparseIterate can supply the logical input matrix. Gradients use the Frobenius inner product on full matrices.

source
ProximalBase.LogisticLoss — Type
LogisticLoss(y, X; weights=nothing, offset=nothing)

Convex, smooth logistic loss with predictor η = X*β + offset, value sum(wᵢ * (log(1 + exp(ηᵢ)) - yᵢ*ηᵢ)) and gradient X' * (wᵢ * (σ(ηᵢ) - yᵢ))ᵢ, where σ is the logistic sigmoid. The defaults are unit weights and zero offset.

Use one-based strided vectors and a strided or SparseMatrixCSC design, all of the same type (Float32 or Float64). Responses must be finite in [0, 1], including on zero-weight rows. Weights must be finite and nonnegative, and offsets finite. The constructor borrows these arrays.

The loss implements gradient! and value_and_gradient!, with no proximal operator. For caller-held predictors use ProximalBase.value_from_predictor or ProximalBase.value_and_gradient_from_predictor!. See logistic regression for ownership, scaling and numerical limits.

ProximalBase.SqrNormL2 — Type
SqrNormL2(λ = 1)
SqrNormL2(λ, y)

Squared-distance function f(x) = (λ/2)‖x-y‖² with nonnegative level λ and center zero when y is omitted. For a matrix, the norm is Frobenius. This is the ridge penalty when uncentered, or half the squared error when λ = 1.

The function is smooth, convex and separable, with gradient λ*(x-y) and proximal point (x + γ*λ*y)/(1 + γ*λ). A supplied center is retained by reference and must have the same shape as x. Use real, one-based arrays; λ is checked nonnegative and not NaN at construction. The retained center's array type and axes are checked at construction; later edits are not revalidated.

Examples

julia> f = SqrNormL2(2.0, [1.0, 0.0]);

julia> f([3.0, -1.0])
5.0

julia> prox(f, [3.0, -1.0], 0.5)
2-element Vector{Float64}:
  2.0
 -0.5

Edge cases

  • For a symmetric iterate, the center must be exactly symmetric; validate with ProximalBase.check_symmetric_parameters.
  • Exact in-place prox is supported; gradient output must be independent of its input.
  • An infinite level follows IEEE arithmetic, not a general projection rule: a zero residual can yield a NaN gradient from Inf*0. A zero level does not suppress every 0*Inf or 0*NaN in gradients or prox.

See squared-norm details and the numerical contract for supported precision, range recovery, restriction constants and non-finite values.

ProximalBase.QuadraticFunction — Type
QuadraticFunction(A, b = nothing, c = 0)

Quadratic function f(x) = x' * A * x / 2 + b' * x + c, with gradient A*x+b; omitted b is zero. Arguments are real, one-based vectors. A must be square and symmetric, and b must have matching length. Symmetry is a caller precondition: the constructor neither checks nor repairs it. Indefinite symmetric A is allowed.

The proximal point solves (I + γ*A)*y = x - γ*b using a cached eigendecomposition. For a negative computed minimum eigenvalue, the prox rejects a step whose rounded γ*(-λmin) is not less than one, raising DomainError before writing the output. This uses the effective step after scaling and conversion to the function's type. A singular positive-semidefinite A (for example X'X when p > n) may have a slightly negative computed eigenvalue; large steps can then raise DomainError even though the exact matrix is positive semidefinite.

Examples

julia> f = QuadraticFunction([2.0 0.0; 0.0 4.0], [1.0, -2.0]);

julia> f([1.0, 1.0])
2.0

julia> gradient(f, [1.0, 1.0])
2-element Vector{Float64}:
 3.0
 2.0

Edge cases

  • isconvex returns false: positive semidefiniteness is not certified. Solvers that require convexity must validate it, including after data changes.
  • A and b are retained by reference. Call reset_cache! after same-shape changes to A; changing b alone needs no reset. Reconstruct after dimension changes. The cached eigenbasis reads A's upper triangle, while values and gradients use A directly.
  • Full-point kkt_violation uses the scratch shared by value and prox. Synchronize calls on one object when they use that scratch.

See quadratic operations and step domain for exact boundary qualifications, caching, alias rules and numerical limits.

ProximalBase.ZeroFunction — Type
ZeroFunction()

Zero function f(x) = 0 for an unpenalized problem. Its gradient is zero and its proximal operator is the identity. Real, one-based arrays are required; shape and output checks still apply.

Examples

julia> f = ZeroFunction();

julia> f([2.0, -1.0])
0.0

julia> prox(f, [2.0, -1.0])
2-element Vector{Float64}:
  2.0
 -1.0

Edge cases

  • Distinct matching sparse/block iterate inputs and outputs use copyto!, replacing destination activity, including stored zeros.
  • Symmetric-iterate proximal writes preserve destination activity; gradients at or into symmetric iterates are not implemented.

See zero-function operations for copying and step behavior.

ProximalBase.LinearFunction — Type
LinearFunction(c, d = 0)

Affine function f(x) = ⟨c,x⟩ + d, with gradient c and proximal point x-γ*c. For matrices the inner product is Frobenius. Coefficients are real, one-based arrays retained by reference; size(c) must equal size(x), not just its entry count.

With a Diagonal coefficient array, only diagonal coefficients contribute for both dense and sparse matrix arguments. On a matrix SparseIterate, only stored nonzero entries contribute: unstored entries and stored zeros are skipped even against NaN or Inf. Skipping those zero entries can give a different result from evaluating a dense copy. Vector and symmetric iterates have their own rules.

Examples

julia> x = SparseIterate(2, 2); x[1, 1] = 2.0;

julia> f = LinearFunction([1.0 NaN; 1.0 1.0], 0.25);

julia> f(x)
2.25

julia> isnan(f(Matrix(x)))
true

Edge cases

  • Every oracle checks coefficient/input shape before writes.
  • For a symmetric iterate, c is an exactly symmetric p × p matrix; use ProximalBase.check_symmetric_parameters to validate it.
  • Exact in-place prox is supported; gradient output must be independent of input and coefficients. Array-step prox is not implemented.
  • Summation order is unspecified. Non-finite terms can change the result's IEEE class; extreme cancellation can exceed finite-value recovery guarantees.

See linear operations and sparse values for the summation, cost and accuracy contract.

Square-root least squares

SqrtLeastSquaresLoss is convex and not smooth, with no gradient and no proximal operator. It is evaluated by the value oracles of the next group.

ProximalBase.SqrtLeastSquaresLoss — Type
SqrtLeastSquaresLoss(Y, X)

The square-root least-squares loss f(β) = ‖Y - Xβ‖₂ for a vector response Y and a design matrix X, with no 1/√n factor: the normalized square-root lasso objective (1/√n) ‖Y - Xβ‖₂ + λ ‖β‖₁ has the data term Scaled(f, inv(sqrt(n))), and a penalty λ_normalized on that scale corresponds to λ_unnormalized = √n λ_normalized on the unnormalized loss. PB defines no sum of functions; the objective is written here as a formula.

The loss is convex and is not smooth: for X ≠ 0 it is not differentiable where Y = Xβ (for X = 0 it is constant in β). It has no gradient and no proximal operator in this package (issmooth(f) and isproximable(f) are false, isconvex(f) is true); gradient!, value_and_gradient!, prox!, value_and_prox!, prox_block, kkt_violation and restrict are a MethodError and lipschitz(f) is an ArgumentError. It stores the same data as LeastSquaresLoss, which an algorithm for the square-root loss reads through ProximalBase.leastsquares_data (the accessor is shared, and the two losses are told apart by their types), and it takes the caller's predictor z = Xβ or residual through the value oracles ProximalBase.value_from_predictor and ProximalBase.value_from_residual, for the loss and for one Scaled of it. There is no ProximalBase.value_and_gradient_from_predictor! for it.

Y is a vector with real entries and X a matrix with real entries and size(X, 1) == length(Y) (a DimensionMismatch otherwise); a matrix Y is a MethodError and complex entries are an ArgumentError. Y and X must have axes that start at 1 (an ArgumentError otherwise). β of f(β) is a vector that mul! with X accepts, such as a dense vector, a SparseIterate or a BlockIterate.

f(β) forms Xβ in the scratch f.tmp and is not safe to call from two tasks on one f. An entry of Xβ that overflows is not formed again: the value is then the norm of the computed Xβ - Y, typically Inf or NaN. The norm of the computed Xβ - Y is evaluated by the kernel of the oracles, in T = float(promote_type(eltype(Y), eltype(X))): the value is α√ŝ (α = 1 here) for the computed sum of squares ŝ when ŝ is not below n floatmin(T)/eps(T) and the product is below floatmax(T)/2, and when either test rejects it the norm is recomputed from the squares in power-of-two units. It is never formed as sqrt(2 * v) from the least-squares value v. The accuracy statement is for finite entries that T represents exactly, n of them with n ≤ 2^40, and either (n + 3) eps(T) ≤ 1/16 or strided Float32 or Float64 vectors of one element type. An entry that T does not represent (an Int Y above maxintfloat(T), a Rational Y) is converted to T inside the sum, and that rounding is outside the bound. With e = (n/2 + 4) eps(T) and v the exact norm of the computed Xβ - Y, the value in T is within e |v| of v, plus 2 nextfloat(zero(T)) where |v| < floatmin(T). The product Xβ itself carries the rounding of the matrix-vector product. f(β) returns its value converted to float(eltype(β)): the bound holds for eltype(β) == T, and a narrower β adds one rounding to its type. With thr = floatmax(T) + ulp/2 the round-to-nearest overflow threshold, a v within the relative error e of thr, below it as well as above it, gives Inf or a finite value within the bound (floatmax(T) is then possible), and a v well above thr gives Inf. Scaled(f, Inf)(β) is Inf * f(β), which is NaN at an exact fit; the value oracles refuse the factor Inf with an ArgumentError.

Oracles at a supplied predictor or residual

Both predictor operations support LeastSquaresLoss and LogisticLoss. SqrtLeastSquaresLoss supports the predictor value operation. The residual value and data accessor serve both least-squares losses. See the individual operations for the supported domains and scaling rules.

ProximalBase.value_from_predictor — Function
ProximalBase.value_from_predictor(f, z)

Evaluate the least-squares value α*sum(abs2, z-Y)/2 from a predictor z = X*β already computed by the caller. Here α = 1 for a LeastSquaresLoss, or is the factor of one Scaled wrapper. No design entries are read and no loss fields are written. The call neither reads nor writes f.tmp; the supplied z may be a view of f.tmp.

Use a vector-response loss with strided Float32 or Float64 data of one type T, and a StridedVector{T} predictor with the response's axes. Other types throw MethodError; mismatched axes throw DimensionMismatch. The result is T.

Examples

julia> f = LeastSquaresLoss([1.0], reshape([2.0], 1, 1));

julia> ProximalBase.value_from_predictor(f, [3.0])
2.0

For SqrtLeastSquaresLoss, or one Scaled wrapper, this returns α*norm(z-Y) rather than a squared loss. The strided type, axes and factor restrictions are the same, including rejection of an infinite scale before evaluating a zero residual. Extreme sums and products use power-of-two range recovery, not sqrt(2*v) of the squared-loss value; see the SqrtLeastSquaresLoss accuracy contract. No entry of X is read, f.tmp is not accessed separately, and the supplied z is read but not modified.

Edge cases

  • A scale must be positive finite Float32/Float64, or an integer exactly representable as Float64; other factors throw ArgumentError.
  • A non-finite predictor gives a non-finite value; the call does not recompute X*β.
  • Finite-input value recovery has explicit rounding and overflow-boundary limits.
  • Calls write no loss fields and can share one loss across tasks while its data remain unchanged. The ordinary path allocates nothing for raw losses and Float32, Float64 or Int scales.

For a LogisticLoss, supply the complete predictor η = X*β + offset with the loss element type and response axes. The call returns the logistic objective and reads neither design entries nor private workspace entries. See logistic regression for its supported layouts.

See predictor domains, accuracy and ownership and ProximalBase.value_from_residual.

source
ProximalBase.value_and_gradient_from_predictor! — Function
ProximalBase.value_and_gradient_from_predictor!(g, d, f, z)

Write residual d = z-Y and gradient g = α*(X'*d) from the caller's predictor z = X*β, and return α*sum(abs2, d)/2. This forms one product with X' and none with X; no loss fields or private scratch are written.

Use the domain and scale of ProximalBase.value_from_predictor, with strided vectors g, d and z of the data type. z and d have the response's axes; g has length size(X, 2) and must be one-based.

Examples

julia> f = LeastSquaresLoss([1.0], reshape([2.0], 1, 1));

julia> g = zeros(1); d = zeros(1);

julia> ProximalBase.value_and_gradient_from_predictor!(g, d, f, [3.0])
2.0

julia> (g[1], d[1])
(4.0, 2.0)

Edge cases

  • Outputs must not overlap each other, the predictor, design, response or loss scratch. Nonempty overlaps reported by Base.mightalias are rejected; undetected sharing remains the caller's responsibility. In-place d === z is not supported.
  • Length/axis, factor and overlap checks precede writes. On any error, g, d and f.tmp remain unchanged.
  • Overflow/underflow in X'*d is not recovered before applying α. Overflow in z-Y makes the value non-finite, even where the standalone predictor value can recover it. Last-bit agreement is not promised.

For a LogisticLoss, supply η = X*β + offset. The operation returns the logistic objective, writes d[i] = w[i] * (σ(η[i]) - y[i]) and forms g = X' * d. Both outputs must be independent of the weights and offset as well. See logistic regression for its supported layouts.

See predictor accuracy, failure and concurrency rules.

source
ProximalBase.value_from_residual — Function
ProximalBase.value_from_residual(f, r)

Evaluate α*sum(abs2, r)/2 from a least-squares residual already held by the caller. Either sign, r = X*β-Y or r = Y-X*β, is accepted. No design or response entries are read and no loss fields are written. The call neither reads nor writes f.tmp; the supplied r may be a view of f.tmp.

Use the loss, scale and strided floating-point domain of ProximalBase.value_from_predictor. The residual must have the response's axes (DimensionMismatch otherwise). The result type, accuracy, allocation and concurrency guarantees are the same, with non-finite residuals producing non-finite values.

For SqrtLeastSquaresLoss, or one Scaled wrapper, the value is α*norm(r) for either residual sign. It has the same scale, domain, accuracy and range-recovery rules as that loss's value_from_predictor; no X, Y or f.tmp entries are accessed and r is not modified.

Examples

julia> f = LeastSquaresLoss([1.0], reshape([2.0], 1, 1));

julia> ProximalBase.value_from_residual(f, [-2.0])
2.0

See predictor and residual operations.

ProximalBase.leastsquares_data — Function
ProximalBase.leastsquares_data(f)

Return borrowed least-squares data as (; Y, X, α). Y and X are the stored arrays themselves, with no copy or conversion. The scale is one(T) for a LeastSquaresLoss of type T, or the stored factor of one Scaled wrapper, with its original type.

Both LeastSquaresLoss and SqrtLeastSquaresLoss, including data outside the strided predictor-oracle domain, are supported, as is one Scaled wrapper of either. For an unscaled loss, α = one(T); for a wrapper, α is the stored factor with its original type. The returned arrays do not distinguish the two losses; their types do. Other functions throw MethodError. The accessor neither validates nor converts the scale; numerical oracles may reject it or use a converted value.

Examples

julia> y = [1.0]; X = reshape([2.0], 1, 1);

julia> data = ProximalBase.leastsquares_data(LeastSquaresLoss(y, X));

julia> (data.Y === y, data.X === X, data.α)
(true, true, 1.0)

Do not mutate the borrowed arrays while the loss or any of its oracles is in use, including on another task. See ownership rules.

Separable nonconvex penalties

ProximalBase.NormL0 — Type
NormL0(λ = 1)

The nonconvex cardinality penalty f(x) = λ ⋅ #{i : xᵢ ≠ 0}, with nonnegative level λ. For positive finite λ and γ, the proximal operator keeps an input v when |v|² > 2γλ and returns positive zero on an exact tie or below the threshold. The comparison is exact for finite homogeneous Float32 and Float64 inputs.

At a zero level the value is zero and the proximal map is the identity for any valid step. At an infinite level the proximal map returns positive zero, including at a zero step. A positive finite level gives the identity at a zero step and the constant zero map at an infinite step. These maps apply to nonfinite entries as well. With a positive finite level and step, NaN and signed infinities pass through. A NaN entry gives a NaN value at any positive level, and each infinity contributes one nonzero entry.

Direct array oracles reject negative and NaN steps before writing, including entries of an array of steps. For prox_block and steps passed through Scaled, use nonnegative, non-NaN steps. A symmetric sparse iterate output requires a scalar step. Its off-diagonal entries count twice in the value. See the numerical contract for storage and endpoint details.

source
ProximalBase.SCAD — Type
SCAD(λ, a = 3.7)

The separable smoothly clipped absolute deviation penalty of Fan and Li (2001). The level satisfies λ ≥ 0 and the shape satisfies a > 2. For finite positive λ and finite a, an entry of magnitude t contributes λ*t up to λ, λ*t - (t-λ)^2/(2(a-1)) from λ to a*λ, and (a+1)*λ^2/2 beyond that.

The scalar proximal operator selects a global minimizer. At an exact tie it chooses the smaller magnitude, with positive zero at a zero minimizer. A zero level gives the zero function and an identity prox. An infinite level gives the indicator of zero, with a constant-zero prox even at a zero step. An infinite shape gives the ℓ₁ limit. At a positive finite level, a zero step gives the identity and an infinite step gives the constant-zero map.

Direct array oracles validate scalar and per-entry steps before writing. Use a nonnegative, non-NaN step with prox_block and as the effective step through Scaled. A symmetric sparse iterate output takes a scalar step. See the numerical contract for endpoint details.

Minimax concave penalty

ProximalBase.MCP — Type
MCP(λ, a = 3)

The separable minimax concave penalty with level λ ≥ 0 and shape a > 0. For finite positive parameters, the entry penalty at magnitude t is λ*t - t^2/(2a) up to t = a*λ and a*λ^2/2 thereafter, including at infinite entries. A NaN entry gives a NaN value at any positive level. At a = Inf and finite positive level, the penalty is λ*abs(x) per entry.

At a positive finite step γ < a the proximal map uses firm thresholding between γ*λ and a*λ (soft thresholding for infinite a). At a finite step γ ≥ a it keeps an entry when abs(x) > λ*sqrt(a*γ) and returns positive zero otherwise, including on an exact tie. Both rules preserve NaN and signed infinities.

A zero level gives zero value even at nonfinite entries and the identity proximal map at every valid step. An infinite level gives zero value at zero and infinite value at nonzero numbers, and maps all inputs to positive zero at every valid step. At a positive finite level, a zero step gives the identity and an infinite step gives positive zero, including for nonfinite inputs. Identity maps preserve signed zeros.

Direct array and iterate oracles reject negative and NaN steps before writing. The scalar hook prox_block and steps forwarded by Scaled require nonnegative, non-NaN steps. Symmetric sparse iterates use scalar steps and count off-diagonal values twice.

See the MCP numerical contract for the supported precision and endpoint rules.

Entrywise ℓ₁ norm, its nonnegative form and elastic net

ProximalBase.NormL1 — Type
NormL1(λ0 = 1)
NormL1(λ0, w)

Weighted ℓ₁ penalty f(x) = λ₀ Σᵢ wᵢ |xᵢ|, with all weights equal to one when w is omitted. The level and weights must be nonnegative and not NaN; these are checked at construction. Weights are retained by reference and paired with entries by linear index; later array mutations are not revalidated.

prox applies entrywise soft thresholding (shrink) with threshold γλ₀wᵢ. The function is separable and zero-preserving; value and same-kind sparse-iterate prox calls visit only stored entries.

Examples

julia> f = NormL1(0.5, [1.0, 2.0]);

julia> f([2.0, -1.0])
2.0

julia> prox(f, [2.0, -1.0], 1.0)
2-element Vector{Float64}:
 1.5
 0.0

Edge cases

  • Use real, one-based arrays and one weight per entry.
  • On a SymmetricSparseIterate, weights have p² entries in full-matrix linear order, interpreted as an exactly symmetric p × p array. Oracles assume this; validate with ProximalBase.check_symmetric_parameters.
  • A zero weight leaves an entry unpenalized. An infinite weight fixes a finite input at zero, even at zero level or step, but can return NaN for non-finite inputs at finite level.
  • An infinite overall level fixes positive-weight entries at +0, even for non-finite inputs and zero step; zero-weight entries remain free.

See ℓ₁ endpoint rules, the numerical contract and prox! for step and alias rules.

source
ProximalBase.NormL1Nonneg — Type
NormL1Nonneg(λ0 = 1)
NormL1Nonneg(λ0, w)

Weighted ℓ₁ penalty on the nonnegative orthant: f(x) = λ₀ Σᵢ wᵢ xᵢ where every entry is ≥ 0, and Inf at a point with a negative entry (the edge cases below give the rules for NaN); all weights equal one when w is omitted. The level and weights must be nonnegative and not NaN; these are checked at construction. Weights are retained by reference and paired with entries by linear index; later array mutations are not revalidated.

For finite inputs and a positive finite level, weight and step, prox applies max(vᵢ - t̂ᵢ, 0) to each entry, with the threshold t̂ᵢ = γλ₀wᵢ formed as NormL1 forms it: the proximal operator of λ₀wᵢxᵢ on xᵢ ≥ 0. The edge cases below give the other parameters. The function is separable, convex and zero-preserving; value and same-kind sparse-iterate prox calls visit only stored entries.

Examples

julia> f = NormL1Nonneg(2.0);

julia> f([1.0, 0.5])
3.0

julia> f([1.0, -1e-300])
Inf

julia> prox(NormL1Nonneg(0.5, [1.0, 2.0]), [2.0, -1.0], 1.0)
2-element Vector{Float64}:
 1.5
 0.0

Edge cases

  • Use real, one-based arrays and one weight per entry.
  • The domain is xᵢ ≥ 0 exactly: -0.0 and +Inf are feasible, and any negative number, a subnormal one included, is not. A zero level or weight keeps the domain. With finite weights, NormL1Nonneg(0.0) is the indicator of the orthant, with value 0 at a feasible point (+Inf entries included); an infinite weight keeps its own rule below at a zero level.
  • The value is NaN when an entry that is read is NaN, and otherwise Inf when one is negative; NaN takes precedence over Inf. A +Inf entry whose positive finite coefficient λ₀wᵢ rounds to zero also gives NaN, as for NormL1 (#655), and then takes precedence over the Inf of a negative entry. At a feasible point the terms are those of NormL1: -0.0 gives +0.

A zero level does the same for a finite weight, and a zero step for a finite level and weight. An infinite step with a positive finite level and a positive finite weight maps finite inputs and -Inf to +0, and +Inf and NaN to NaN; with a zero level or weight it projects.
  • An infinite level fixes positive-weight entries at +0 for every step γ ≥ 0, NaN and ±Inf inputs included; zero-weight entries are projected. The value of a positive-weight entry is 0 at 0, NaN at NaN and Inf at any other entry.
  • An infinite weight at a finite level maps finite inputs and -Inf to +0, also at zero level or step, and +Inf and NaN inputs to NaN. Its value is 0 at an entry 0 and Inf at any other number, also at a zero level.
  • A negative or NaN scalar step throws an ArgumentError before any write in prox, prox! and value_and_prox!. The entries of an array of steps and the scalar step of prox_block are not checked, and neither is a step that reaches the function through Scaled; there a negative step violates the precondition γ ≥ 0, and the result can depend on the representation (dense, sparse or symmetric).
  • On a SymmetricSparseIterate, weights have p² entries in full-matrix linear order, interpreted as an exactly symmetric p × p array. Oracles assume this; validate with ProximalBase.check_symmetric_parameters.

See ℓ₁ endpoint rules, the numerical contract and prox! for step and alias rules.

ProximalBase.IndBallL0 — Type
IndBallL0(s; diagonal = true)

Indicator of the set with at most s counted nonzero entries. The budget is a nonnegative integer, saturated at typemax(Int). The value is 0 for a feasible argument and Inf otherwise. A counted NaN gives NaN at any budget. Counted infinities are nonzero, and either sign of zero counts as zero.

julia> Tuple(prox(f, Symmetric(X, :L)))
(5.0, 0.0, 0.0, 7.0)

Maximum-magnitude norm

ProximalBase.NormLinf — Type
NormLinf(λ = 1)

The ℓ∞ norm f(x) = λ max|xᵢ| (the largest magnitude of the entries, of a matrix included), with a nonnegative level λ (an ArgumentError otherwise, NaN included). It is not separable. Its proximal operator clips the entries at a level τ ≥ 0: prox_{γf}(x)ᵢ = clamp(xᵢ, -τ, τ), where τ solves Σᵢ (|xᵢ| - τ)₊ = γλ, and τ = 0 (the output +0) when γλ ≥ ‖x‖₁, for finite entries. The comparison is made in floating point, and in units of a power of two when the sum or the radius leaves the range: with M = floatmax(Float64), prox(NormLinf(1.0), [M, M], M) gives [M/2, M/2] and prox(NormLinf(1.5), [M, M], M), whose radius 1.5M is beyond the range, gives about [M/4, M/4]. This is x minus its projection onto the ℓ1 ball of radius γλ, formed by the clip itself: for a positive clip level, the entries within the clip interval are copied, and a zero level fills +0. The level τ comes from Condat's algorithm, in O(n) expected time, with Michelot's algorithm when many entries become candidates.

The value takes arrays, the three iterates and a SymmetricSparseIterate (its largest stored magnitude: a repeated off-diagonal coordinate does not change a maximum), and is λ times the largest magnitude rounded once, in the floating type of the entries. With λ = 0 the value is zero, a NaN or infinite entry included; with λ = Inf it is zero at the zero argument (an empty one included), Inf at any other argument without a NaN entry, and NaN at a NaN entry. A level that is not of the type of the entries is applied in the promoted type and rounded once.

prox!, prox and value_and_prox! take arrays of the same size (a BlockIterate or a SparseIterate through indexed reads and writes of its entries, O(length)) and a scalar step; prox!(x, f, x, γ) is supported. A negative or NaN step, complex entries and indexing that is not one-based throw an ArgumentError, and a size mismatch a DimensionMismatch, before anything is written, also through Scaled. A SymmetricSparseIterate argument or output throws an ArgumentError before anything is written, also through Scaled: its proximal operator is not provided. After those checks the rules apply in this order. λ = Inf gives +0 at every nonnegative step, γ = 0 and γ = Inf included (#665), for every input. Otherwise λ = 0 or γ = 0 gives the identity (so γ = Inf with λ = 0 is the identity). Otherwise γ = Inf gives +0. At positive finite γ and λ, a NaN entry makes every output NaN, and an infinite entry without NaN leaves the argument unchanged, also when the finite product γλ overflows in floating point; otherwise the clip above, with the output +0 when γλ is at least ‖x‖₁ or overflows while ‖x‖₁ is finite. For finite entries a sum of magnitudes above floatmax/2 is handled in power-of-two units. value_and_prox! returns the value of the stored output. Through Scaled, the wrapper's recovery of a radius γλα beyond the range has a limit: for Scaled(NormLinf(2.0 * 2.0^-1000), 2.0^1000) at the step 0.75 floatmax(Float64) on two entries equal to floatmax(Float64), even the folded level at half the scale is out of range, the wrapper passes an infinite step, and the output is +0 where the exact result is about floatmax/4.

The accuracy of τ is absolute, of order n eps(T) max|xᵢ| + δ in the floating type T of the output for n entries, with δ = nextfloat(zero(T)): unlike the relative bounds of NormL2, an entry far below max|xᵢ| has no relative guarantee, and the storage of a subnormal radius or output adds the term δ (x = [δ], λ = δ, γ = 0.5 gives [δ] where the exact point is δ/2). The entries are read as abs(convert(T, xᵢ)); Float32 and Float64 with arguments of the same type are the supported precisions.

The threshold needs a buffer of length length(x). The object's own buffer is left untouched when the output y is an Array with element type T, the argument is an Array or a view of an Array, and y does not overlap the argument (Base.mightalias is false): y then serves as the buffer, before the clip overwrites it. Otherwise (for instance y === x, an overlapping output, a view or an iterate as output, another output type, or an argument of another type) a threshold call may use the object's own buffer, which is allocated by the first threshold call that needs it and again when the size or the element type changes. The early exits before the threshold is selected (a zero or infinite level, a zero or infinite step, a NaN or infinite entry, the zero fill when γλ ≥ ‖x‖₁) do not touch it. The same object must not be used from several tasks at once when its buffer may be in use: construct a fresh NormLinf(f.λ) for each task, or synchronize the calls.

Group maximum-magnitude norm

ProximalBase.GroupNormLinf — Type
GroupNormLinf(λ0, groups)
GroupNormLinf(λ0, groups, w)

Group ℓ∞ penalty f(x) = λ₀ Σₖ wₖ max_{i∈Gₖ} |xᵢ|, with default weights wₖ = 1. Groups are nonempty, disjoint lists or ranges of positive linear indices. julia> prox_block(f, [3.0, -1.0], 1, 4.0)

julia> kkt_violation(GroupNormLinf(1.0, [1:2]), [2.0, 4.0], [1.0, 0.0], 1)
5.0

Edge cases

  • Real, one-based arrays and valid shapes/groups are required. Negative or NaN steps fail before writes.
  • In-place prox (y === x) is supported. For compact blocks, out === u is supported; other overlaps detected by Base.mightalias are rejected, and out must not alias iterate storage.
  • The rules apply to each group in this order. wₖ = 0 leaves the group unchanged, also with λ₀ = Inf or γ = Inf. Otherwise wₖ = Inf, or λ₀ = Inf, gives +0 at every nonnegative step, γ = 0 and γ = Inf included. Otherwise λ₀ = 0 or γ = 0 gives the identity, also when λ₀wₖ overflows, and γ = Inf gives +0. At positive finite parameters a NaN entry makes every entry of its group NaN and leaves the other groups unaffected, and an infinite entry without NaN leaves its group unchanged, also when the finite product γλ₀wₖ overflows. For finite entries a sum of magnitudes above floatmax/2 is handled in power-of-two units, and a radius that overflows while the sum is finite gives +0.
  • The value of a group is λ₀wₖ max|x[Gₖ]|, formed in floating point as (λ₀wₖ) m (two rounded products) when λ₀wₖ is a normal number and by the three-factor kernel in power-of-two units otherwise, then converted to the output type: zero when wₖ = 0 (whatever the group holds), when the group is zero, and when λ₀ = 0 with a finite weight; then NaN at a NaN entry; Inf at a nonzero group, without NaN, when λ₀ or wₖ is infinite. The sum of the terms may be recomputed in power-of-two units where it may have lost accuracy (below K floatmin for K groups) or class (at or above floatmax/2). value_and_prox! returns the value of the stored output.
  • For finite inputs and positive finite parameters of the same type T (Float32 or Float64), the error of each stored proximal entry in a group of size n is bounded by 8 n eps(T) max|x[Gₖ]| + (2n + 1)δ, with δ = nextfloat(zero(T)). This assumes round-to-nearest arithmetic and n eps(T) ≤ 1/2 (unchecked, at most 2^22 entries per group in Float32). The bound is absolute and compares with clipping at the exact product γλ₀wₖ. The implementation uses the shared ℓ1-ball threshold of NormLinf, with power-of-two scaling for large sums.
  • kkt_violation(f, v, x, k) scores the group of entry k of an array point, or group k of a BlockIterate; an entry in no group scores abs(v[k]). At a zero group it is the signed margin ‖v[Gₖ]‖₁ - λ₀wₖ. At a nonzero group it is the Euclidean distance from -v[Gₖ] to the subdifferential of λ₀wₖ max|x[Gₖ]| at x[Gₖ], computed as the full-point score of NormLinf is, with its face (the entries of largest magnitude after conversion to the working type, with no tolerance), its exceptional values and its accuracy bound. kkt_violation(f, v, x) is the maximum of zero, of abs(v[i]) over the entries in no group and of that distance for every group, a zero group included: there it is the distance from v[Gₖ] to the ℓ1 ball of radius λ₀wₖ, which is not the margin. The three-argument form kkt_violation(f, v, i) and a SymmetricSparseIterate throw an ArgumentError, and so does a nonzero group of n entries for which n + 1 is not a finite number of the working type (in the full-point form, any group of that size).
  • The threshold needs a buffer of the length of the largest group. The object keeps one, allocated by the first group step that needs it and again when the element type changes. prox! and value_and_prox! use it for every group that reaches the threshold. prox_block! uses out as the buffer, and leaves the buffer of the object untouched, when out is an Array with a floating-point element type, u is an Array or a SubArray of an Array, and !Base.mightalias(out, u) (so not when out === u); otherwise it uses the buffer of the object. The parameter exits, a NaN or infinite group and a zero fill decided before the threshold (the computed radius reaches the computed sum of magnitudes) do not touch the buffer; a threshold whose level is zero has already used it. The same object must not be used from several tasks at once while its buffer may be in use: a Scaled wrapper shares the buffer of its function, and a threaded loop of prox_block!(u, f, u, k, γ) over groups does too. It must not be used reentrantly either, also within one task: a nested call on the same object, from a getindex of an argument while the threshold runs, can overwrite the candidates of the running threshold if it reaches the threshold with the shared buffer. Construct a fresh GroupNormLinf for each task, or synchronize the calls.
  • No SymmetricSparseIterate, restrict, per-group steps or compact block method under Scaled.
