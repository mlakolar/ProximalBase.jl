Range clauses

For supported homogeneous Float32 or Float64 calls, the value and numerical outputs use that working precision. The implementation may compute in a wider type for heterogeneous argument/destination calls, but this is not a supported mixed-precision contract. In the current kernels, the value uses the argument's precision; gradients and proximal points use the wider of the argument and destination precisions. Parameters are rounded to that working precision when representable, and proximal products are formed from their unrounded factors before rounding. Combined gradient calls return the standalone input value and gradient; combined proximal calls return the value at the stored output. These implementation details do not extend the supported configurations. Range recovery avoids losing a representable result to overflow/underflow in a coefficient or difference. For the supported mode, supply the level, center, step and destination in the same floating-point type as the argument. See numerics for FP32/FP64 and zero/non-finite cases. Shape mismatch is DimensionMismatch; complex center, argument or output is ArgumentError. Exact gradient aliasing with the input is rejected. Use independent parameter/output buffers even where a particular kernel can safely read an aliased center.

SqrNormL2 also recovers gradient differences and proximal convex-combination coefficients.

Endpoint clauses

The SqrNormL2 guide gives the score formula. See the shared non-finite KKT rules for the referenced rows.

CaseRetained behavior
SqrNormL2, zero levelZero standalone value; gradient/prox can still encounter IEEE zero-times-nonfinite arithmetic
SqrNormL2, infinite levelGradient is the IEEE λ(x - y): ±Inf for every nonzero residual, subnormal ones included, and NaN at a zero residual; the four-argument and full-point kkt_violation scores of SqrNormL2 take their gradient entry from the ridge-gradient helpers and follow this rule for finite v and x (the non-finite rules of the kkt_violation rows below take precedence, at an infinite level too: SqrNormL2(Inf), v = [Inf], x = [0.0] scores +Inf), while the three-argument screen does not use the gradient (kkt_violation(SqrNormL2(Inf), [1.0], 1) is 1.0)

The rules for non-finite entries of v and x take precedence over this formula (for f = SqrNormL2(1.0), v = [-Inf] and x = [Inf] the score is +Inf while norm(v + gradient(f,x), Inf) is NaN). The precision can differ: for f = SqrNormL2(1.0, [nextfloat(1.0)]), x = Float32[1] and v = Float32[0] the score works in Float64 and is eps(Float64), while gradient(f,x) rounds the center to Float32 and is zero. With an infinite level and finite v and x the four-argument and full-point scores follow the gradient oracle (NaN at a zero residual, Inf elsewhere); a non-finite entry of v or x still follows the non-finite rules (for f = SqrNormL2(Inf), v = [Inf] and x = [0.0] the score is +Inf, while the gradient is NaN).

A zero level makes the value zero, but does not make every gradient or endpoint operation immune to IEEE 0*Inf/0*NaN arithmetic.
