Scaling a function

Assumes: scalar multiplication and gradients · You will learn: how Scaled(f, α) changes function values, gradients and proximal steps.

The Julia type Scaled represents a nonnegative multiple of an existing mathematical function. This changes the scale of a function; it does not add two functions together or create a solver.

Nonnegative scaling

For $h=\alpha f$ with $\alpha>0$ and finite ordinary arithmetic,

\[h(x)=\alpha f(x),\qquad \nabla h(x)=\alpha\nabla f(x),\qquad \operatorname{prox}_{\gamma h}(x)=\operatorname{prox}_{(\gamma\alpha)f}(x).\]

The symbols map to Julia as follows: start with a function object f, choose a nonnegative scale α, and construct h = Scaled(f, α). The expressions α * f and f * α have the same meaning. Call h(x) to evaluate the scaled function. Thus f is the function being scaled, α is the multiplier, and x is the evaluation point. Negative or NaN scales throw ArgumentError; infinite scaling has function-specific exceptional arithmetic described in Array and precision conventions.

Built-in indicators. The indicators IndBallL0, IndBallL1, IndBallL2, IndBox (including IndBallLinf) and IndNonnegative do not depend on a nonnegative scale. Scaled(f, α), α * f and f * α return the indicator f itself for any nonnegative α, including 0, -0.0 and Inf, and nested scalings of an indicator return it too. A negative, NaN or -Inf factor throws ArgumentError. The constructor returns the indicator, so a call on the result is a call on the indicator, documented with each indicator. A negative or NaN scalar step makes prox, prox! and value_and_prox! throw before writing; another check (argument axes, shape or type) can raise its error first. The box and the orthant prox_block ignore the step. iszeropreserving(Inf * f) is that of f.

Smoothness, convexity, proximability and separability traits come from the original function. The type traits of a wrapper query its declared field type F. Zero preservation of a Scaled wrapper additionally requires a finite scale and an original function that preserves zero. Scaling only works with operations already supported by the original function. For example, scaling does not create a gradient for a function without one. Details about per-entry steps, special storage and extension hooks are in Operations on functions and Writing your own function.

For example, a proximal point for positive finite α and γ uses the original function's proximal map with step α * γ, as in the equation above. The lipschitz bound also scales by α. Other supported operations, such as scalar coordinate updates, coordinate restriction, and cache invalidation, are forwarded to the original function where methods exist. This wrapper does not automatically provide every possible extension, including value_entry or a compact-vector prox_block! implementation. See Writing your own function for extension contracts.

using ProximalBase
f = SqrNormL2(2.0)
h = Scaled(f,0.25)
x = [2.0,-1]
@assert h(x) == 0.25 * f(x)
@assert gradient(h,x) == 0.25 * gradient(f,x)
@assert prox(h,x,0.4) ≈ prox(f,x,0.1)
@assert lipschitz(h) == 0.5
@assert reset_cache!(h) === h
prox(h,x,0.4)
2-element Vector{Float64}:
  1.6666666666666667
 -0.8333333333333334

A built-in indicator is returned as it is:

box = IndBox(0.0, 1.0)
@assert 2.0 * box === box && Scaled(box, Inf) === box && 0 * (Inf * box) === box
prox(2.0 * box, [-1.0, 0.5, 3.0], 0.4)
3-element Vector{Float64}:
 0.0
 0.5
 1.0

Scoring optimality

kkt_violation(h, v, x, k) and kkt_violation(h, v, x) of h = Scaled(f, α) with a finite positive α evaluate the existing score of f on the lazy gradient v/α and multiply it by α: in exact arithmetic the score of $\alpha f$ is positively homogeneous in $\alpha$ and v together. f is NormL1, NormL1Nonneg, ElasticNet, ZeroFunction, LinearFunction, SqrNormL2, GroupNormL2, GroupNormLinf or, for the full-point form, NormL2, NormLinf, LeastSquaresLoss or QuadraticFunction. For one wrapper with a finite positive factor, on the numerical domain below with finite entries of the lazily scaled gradient v/α, at a zero coordinate and for arrays and parameters of one floating type, the signed score of a function that has a three-argument screen (NormL1, NormL1Nonneg, ElasticNet, ZeroFunction, LinearFunction, SqrNormL2) agrees bit for bit with the scaled three-argument screen, except for the endpoint cases of the numerical contract and for SqrNormL2 with an infinite level, whose score takes its gradient entry from the ridge-gradient helpers. GroupNormL2 and GroupNormLinf have no three-argument screen. The scores of the function are in scoring a coordinate.

h1 = Scaled(NormL1(0.5), 2.0)             # the function NormL1(1.0)
@assert kkt_violation(h1, [3.0, 0.5], [0.0, 1.0], 1) == 2.0      # 2 (|3/2| - 0.5)
@assert kkt_violation(h1, [3.0, 0.5], [0.0, 1.0], 2) == 1.5      # 2 |0.5/2 + 0.5|
kkt_violation(h1, [3.0, 0.5], [0.0, 1.0])
2.0

The full-point form of NormLinf is scored the same way. Scaled(NormLinf(0.5), 2.0) is the function NormLinf(1.0), and for a power of two as α the quotient v/α is exact where it neither overflows nor underflows.

h2 = Scaled(NormLinf(0.5), 2.0)           # the function NormLinf(1.0)
@assert kkt_violation(h2, [3.0, 1.0], [0.0, 0.0]) ≈ sqrt(5.0)                 # 2 × the score at v/2 = (1.5, 0.5)
@assert kkt_violation(h2, [3.0, 1.0], [0.0, 0.0]) ≈ kkt_violation(NormLinf(1.0), [3.0, 1.0], [0.0, 0.0])
kkt_violation(h2, [-0.4, 0.3], [2.0, 1.0])
0.6708203932499369
