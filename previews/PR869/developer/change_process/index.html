Contract conformance and contributor workflow

Reproducible documentation build

From the repository root on Linux with current Julia 1.x:

julia scripts/instantiate.jl docs
julia --project=docs docs/make.jl
python3 -m http.server 8000 --directory docs/build

Open http://localhost:8000/. The default local build uses .html links; CI uses directory URLs. Set CI=true locally to inspect that form. To rebuild without running each script in a separate process again, use PB_DOCS_SKIP_ISOLATED=true only during editing; the final/CI build runs them. The build always executes Literate examples in Documenter sandboxes and doctests. External link availability checks are optional via DOCUMENTER_LINKCHECK=true; internal cross-references and docstrings remain strict regardless.

The docs project contains Documenter, Literate and the local package. The instantiate script develops this checkout explicitly and restores Project.toml after Pkg setup. Generated docs/src/examples, developer/contracts, manifests and docs/build are ignored. Edit examples/.jl or docs/design/.md, not generated copies. The source listing in the extension tutorial is read from executable examples, so there is one authored definition.

Required checks

docs/make.jl preserves checkdocs=:exports, doctest=true, warnonly=false, KaTeX and HTML collapselevel=1. It checks explicit public reference coverage, regenerates Literate pages/contracts, runs every example in a fresh process, then builds with Documenter. Missing pages, unresolved @ref links, doctest failures and invalid docstrings fail the build. docs/check_html.py checks rendered internal links/anchors, page coverage and sidebar/math/code markup. Actual browser inspection complements that structural check.

julia --project=docs docs/run_examples.jl
julia --project=. -e 'using Pkg; Pkg.instantiate(); Pkg.test(; julia_args=["--check-bounds=yes"])'
python3 docs/check_html.py

CI is .github/workflows/CI.yml: one Linux/current-Julia job plus the existing PR required jobs and PR merge gate checks. There is no LTS/cross-platform/GPU documentation matrix. The docs build uses small deterministic CPU examples, without datasets or benchmark runs. CI also keeps the existing package tests and frozen benchmark reference integrity check. HTML and complete logs are uploaded as separate artifacts for review. On master pushes, a Linux/current-Julia deployment job waits for the merge gate, retrieves that exact validated HTML and calls docs/deploy.jl to restore historical Documenter publication to gh-pages/dev. Pull requests do not deploy previews or releases. Local docs/make.jl only validates/builds. Do not bypass required gates because local docs passed.

Tests and independent numerical checks

test/tiers.toml declares every retained test/helper. The current full inventory runs in isolated Julia processes; historical conformance suites are archived. julia scripts/test.jl core_functions selects a filename prefix; use --list to inspect selection. Add tests to the declared inventory and test/TESTING.md.

Choose independent reference calculations: direct residual/gradient formulas, linear solves for quadratic prox, BigFloat for range-sensitive ridge cases, explicit lower-triangle enumerations for owners, and expected active IDs for storage. Comparing two PB oracles alone can reproduce the same bug. Test FP32/FP64, dimensions, non-finite/zero parameters, aliasing, partial failures, active zeros and arbitrary ordered blocks as appropriate to the change.

Adding a function or storage method

  1. Specify mathematics, supported signatures, domain/shapes, traits, parameter ownership, return values and errors. Distinguish scalar/block/global index spaces.
  2. Implement public validation before predictable writes. Define parameter metadata and cache invalidation where needed. Keep private helpers private.
  3. Add independent regression evidence and a small executable example. For new storage writers check reverse maps/activity after both success and failure.
  4. Update docstrings, operations catalog, concrete guide, current contracts and the explicit API coverage matrix. Every public binding needs a grouped @docs entry.
  5. Measure relevant hot paths with the retained benchmark harness before making performance claims. Frozen-baseline controls and A/A comparisons matter for numerical changes; historical timings alone are not a current guarantee.
  6. Build strictly, inspect generated HTML/navigation and obtain an independent substantive review. Report implementation defects/ambiguous contracts separately during documentation work rather than changing code to fit an example.

Historical acceptance records

The archived iterate-family acceptance and symmetric-owner acceptance include old targets, amendments and past evidence. They are not current test commands or new public requirements. The current contracts and actual retained source/tests must agree before a behavior is described as supported.
