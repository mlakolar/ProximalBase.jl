Iterate and utility reference

The storage overview distinguishes entries, independent symmetric variables, groups and active slots. The product domain table documents supported Base/LinearAlgebra methods in addition to the named operations below.

Storage types

ProximalBase.SparseIterate — Type
SparseIterate([T = Float64,] n)
SparseIterate([T = Float64,] n, m)
SparseIterate(x::Union{SparseVector, SparseMatrixCSC, Array})

A vector or matrix that stores its nonzero entries in a compact list, so that reading or writing any entry is O(1), with supported sparse-aware products scaling with the number of active coordinates, nactive(x). Intended for coordinate-descent and active-set iterates that stay sparse. Its coordinates (see ncoordinates) are its entries, in linear order.

Setting an entry to zero keeps it in the list; call dropzeros! to remove stored zeros. The stored entries are the active coordinates (activecoordinates).

Its entries are real. The constructors, two-argument copyto! from an array (for a matrix also from a UniformScaling or an orthogonal factor), copy!, broadcasting into x and fill! throw an ArgumentError for a source or value of complex type, even with a zero imaginary part, before anything is written. A broadcast into x checks its leaves and its result: a result known to be complex from the types is rejected, and a result of another non-real type (a Union with a complex member, Any, Number) is evaluated before writing and rejected if an element is complex, with x unchanged. For a vector x, vec(x) and reshape(x, length(x)) are x itself and are checked too. copy! from a source of another size throws Base's error first, unless the source is a SparseIterate or a BlockIterate: one of the same length is copied by value in linear order, and one of another length throws a DimensionMismatch. The two-argument copyto! and copy! read types: a tuple, a generator or an array of abstract element type such as Vector{Any} passes the check, and its values are converted one by one. Other writes also convert values one by one, as writes into a plain Array of the element type of x do: writes through a view, through coordinates(x), through vec of a matrix or a reshape to another shape, indexed assignment such as x[i] = v or x[:] = c, copyto! with offsets or index ranges, and map!. A complex value converted one by one throws an InexactError, possibly after part of x has been written.

For a matrix, copyto!(x, Q) from an orthogonal or unitary factor Q, such as qr(A).Q, qr(A, ColumnNorm()).Q, lq(A).Q, hessenberg(A).Q (types QRCompactWYQ, QRPackedQ, LQPackedQ, HessenbergQ) or the adjoint of one, takes Q to be a lazy factorization object, not a dense matrix. It materializes Q into a dense temporary of the element type of x and then writes that matrix as an ordinary array value write. A complex factor, a size other than size(x), a failure to materialize Q and a failing conversion (an InexactError for a fractional value written into an integer x) throw before anything is written, so x is unchanged. The write is a value write, not a copy of a working-set state: an active coordinate whose new value is zero stays active. The dense temporary and its allocation are deliberate; a caller who needs speed can pass a precomputed dense matrix of the full size size(Q), such as lmul!(Q, Matrix{T}(I, size(Q))) with T = eltype(Q). Matrix(Q) can be thin, for example for a tall QR factor (qr(randn(4, 3)).Q has size 4x4 while Matrix(Q) is 4x3), whereas the write uses the full size(Q) matrix.

ProximalBase.SymmetricSparseIterate — Type
SymmetricSparseIterate([T = Float64,] p)
SymmetricSparseIterate(X::AbstractMatrix)

Symmetric matrix storage for the q = p(p + 1) / 2 variables of a real symmetric p × p matrix: the entries of its lower triangle, stored in a compact list with O(1) access, as SparseIterate. It is not an array. It has size(x) == (p, p), eltype(x), ncoordinates(x) == q, and the two-index access below; it has no length, axes, iteration, broadcasting or one-index access. Read it through one of its views, or copy it:

  • coordinates(x): a live, writable vector of the q variables, in the column-major order of the lower triangle (tril_index);
  • matrixview(x): a live, read-only p × p matrix (matrixview);
  • Matrix(x): an independent dense copy.

x[i, j] reads and x[i, j] = v writes one variable, from either triangle: the positions (i, j) and (j, i) name the same variable, and an index outside 1:p throws a BoundsError. x[k] with one integer is an ArgumentError, because coordinates(x)[k] and matrixview(x)[k] mean different things. A write converts the value to T first, and stores a nonzero converted value (NaN included) as an active coordinate; a zero written to a coordinate that is not active does not activate it, and a zero written to an active coordinate keeps it active. Use activate! for an explicit active zero and dropzeros! to remove active zeros. nactive counts the active coordinates; count(!iszero, activevalues(x)) counts those that are nonzero.

  • copy(x) is an independent state: values, active zeros and activation order.
  • similar(x) and similar(x, S) are empty symmetric iterates of the same p.
  • copyto!(y, x) between symmetric iterates replaces the state of y with a copy of that of x; copyto!(x, x) does nothing.
  • copyto!(x, A) and SymmetricSparseIterate(A) import a matrix A: it must be real, of size (p, p) and exactly symmetric (NaN matches NaN, 0.0 matches -0.0), compared before conversion to T. The previous active set of x is replaced by the coordinates whose converted value is nonzero, in increasing coordinate order. copyto!(x, A) with a source that shares memory with x, such as matrixview(x), throws an ArgumentError. To store one triangle of a matrix that is not symmetric, pass Symmetric(A, :L).
  • fill!(coordinates(x), 0) writes only the active values; with dropzeros!(x) it empties x in O(nactive(x)). There is no fill!(x, v).

Two symmetric iterates are == and isequal when their matrices are: isequal(x, y) is isequal(Matrix(x), Matrix(y)), so an active -0.0 differs from an absent coordinate under isequal but not under ==, and paired NaNs are isequal but not ==. Equal matrices have equal hashes whatever the active sets and their order. There is no comparison with an array and no isapprox: use Matrix(x) or matrixview(x).

Its coordinates are numbered column by column (tril_index): Public indexed assignment updates them, activecoordinates lists the active ones and coordinates is a vector view of them.

See Symmetric parameters for which arrays must be symmetric and which calls check them.

ProximalBase.BlockIterate — Type
BlockIterate([T = Float64,] p, groups)
BlockIterate(x::AbstractVector, groups)
BlockIterate([T = Float64,] p, num_groups::Integer)
BlockIterate(x::AbstractVector, num_groups::Integer)

A vector of length p whose coordinates, for coordinate descent, are the groups ("blocks") x.groups[k], which partition 1:p. The groups are ranges such as 1:5 or vectors of indices such as [2, 7, 9], of any sizes; BlockIterate(p, num_groups) and BlockIterate(x, num_groups) split 1:p into num_groups equal contiguous groups.

As the stored entries of a SparseIterate do, a set of active groups serves as the active set of a solver, and the entries of the other groups are zero. Writing a nonzero entry activates its group, activate! activates a group, and dropzeros! deactivates the active groups whose entries are all zero; an iterate built from a vector x starts with the groups that hold a nonzero entry. Reading or writing an entry is O(1), and so is activating or deactivating a group. ncoordinates is the number of groups, nactive, activecoordinates and isactive give the active groups, and blockview is a view of x at the entries of a group. Writing through this view follows the same activation rule as writing to x.

Its entries are real. The constructors, two-argument copyto! from an array, copy!, broadcasting into x and fill! throw an ArgumentError for a source or value of complex type, even with a zero imaginary part, before anything is written. A broadcast into x checks its leaves and its result: a result known to be complex from the types is rejected, and a result of another non-real type (a Union with a complex member, Any, Number) is evaluated before writing and rejected if an element is complex, with x unchanged. vec(x) and reshape(x, length(x)) are x itself and are checked too. copy! from a source of another length throws Base's error first, unless the source is a BlockIterate or a SparseIterate, which throws a DimensionMismatch. The two-argument copyto! and copy! read types: a tuple, a generator or an array of abstract element type such as Vector{Any} passes the check, and its values are converted one by one. Other writes also convert values one by one, as writes into a plain Vector of the element type of x do: writes through blockview(x, k) or another view, indexed assignment such as x[i] = v or x[:] = c, copyto! with offsets or index ranges, and map!. A complex value converted one by one throws an InexactError, possibly after part of x has been written.

Working sets and views

ProximalBase.ncoordinates — Function
ncoordinates(x)

The number of independent coordinates of the iterate x that a solver updates: the entries of a SparseIterate, the entries of the lower triangle of a SymmetricSparseIterate, the groups of an BlockIterate.

source
ProximalBase.nactive — Function
nactive(x)

The number of active coordinates of x: the stored entries of a SparseIterate or SymmetricSparseIterate, the active groups of a BlockIterate. Active-set solvers use them as the active set.

source
ProximalBase.coordinates — Function
coordinates(x)

A vector view of the coordinates of x (see ncoordinates): the entries of a SparseIterate in linear order, whatever its shape, and the entries of the lower triangle for a SymmetricSparseIterate. The view is an AbstractVector of length ncoordinates(x) indexed by coordinate, live (a later write to x shows through it) and writable, and building it copies nothing. It is never x itself.

The view is an ordinary vector of the element type of x. A write through it is a value write: it activates the coordinates it makes nonzero and removes none, and converts the value as a write into a plain vector does, so a complex value throws an InexactError, possibly after part of x has been written; the view has no complex check of its own. Its products and reductions are those of an ordinary vector (IEEE, O(length(x))): for the sparse product use x itself, as in dot(v, x). copyto!(coordinates(x), coordinates(y)) is a value write, while copyto!(x, y) is the state copy. A copyto!, copy! or broadcast that takes both x and coordinates(x) copies the source once first, so that its result is that of copying the source before writing; other calls, such as mul! with the view as both output and input, behave as they do on an aliased plain vector.

source
ProximalBase.activecoordinates — Function
activecoordinates(x)

A read-only AbstractVector{Int} of the active coordinates of x (see nactive), in the order in which they became active, except that dropzeros! moves the last ones into the places of those it removes. It is a handle on the internal list, not a snapshot: nothing is copied, and it does not grow when coordinates become active, so call activecoordinates again after changing the active set: after an activation, after dropzeros!, and after a whole-state replacement such as copyto!(x, y), which can reorder the list even when the active set and nactive(x) stay the same. Writing through it throws an ArgumentError, because the list and the iterate's reverse map must stay in agreement; write values through activevalues (or blockview(x, k) for a BlockIterate).

source
ProximalBase.activevalues — Function
activevalues(x::Union{SparseIterate, SymmetricSparseIterate})

A writable vector view of the values of the active coordinates of x, in the order of activecoordinates: entry a is the value of coordinate activecoordinates(x)[a]. Writing zero through it keeps the coordinate active; use dropzeros! to remove it. The view has the length nactive had when it was taken and does not grow, so, like activecoordinates, take it again after a coordinate becomes active, after dropzeros! or after a whole-state replacement such as copyto!(x, y), each of which can reorder the active list. Nothing is copied.

source
ProximalBase.isactive — Function
isactive(x, k)

Whether coordinate k of x is active (see nactive).

ProximalBase.activate! — Function
activate!(x::SparseIterate, i)
activate!(x::SymmetricSparseIterate, k)
activate!(x::BlockIterate, k)

Make coordinate i of x active, storing it as an explicit zero if it is not stored already, and return x. Assigning a zero does not store an entry, so this is how a coordinate joins the active set of an active-set solver; dropzeros! removes it again while it is zero. For a BlockIterate, make group k active, keeping its entries.

source
ProximalBase.matrixview — Function
matrixview(x::SymmetricSparseIterate)

A live, read-only p × p matrix view of x: ordinary matrix indexing, both triangles, no copy of the data. Later writes to x show through it. Nothing can be written through the view or through a wrapper derived from it (view, reshape, transpose, Symmetric): the write is refused and x is unchanged. A generic allocating operation on the view (A .+ 1, similar(A), collect(A)) returns an ordinary writable dense array. mul! of the view and a dense vector costs O(p + nactive(x)); other generic matrix operations on the view read all p² entries. Use Matrix(x) for an independent dense copy.

Non-finite vectors

A coefficient of x that is zero contributes nothing to the product, whether it is absent or an explicitly stored zero: a non-finite entry of v that meets only zero coefficients does not reach the result, and mul!(y, matrixview(x), v) is the same before and after dropzeros!(x), up to the order of the finite summation. A NaN coefficient is not zero and gives NaN.

Entries (r, c) and (c, r) are one variable of x; a coordinate of x is reached through coordinates, not through this view, so matrixview(x)[4] is a matrix linear index.

source
ProximalBase.blockview — Function
blockview(x::BlockIterate, k)

A view of the entries of group k. It is a view of x itself, so it aliases x. Writing through it follows the rule of x[i] = v: a nonzero entry activates the group and a zero never deactivates it (see dropzeros!). To take a proximal step at a trial point without activating the group first, compute prox_block!(out, f, u, k, γ) in a numerical buffer, then write the result with copyto!(blockview(x, k), out). norm and dot of the view read the storage directly (BLAS for contiguous groups), while other BLAS routines take generic paths for it.

source
ProximalBase.blockindices — Function
blockindices(x::BlockIterate, k::Integer)

The indices of the entries of group k, in the order in which x stores them, as a read-only AbstractVector{<:Integer}. A group stored as a range is returned as that range, whatever its index type: a group stored as UnitRange{Int32} is returned as a UnitRange{Int32}. A group stored as a vector is returned as a read-only wrapper of the stored vector whose element type is Int. A write through the wrapper (h[i] = v, fill!, copyto!, h .= v, sort! and the like) throws an ArgumentError and leaves the groups unchanged.

Constructing the result takes constant time and does not allocate or copy, and it stays valid for as long as x: the groups of an iterate never change, and activating groups, dropzeros!, copyto! and the other writes of values do not affect it. k must be in 1:ncoordinates(x), or a BoundsError is thrown (a Bool is not a group index).

The result can index any array: view(g, blockindices(x, k)) is the part of g that belongs to group k. The fields of x and of the wrapper (h.ids) are internal, and so is the array that parentindices(blockview(x, k)) returns: reading or changing them is not supported, and is not blocked.

Examples

x = BlockIterate(6, [[1, 4], [2, 5], [3, 6]])
blockindices(x, 2) == [2, 5]                 # a read-only vector of Int
blockindices(BlockIterate(6, 3), 2) === 3:4   # the stored range

ProximalBase.samegroups(a::BlockIterate, b::BlockIterate)

Whether two block iterates have the same block layout. Group arrays must not be mutated after construction. A successful comparison may cache the layout identity in an iterate; concurrent comparisons on the same iterate require external synchronization. This function is public but not exported.

Compaction and sparse-array binding

There is no nnz method for iterates. Count activity or mathematical nonzeros explicitly as explained in the guide.

SparseArrays.dropzeros! — Method
dropzeros!(x::Union{SparseIterate, SymmetricSparseIterate})

Remove stored zero coordinates from x and return x. On a SymmetricSparseIterate, these are coordinates of the lower triangle. When every stored value is zero, the working set is emptied. Otherwise the last stored coordinate moves into the place of each removed one, so the order of activecoordinates can change. The entries of x do not change.

source
SparseArrays.dropzeros! — Method
dropzeros!(x::BlockIterate)

Deactivate the active groups of x whose entries are all zero and return x. When every entry of every active group is zero, all groups are deactivated. Otherwise the last active group moves into the place of each removed one, so the order of activecoordinates can change. The entries of x do not change.

source
SparseArrays.nnz — Function
nnz(A)

Re-export of SparseArrays.nnz for standard sparse arrays. ProximalBase does not define an nnz method for its iterates. Use nactive to count active coordinates, including explicitly stored zeros; use count(!iszero, activevalues(x)) to count nonzero entries of a SparseIterate.

shrink(v, c)

Soft thresholding: sign(v) ⋅ max(|v| - c, 0) for a threshold c ≥ 0, the proximal operator of c|⋅|. A NaN in v propagates.

‖A - B‖ without allocating A - B: the Euclidean (Frobenius) norm for p = 2, the largest absolute entry for p = Inf. Both arrays must have real entries.

Selected three-factor product docstrings

These methods require matching Float32/Float64 and Symmetric wrappers of strided factors for their direct numerical guarantee. Mixed/generic methods have the narrower guarantees described in numerics.

Base.:* — Method
*(A::Symmetric{T}, X::SparseIterate{T, 2}, B::Symmetric{T}) where {T<:Union{Float32, Float64}}

The product C = A * X * B for a sparse iterate X, with C[i, j] the sum of A[i, k] * X[k, l] * B[l, j] over the coordinates (k, l) where X is mathematically nonzero, in O(nactive(X) * m * n) operations and O(m * n) memory for X of size m × n. A stored zero and an unstored entry are the same: no term is formed, and an X without nonzeros gives the zero matrix without reading A or B. A nonzero coefficient of X, including NaN and ±Inf, always contributes; the zeros of A and B are ordinary zeros, so a nonzero Inf of X against a zero of A or B gives NaN. The result need not equal A * Matrix(X) * B.

A term with three finite nonzero factors has the accuracy of an ordinary product of three numbers: it differs from the correctly rounded exact product by at most one neighbouring floating-point number for a normal result (a relative error below about 2 eps(T)), and by at most one spacing for a subnormal one. A term within that error of the overflow threshold or of half the smallest subnormal can fall on either side of it, the neighbour of floatmax(T) being Inf and the neighbour of zero being the smallest subnormal. Correct rounding is not promised. Beyond that margin the class of a term is decided by its final value and not by the first partial product, so 2^600 * 2^600 * 2^-600 is 2^600 and its underflow mirror is exact.

Terms are added in the storage order of X in the precision T, so tiny terms next to large ones are rounded away, as in any floating-point sum. An entry whose ordinary sum is non-finite is recomputed from its terms as a scaled sum when every factor of every nonzero coefficient at that entry is finite, so a sum that overflows before a later cancellation gives its finite value, and a sum beyond the range of T is ±Inf. If any such factor is NaN or infinite the ordinary IEEE value stands. A sum that is exactly zero is +0.0.

The guarantee covers Float32 and Float64 with Symmetric wrappers of strided matrices of the same element type as X. Other element types, and mixed element types, are outside the guarantee and take other methods of *. See Numerical contract.

Base.:* — Method
*(A::Symmetric{T}, X::SymmetricSparseIterate{T}, B::Symmetric{T}) where {T<:Union{Float32, Float64}}

The product C = A * X * B for a symmetric sparse iterate X, with the same contract as the product for a matrix SparseIterate: C[i, j] is the sum of A[i, k] * X[k, l] * B[l, j] over the entries (k, l) of the p × p matrix X that are mathematically nonzero, in O(X.nnz * p^2) operations and O(p^2) memory. A stored off-diagonal coefficient stands for the two entries (r, c) and (c, r), each contributing one term, and a diagonal coefficient for one. A stored zero and an unstored entry are the same: no term is formed, and an X without nonzeros gives the zero matrix without reading A or B. A nonzero coefficient, including NaN and ±Inf, always contributes; the zeros of A and B are ordinary zeros, so 0 * Inf is NaN. The result need not equal A * Matrix(X) * B.

A term with three finite nonzero factors has the accuracy of an ordinary product of three numbers: it differs from the correctly rounded exact product by at most one neighbouring floating-point number for a normal result (a relative error below about 2 eps(T)), and by at most one spacing for a subnormal one. A term within that error of the overflow threshold or of half the smallest subnormal can fall on either side of it. Correct rounding is not promised. Beyond that margin the class of a term is decided by its final value and not by the first partial product. Terms are added in the storage order of X in the precision T, the entry (r, c) of a coefficient before (c, r), so tiny terms next to large ones are rounded away, as in any floating-point sum. An entry whose ordinary sum is non-finite is recomputed from its terms as a scaled sum when every factor of every nonzero entry of X at that entry is finite, so a sum that overflows before a later cancellation gives its finite value; if any such factor is NaN or infinite the ordinary IEEE value stands. A sum that is exactly zero is +0.0.

The guarantee covers Float32 and Float64 with Symmetric wrappers of strided matrices of the same element type as X. Other element types, and mixed element types, are outside the guarantee and take other methods of *. The method reads the stored fields nzval, nzval2ind, nnz and p. See Numerical contract.
