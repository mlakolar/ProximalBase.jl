Writing your own function

Assumes: Julia structs and multiple dispatch · You will learn: how to implement mathematical function interfaces and check their inputs.

Extend mathematical methods without reaching into iterate fields. Choose the smallest interface that describes the operations you can implement.

The AbstractFunction extension rules below apply to array functions. For observation-level prediction losses, implement the separate ProximalBase.ScalarLoss interface.

Any mathematical function

Subtype AbstractFunction, define the callable value (f::MyFunction)(x) and declare the appropriate type traits. Generic defaults are deliberately limited:

Capability you implementRequired hooksGeneric result
Smooth functionvalue_and_gradient!(out,f,x) and issmoothgradient! delegates to it; allocating gradient/value_and_gradient use it
Proximable functionprox!(out,f,x,γ) and isproximableallocating prox; default value_and_prox! computes prox then f(out)
Entry-separable functionSubtype SeparableFunction, value_entry and scalar prox_blockArray/iterate values, prox!, value_and_prox!; separability/proximability traits true
Compact block-only oracleprox_block!(out,f,u,k,γ)Allocating vector prox_block only

isconvex defaults false and must be declared when justified. There is no automatic gradient from a value, scalar prox from a full-array prox, KKT screen, restriction, Lipschitz bound or full-array lifting of a compact block oracle. Generic methods accepting tuples do not imply that the underlying function supports tuple inputs; it still needs methods for the requested argument types. The generic gradient! default depends on value_and_gradient!, so implement that hook if relying on the default.

An overriding public operation owns real-type, shape, parameter-extent and aliasing preflight; parameter symmetry is a model precondition that the caller or solver validates. Destination comes first. Return the identical output for gradient!/ prox!/prox_block!, a scalar input value for value_and_gradient!, and a scalar stored-output value for value_and_prox!. Proximal output may be exactly the input; gradient output must be independent. Do not write parameters, input buffers or solver storage while constructing a pure numerical result.

Floating-point precision for extensions

For the supported CPU numerical targets, test custom functions with homogeneous Float64 arguments/parameters/outputs and, where supported by the extension, homogeneous Float32 arguments/parameters/outputs. Custom hooks are not automatically required to handle mixed Float32/Float64 calls, and the generic interface does not supply arbitrary-precision or exceptional-range recovery. If an extension supports additional combinations, document their conversion and result type rules separately.

Stable formulas and selective recovery for representable results are encouraged. The common finite path should remain efficient; the extension author decides which exceptional cases merit additional arithmetic. See the numerical contract.

Separable functions

Suppose the function can be written as a sum of independent coordinate terms,

\[f(x)=\sum_{i=1}^{p} f_i(x_i).\]

A Julia subtype of SeparableFunction supplies two scalar operations: value_entry(f, v, i) evaluates $f_i(v)$, while prox_block(f, v, i, γ) computes the scalar proximal point of $\gamma f_i$ at $v$. Here i is the linear entry index of the underlying argument, used to index parameters. Generic kernels visit arrays, SparseIterate, BlockIterate and symmetric iterates. Declare check_parameters(f,x) to reject wrong parameter extent before generic writes. Use prod(size(x)) rather than length(x) when accepting symmetric iterates.

Declare every per-entry array in entry_parameters(f) as a tuple of Symbol=>value pairs; declare () if none. A custom SeparableFunction's default is nothing, which check_symmetric_parameters rejects. On a symmetric iterate your per-entry arrays must be exactly symmetric: the generic kernels assume it and compare no mirrored entries, so asymmetric arrays are an invalid model with no guaranteed numerical meaning. Call check_symmetric_parameters(f,x) once per model, at the solve or workspace boundary and after any change to the arrays. Within ProximalBase it is the only reader of entry_parameters; the extent of your arrays is the job of check_parameters. See symmetric parameters.

iszeropreserving(f)=true is a mathematical promise that $f_i(0)=0$ and $prox_{γf_i}(0)=0$ for all positive finite γ. Only declare it when valid for every parameter value the instance permits. It enables sparse traversal; it does not provide an oracle or license arbitrary NaN suppression. Symmetric values count off-diagonal entry terms twice, while coordinate vectors count one independent value. Raw scalar calls do not check symmetric-iterate symmetry; validate the original function before using them.

For example, the WeightedSquare implementation represents

\[f(x)=\frac12\sum_{i=1}^{p}w_i x_i^2,\qquad w_i\geq0.\]

Its scalar functions are

\[f_i(v)=\frac{w_i v^2}{2},\qquad \operatorname{prox}_{\gamma f_i}(v)=\frac{v}{1+\gamma w_i}.\]

The Julia methods correspond directly to these formulas:

ProximalBase.value_entry(f::WeightedSquare, v, i) = f.w[i] * v^2 / 2
ProximalBase.prox_block(f::WeightedSquare, v, i, γ) = v / (1 + γ * f.w[i])

The complete implementation owns its weights, checks finite nonnegative parameters, defines both methods and the required parameter metadata, and verifies dense, sparse and symmetric use and the explicit rejection of asymmetric weights. Its definition and checks are included below from that executable source.

# A custom separable function
#
# *Assumes: Julia structs and convex separable functions · You will learn: a custom function with mathematical value and proximal hooks.*
# See [zero-preserving functions](../glossary.md#Zero-preserving-function) for the sparse-computation trait.
#
# WeightedSquare represents sum(w[i]*x[i]^2)/2, with finite nonnegative weights.
using ProximalBase, LinearAlgebra
struct WeightedSquare{A<:AbstractArray} <: SeparableFunction
    w::A
    function WeightedSquare(w::A) where {A<:AbstractArray}
        eltype(w) <: Real || throw(ArgumentError("real weights required"))
        all(v -> isfinite(v) && v >= 0, w) || throw(ArgumentError("finite nonnegative weights required"))
        new{A}(copy(w))
    end
end
ProximalBase.value_entry(f::WeightedSquare, v::Real, i::Integer) = f.w[i] * v^2 / 2
ProximalBase.prox_block(f::WeightedSquare, v::Real, i::Integer, γ::Real) = v / (1 + γ * f.w[i])
ProximalBase.iszeropreserving(::WeightedSquare) = true
ProximalBase.isconvex(::Type{<:WeightedSquare}) = true
ProximalBase.entry_parameters(f::WeightedSquare) = (:w => f.w,)
function ProximalBase.check_parameters(f::WeightedSquare, x)
    length(f.w) == prod(size(x)) || throw(DimensionMismatch("weights must match the number of entries"))
    nothing
end
# No smoothness trait or gradient is synthesized by SeparableFunction.
f = WeightedSquare([1.0, 2, 3])
x = [1.0, -2, 0]
@assert isseparable(f) && isproximable(f) && !issmooth(f)
@assert f(x) ≈ sum(f.w .* x.^2) / 2
@assert prox(f, x, 0.5) ≈ x ./ (1 .+ 0.5 .* f.w)
s = SparseIterate(x)
activate!(s, 3)
z = prox(f, s, 0.5)
@assert Vector(z) ≈ prox(f, x, 0.5)
@assert nactive(z) == 2  # fresh output does not inherit an active zero
# On a symmetric iterate the weights must be exactly symmetric. The oracles assume
# this; the declaration above lets the explicit check validate the model once.
h = WeightedSquare([1.0 2; 2 3])
sym = SymmetricSparseIterate([1.0 2; 2 0])
@assert ProximalBase.check_symmetric_parameters(h, sym)
@assert h(sym) ≈ sum(h.w .* Matrix(sym).^2) / 2
@assert Matrix(prox(h, sym, 0.5)) ≈ Matrix(sym) ./ (1 .+ 0.5 .* h.w)
# Asymmetric weights are an invalid model, rejected by the explicit check before any
# oracle is called. The oracles give them no meaning.
bad = WeightedSquare([1.0 2; 3 1])
try
    ProximalBase.check_symmetric_parameters(bad, sym)
    error("expected asymmetric weights to fail")
catch err
    @assert err isa ArgumentError
end
Vector(z)

This example deliberately leaves issmooth=false; being a mathematical quadratic does not synthesize a gradient method. Its simple scalar arithmetic does not promise the built-in ridge kernel's extreme-range recovery. To make it smooth, implement/check a full fused gradient and define the trait; to support KKT/restrict/lipschitz, define and validate those independently.

Compact-vector block extensions

A block function may act on a compact vector $u$ representing one group. For the BlockSquare example, group $k$ has the mathematical form

\[h_k(u)=\frac{a_k}{2}\|u\|_2^2,\qquad \operatorname{prox}_{\gamma h_k}(u)=\frac{u}{1+\gamma a_k}.\]

Its Julia implementation stores a parameter a[k] for each group and implements prox_block!(out, f, u, k, γ) by writing u ./ (1 + γ * f.a[k]) to out.

More generally, a custom block method computes $\operatorname{prox}_{\gamma h_k}(u)$ from a numerical trial u and group index k. Buffers are in that group's ordered compact index space, not the full vector. Validate one-based real vectors, group bounds, exact length, parameters and overlap before writes. Support out===u; reject other overlap. Return out. The allocating default creates a plain floating Vector and calls your hook; it does not check your parameters or lift the hook into full-array prox.

Output must be independent of iterate storage and solver/model caches. The caller matches the partition, computes the trial, invokes the hook in scratch, then writes copyto!(blockview(x,k),out) and updates its residual. A zero result can leave an absent block inactive because the trial was never written there. Parameter symmetry and independent-coordinate geometry are not automatically defined for an arbitrary block decomposition on a symmetric iterate.

The complete BlockSquare example checks allocating, exact in-place and rejected-overlap calls. Implementing only this block method does not by itself define a full-array proximal operator or its associated traits.

# A compact-vector block proximal extension
#
# *Assumes: block-coordinate methods and Julia dispatch · You will learn: a custom block proximal operator that does not mutate solver storage.*
# The [proximal operator](../glossary.md#Proximal-operator) computes a mathematical point without updating solver storage.
#
# BlockSquare defines h_k(u)=a[k]*||u||²/2 on each ordered group.
# This example implements a custom group function, not a built-in group penalty.
using ProximalBase, LinearAlgebra
struct BlockSquare <: AbstractFunction
    groups::Vector{Vector{Int}}
    a::Vector{Float64}
end
function ProximalBase.prox_block!(out::AbstractVector, f::BlockSquare,
                                  u::AbstractVector, k::Integer, γ::Real)
    Base.require_one_based_indexing(out, u)
    eltype(out) <: Real && eltype(u) <: Real || throw(ArgumentError("real buffers required"))
    checkbounds(f.groups, k)
    length(out) == length(u) == length(f.groups[k]) || throw(DimensionMismatch("compact block length"))
    out === u || !Base.mightalias(out, u) || throw(ArgumentError("overlapping buffers"))
    length(f.a) == length(f.groups) || throw(DimensionMismatch("one level per block"))
    a = f.a[k]
    isfinite(a) && a >= 0 || throw(ArgumentError("finite nonnegative level required"))
    isfinite(γ) && γ > 0 || throw(ArgumentError("positive finite step required"))
    ## This illustrative extension accepts ordinary finite arithmetic. Unlike the
    ## built-in ridge kernel, it does not promise extreme-range recovery.
    denominator = 1 + γ * a
    isfinite(denominator) || throw(ArgumentError("step times level overflowed"))
    out .= u ./ denominator
    out
end
# A block-only hook does not establish a full-array proximal capability.
f = BlockSquare([[3, 1], [4, 2]], [2.0, 4])
x = BlockIterate(4, f.groups)
@assert all(collect(blockindices(x, k)) == f.groups[k] for k in 1:2)
u = [3.0, -2]
out = zeros(2)
@assert prox_block!(out, f, u, 1, 0.5) === out
@assert out ≈ u / 2 && nactive(x) == 0
allocated = prox_block(f, u, 1, 0.5)
@assert allocated !== u && allocated ≈ out
inplace = copy(u)
prox_block!(inplace, f, inplace, 1, 0.5)
@assert inplace ≈ out
# Only this separate public storage write activates the block.
copyto!(blockview(x, 1), out)
@assert collect(activecoordinates(x)) == [1]
copyto!(blockview(x, 2), prox_block(f, zeros(2), 2, 0.5))
@assert !isactive(x, 2)
# Other overlapping buffers fail before any output changes.
buffer = [1.0, 2, 3]
try
    prox_block!(view(buffer, 1:2), f, view(buffer, 2:3), 1, 0.5)
    error("expected overlap to fail")
catch err
    @assert err isa ArgumentError
end
@assert buffer == [1, 2, 3]
Vector(x)

Validation checklist

Verify independent formulas, source/destination order, identical-output return, FP32/FP64 behavior you intend to support, stored zeros, wrong extent and bad parameters, exact in-place prox, rejected overlap and parameter metadata. Use arbitrary ordered/noncontiguous groups to catch accidental global indexing of compact buffers. For symmetric support, test multiplicity, exact pair checks and unchanged values/activity after preflight errors. The developer workflow describes where regression tests and executable examples belong.
