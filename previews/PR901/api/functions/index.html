Function reference

The function library gives dimensions, errors, numerical examples and capability limits for the available concrete function types.

Smooth array functions

ProximalBase.LeastSquaresLoss — Type
LeastSquaresLoss(Y, X)

The least-squares loss f(β) = ‖Y - Xβ‖² / 2, smooth with gradient X'(Xβ - Y). Y may be a vector or an n × k matrix with one column per response; then β and the gradient are p × k matrices and ‖⋅‖ is the Frobenius norm, as in multi-response regression. β may be a dense array, a SparseIterate or a BlockIterate, whose products cost O(n ⋅ nnz).

It is also proximable: the first proximal operator computes the thin SVD X = U Diagonal(s) V' and Diagonal(s) U'Y once, after which prox_{γf}(v) = (X'X + I/γ)⁻¹ (X'Y + v/γ) costs two products with V for any γ, also when p > n. ADMM changes γ freely at no cost.

ProximalBase.SqrNormL2 — Type
SqrNormL2(λ = 1)
SqrNormL2(λ, y)

The squared Euclidean norm f(x) = (λ/2) ‖x - y‖², with y = 0 when omitted: the ridge penalty, and for λ = 1 the loss ‖x - y‖² / 2. Smooth, with gradient λ(x - y), separable, and proximable, with proximal operator (x + γλy) / (1 + γλ). For a matrix x, ‖⋅‖ is the Frobenius norm. Values follow the overflow rule in Overflow and underflow of values.

Precision

The level λ, the center y and the step are parameters; they are rounded once to the model precision of each result and never widen it. That precision is the wider of the argument's and the destination's for a gradient or a proximal point, and the argument's for the value (so the value written by value_and_prox! is the value at the stored point, and value_and_gradient! returns the standalone value and writes the standalone gradient). The proximal weight γλ is formed from the unrounded factors before it is rounded.

A parameter, a product or a coefficient that would leave the range of the model precision does not change a representable result: the gradient of SqrNormL2(2^-1022, [-2^1023]) at [2^1023] is [4.0] although x - y overflows, and prox! of SqrNormL2(2^800) with step 2^800 at [2^900] gives 2^-700 in Float64, where 1/(1 + γλ) is not a number. The ordinary computation runs first, and the recovery is chosen once per call from the parameters, except for a Float64 center entry outside the range of a Float32 model, which is handled for that entry.

ProximalBase.QuadraticFunction — Type
QuadraticFunction(A, b = nothing, c = 0)

The quadratic f(x) = x'Ax / 2 + b'x + c for a symmetric positive semidefinite A, with b = 0 when omitted. Smooth, with gradient Ax + b, and proximable: the first proximal operator computes the eigendecomposition A = QΛQ' once, after which prox_{γf}(x) = Q (I + γΛ)⁻¹ Q'(x - γb) costs two products with Q for any positive finite γ.

The constructor checks real types, squareness and the length of b, but does not verify symmetry or positive semidefiniteness. Those are caller assumptions. Values/gradients use A directly; the cached eigenbasis uses Symmetric(Matrix(A)) with its default upper triangle. Use vectors of compatible length. Data are retained by reference; after same-shape A changes call reset_cache!.

ProximalBase.ZeroFunction — Type
ZeroFunction()

The zero function f(x) = 0: smooth, with gradient zero, and proximable, with the identity as proximal operator. The penalty of an unpenalized problem. Array proximal copies use copyto!, so matching SparseIterate/BlockIterate input and output replace active state when distinct. Symmetric-iterate proximal writes preserve destination activity. Symmetric-iterate gradients are not implemented.

ProximalBase.LinearFunction — Type
LinearFunction(c, d = 0)

The linear function f(x) = ⟨c, x⟩ + d, with gradient c. Its proximal operator is the shift x - γc.

The coefficients and the argument have the same dimensions, size(c) == size(x); on a SymmetricSparseIterate, c is p × p. Every oracle throws a DimensionMismatch for any other pair, even one with as many entries, before it writes.

At a matrix SparseIterate the value is the sum over its stored entries whose value is nonzero, and reads c at those entries only. A Diagonal c is read at the nonzero stored diagonal entries, in O(p); the other entries of x are ignored, as in the diagonal-only dot of Diagonal. An entry that is not stored, or is stored as +0 or -0, adds nothing, even if the coefficient there is NaN, Inf or -Inf; the constant d is added after the sum. A nonzero entry follows ordinary arithmetic, also when it or its coefficient is not finite. The order of the summation is not specified: the general loop may reassociate (@simd), and the Diagonal loop runs in increasing diagonal index. The order can change the IEEE class of the result when an entry is not finite. For example, with c = ones(2, 2), d = 0 and h = 2^exponent(floatmax(T)), storing x[2] = h, x[3] = h and then x[1] = -Inf, a serial sum in the storage order overflows to +Inf before it adds -Inf and gives NaN, while the dense dot gives -Inf. When d, the nonzero entries of x and the coefficients at them are finite, a dot that overflows is summed again in exponent-separated terms and combined with d in its own units. Its accuracy is the absolute bound 4 n eps (sum |cᵢxᵢ| + |d|), and when that bound is below the range of the type and the exact value lies inside the range by that bound, the value is finite, also if products or partial sums overflow. When the bound exceeds the range (products far beyond it), there is no guarantee of a finite value: extreme cancellation can give an infinity for a finite exact value.

x = SparseIterate(2, 2); x[1, 1] = 2.0
f = LinearFunction([1.0 NaN; 1.0 1.0], 0.25)    # NaN at an entry of x that is not stored
f(x)                                            # 2.25
f(Matrix(x))                                    # NaN, as dot(f.c, Matrix(x)) + f.d

This rule is for the value at a matrix SparseIterate. For a dense c that is not a Diagonal, dot(c, x) is the generic dot, which visits all positions; for a Diagonal it is the diagonal-only dot of Diagonal. A vector SparseIterate and a SymmetricSparseIterate keep their own rules.

Entrywise ℓ₁ norm

ProximalBase.NormL1 — Type
NormL1(λ0 = 1)
NormL1(λ0, w)

The weighted ℓ1 norm f(x) = λ0 Σᵢ wᵢ |xᵢ|, with all wᵢ = 1 when w is omitted. Its proximal operator is entry-wise soft thresholding (shrink). Separable, so prox_block computes any scalar coordinate, and on a sparse iterate the value and the proximal operator touch only the stored entries. On a SymmetricSparseIterate the weights are a p × p matrix (or anything indexed by the linear indices of one), as for a dense matrix. On a symmetric iterate the weights must be exactly symmetric, a precondition that the oracles assume and do not compare; validate it with ProximalBase.check_symmetric_parameters. Wrap a matrix in Symmetric(W, :L) to use its lower triangle. Values follow the overflow rule in Overflow and underflow of values; terms that round below floatmin are recomputed where they could change the value by more than ordinary rounding (issue #373). An infinite weight maps a finite input value to zero at every level and step, including a zero level or step (the value is Inf away from zero). For inputs of NaN or ±Inf at finite level there is no fixed-zero guarantee: ordinary soft thresholding may return NaN (issue #853). A zero weight remains unpenalized. An infinite overall level λ0 at any nonnegative step instead fixes every positive-weight entry at +0, even for non-finite inputs (historical decision 49). At γ = 0 this is the limit γ → 0+ of the proximal map of the fixed function, the projection onto the closure of its domain, not soft thresholding by 0⋅Inf (issue #665): prox(NormL1(Inf, [1, 0, 2]), [3.0, 4.0, 5.0], 0.0) == [0.0, 4.0, 0.0]. Zero-weight entries stay free. A threshold that overflows to Inf from finite level, step and weight factors is not an infinite model parameter; its behavior for ±Inf inputs is a deferred limitation (issue #866). The value is 0 at the zero vector and remains NaN at a NaN entry.

See Symmetric parameters for which arrays must be symmetric and who validates them.

ℓ₂ and group ℓ₂ norms

ProximalBase.NormL2 — Type
NormL2(λ = 1)

The Euclidean norm f(x) = λ ‖x‖₂ (the Frobenius norm for a matrix), with a nonnegative level λ (an ArgumentError otherwise, NaN included). Its proximal operator shrinks the whole argument towards zero: prox_{γf}(x) = max(1 - γλ/‖x‖₂, 0) x. On a nonempty argument it is GroupNormL2(λ, [1:length(x)], [1]), one group with weight one, and follows the same rules: a sum of such norms over groups of entries is GroupNormL2.

The value takes arrays, the three iterates and a SymmetricSparseIterate, whose norm is that of the symmetric matrix it represents: each stored off-diagonal coordinate counts twice in the squared norm. On a SparseIterate or a SymmetricSparseIterate the value reads the stored entries only, also when a sum of squares that overflows or underflows is recomputed in power-of-two units (#808). With λ = 0 the value is zero; with λ = Inf it is zero at the zero argument (an empty one included), Inf at any other argument without a NaN entry, and NaN at a NaN entry.

prox!, prox and value_and_prox! take arrays of the same size (a BlockIterate or a SparseIterate through indexed reads and writes of its entries, O(length) in general, as for an array) and a scalar step. A negative or NaN step throws an ArgumentError before anything is written, and so do sizes, real element types and one-based indexing; prox!(x, f, x, γ) is supported. A SymmetricSparseIterate argument or output throws an ArgumentError before anything is written: its proximal operator is not provided. Exceptional cases are those of a single group of GroupNormL2 with weight one, in this order: λ = Inf gives +0 at every nonnegative step, γ = 0 included (#665), for every input; otherwise λ = 0 or γ = 0 gives the identity (so γ = Inf with λ = 0 is the identity); γ = Inf with a positive finite λ gives +0; at positive finite γ and λ, a NaN entry makes every output NaN, an infinite entry without NaN leaves the argument unchanged, also when the finite threshold γλ overflows in floating point, and the zero argument gives +0. For finite inputs, a norm whose sum of squares overflows or underflows and a threshold out of range are recomputed in power-of-two units. A value at or above floatmax/2 is recomputed in power-of-two units, accumulated in at least Float64; within a few eps of the overflow threshold either floatmax or Inf may be returned, regardless of which of them the exact value rounds to (#904). value_and_prox! returns the value at the stored output.

ProximalBase.GroupNormL2 — Type
GroupNormL2(λ0, groups)
GroupNormL2(λ0, groups, w)

The group-lasso penalty f(x) = λ0 Σₖ wₖ ‖x[Gₖ]‖₂ over disjoint groups Gₖ = groups[k] of linear indices of x, of any sizes and in any order, such as 1:5 or [7, 2, 9]. The weights default to wₖ = √|Gₖ|. A group of one index with weight w is the term λ0 w |xᵢ| of NormL1(λ0, w). Indices in no group are not penalized: prox! copies them and f(x) ignores them.

λ0 and the weights must be nonnegative (an ArgumentError otherwise, NaN included), with one weight per group (DimensionMismatch). Groups must be nonempty and disjoint, with positive indices (ArgumentError). The constructor stores its own copies of groups (integer indices: when the element type of groups is a concrete range type the ranges are kept, otherwise every group becomes a Vector{Int}) and of w; the level and the weights are converted to the promoted floating type of λ0 and w. Changing the arrays passed in does not change f.

The proximal operator shrinks each group towards zero in Euclidean norm: prox_{γf}(x)[Gₖ] = max(1 - γλ0wₖ/‖x[Gₖ]‖₂, 0) x[Gₖ]. On arrays, prox!, prox and value_and_prox! take a scalar step. For one group, prox_block!(out, f, u, k, γ) writes the result for the compact vector u = x[Gₖ] (in the order of groups[k]) into out and returns out. prox_block(f, u, k, γ) allocates out. Neither writes to or activates an iterate (u may be a view that reads one; out must not alias iterate storage, as the block contract requires): to update a BlockIterate with the same groups, write out with copyto!(blockview(x, k), out). BlockIterate(x, f) and BlockIterate(p, f) build an iterate with the groups of f. The groups must then partition 1:length(x).

kkt_violation(f, g, x, k) on a BlockIterate is ‖g[Gₖ]‖₂ - λ0 wₖ, the violation of the optimality of the zero group k for the smooth-part gradient g. Group k of x must equal groups[k] (DimensionMismatch otherwise). On an array point, kkt_violation(f, g, x, i) takes an entry i: the same group screen when the group of i is zero in x, and |g[i]| when i is in no group or its group has a nonzero entry. The three-argument form throws an ArgumentError: the penalty is not separable. In the group screen the coefficient λ0 wₖ follows the NormL1 screen: 0 for a zero weight, also with an infinite level, and Inf for an infinite weight or for an infinite level with a positive weight. A norm or coefficient outside the range is recomputed for finite gradients. When the screened group holds a ±Inf entry and no NaN, the screen is the IEEE Inf - λ0 wₖ, which is NaN when that coefficient is infinite, also when it overflows from finite factors; a NaN entry gives NaN.

Steps must be nonnegative: a negative or NaN step throws an ArgumentError before anything is written, in prox!, value_and_prox! and prox_block!. Shapes, the group extent (every group index at most length(x)), real element types, one-based indexing, and for prox_block! the group index, the buffer lengths and the aliasing of out and u, are checked before writes as well. out === u is supported; any other overlap of out and u that Base.mightalias reports throws an ArgumentError. On arrays, prox!(x, f, x, γ) is supported and other sharing of memory is not, as for every function.

Exceptional parameters and values, for each group k:

  • wₖ = 0: unpenalized, the group is returned unchanged (NaN and ±Inf included), and its value is zero.
  • wₖ = Inf, or λ0 = Inf with wₖ > 0: the group is fixed at +0 at every nonnegative step, γ = 0 included, and for every input, NaN and ±Inf included. At γ = 0 this is the limit γ → 0+ with the function fixed, the projection onto the closure of its domain, as for NormL1(Inf) (#665). The value is zero at the zero group and Inf (or NaN at a NaN entry) elsewhere.
  • λ0 = 0 or γ = 0 (finite wₖ and λ0): the identity.
  • γ = Inf (positive finite λ0 and wₖ): the group is fixed at +0.
  • Positive finite γ, λ0 and wₖ: a group with a NaN entry becomes all NaN; a group with an infinite entry and no NaN is returned unchanged, since its norm is infinite and the threshold γλ0wₖ is finite, also when that product overflows in floating point; a zero group becomes +0.

For finite inputs, a norm whose sum of squares overflows or underflows, and a threshold γλ0wₖ outside the floating-point range, are recomputed in power-of-two units, so that a representable proximal point is returned accurately. Values follow the overflow rule in Overflow and underflow of values: for Float32 and Float64 values, a sum of group terms below K⋅floatmin, for K groups, is recomputed with each term's exponent, as for NormL1 (#373), and a value at or above floatmax/2 is recomputed in power-of-two units, accumulated in at least Float64; within a few eps of the overflow threshold the result may be floatmax or Inf, regardless of which of them the exact value rounds to (#904). value_and_prox! returns the value at the stored output.

The penalty does not apply to a SymmetricSparseIterate, and it has no restrict, no per-group step and no compact block method under Scaled.

Example

f = GroupNormL2(0.5, [1:3, [6, 4]])     # x[5] is not penalized
prox(f, randn(6), 1.0)
out = prox_block(f, [3.0, 4.0], 2, 1.0)  # (1 - 0.5√2/5) .* [3, 4]
