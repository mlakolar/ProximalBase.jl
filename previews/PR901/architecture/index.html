Package structure

The implementation separates mathematical function dispatch from iterate storage. An algorithm asks a function for a numerical operation and decides when to write the resulting values to an iterate. Private scratch/decomposition state belongs to functions; residuals, stopping policy and working sets belong to the caller.

The include order defines both iterate types in iterate_storage.jl before shared union dispatch and the sparse/symmetric implementations. Storage precedes the mathematical interface because explicit symmetric-iterate methods need the SymmetricSparseIterate type. Generic interface methods then combine with concrete implementations and final symmetric/array-step routes. There is no automatic device registration or removed-family plugin layer.

Representative call paths

Public callPrincipal retained path
prox!(y,NormL1(λ,w),x,γ)Checked separable boundary → dense/stored traversal → scalar prox_block → shrink
f(x) for custom SeparableFunctionParameter-extent validation (symmetric parameters are assumed, not compared) → entry values; skip inactive zeros only under declared promise
gradient!(g,LeastSquaresLoss(Y,X),β)Checked output → residual Xβ−Y → transpose-design product
prox!(y,QuadraticFunction(A,b),x,γ)Shape/type preflight → cached eigenbasis → diagonal inverse factors → output conversion
prox_block(f,u::AbstractVector,k,γ)Allocate plain floating Vector → user prox_block!
prox!(X::SymmetricSparseIterate,g,V,γ)Symmetric argument where needed → structural preflight (parameter symmetry is a model precondition) → the symmetric-coordinate kernel of the function, which follows the iterate activity rules
kkt_violation(g,grad,block,k)Retained scalar screen at each global member → maximum

Traits describe mathematical properties and capabilities; Julia concrete methods determine supported signatures. isseparable=true alone neither supplies entry hooks nor turns a full-vector function into a compact block oracle. Dispatch describes extension boundaries.

Public contracts and implementation details

Stable public contracts describe coordinate meanings, active-zero lifecycle, return values, alias restrictions and checked failure behavior. Fields, private wrapper names, scratch layouts, loop order/crossover thresholds and the layout cache are implementation details. They explain why the current implementation has its behavior; consumers must not depend on their representation.

Historical architecture SVGs included removed families, second-order layers and devices. They are retained in the immutable historical snapshot rather than displayed as current diagrams. The source map here matches the retained include graph. Current contract documents are authored in docs/design and rendered into Developer Documentation at build time.
