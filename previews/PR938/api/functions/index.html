Function reference

The function library gives dimensions, errors, numerical examples and capability limits for the available concrete function types.

Smooth array functions

ProximalBase.LeastSquaresLoss — Type
LeastSquaresLoss(Y, X)

Least-squares loss $f(β) = \lVert Y-X\beta\rVert^2/2$ with gradient X'*(X*β-Y). X is an n × p design matrix. A length-n response Y uses length-p coefficients; an n × k response uses p × k coefficients and the Frobenius norm. Data and arguments must be real and one-based.

The loss is smooth, convex and proximable. Dense arrays, SparseIterate and BlockIterate use their supported array products. The first proximal call caches a thin SVD; later calls reuse it for different steps, including when p > n.

Examples

julia> f = LeastSquaresLoss([1.0, -1.0], [1.0 0.0; 0.0 1.0]);

julia> f([3.0, 1.0])
4.0

julia> gradient(f, [3.0, 1.0])
2-element Vector{Float64}:
 2.0
 2.0

Edge cases

  • X and Y are retained by reference. After same-shape changes, call reset_cache! before another prox; reconstruct after dimension changes.
  • Values, gradients and prox reuse private scratch: synchronize concurrent calls on one loss. Supplied-predictor oracles have separate ownership rules.
  • No symmetric-iterate or scalar-coordinate prox is provided.
  • Value range recovery does not guarantee recovery of matrix products or SVDs.

See least-squares operations and supplied-predictor oracles.

ProximalBase.SqrNormL2 — Type
SqrNormL2(λ = 1)
SqrNormL2(λ, y)

Squared-distance function $f(x) = (\lambda/2)\lVert x-y\rVert^2$ with nonnegative level λ and center zero when y is omitted. For a matrix, the norm is Frobenius. This is the ridge penalty when uncentered, or half the squared error when λ = 1.

The function is smooth, convex and separable, with gradient λ*(x-y) and proximal point (x + γ*λ*y)/(1 + γ*λ). A supplied center is retained by reference and must have the same shape as x. Use real, one-based arrays; λ = NaN is invalid.

Examples

julia> f = SqrNormL2(2.0, [1.0, 0.0]);

julia> f([3.0, -1.0])
5.0

julia> prox(f, [3.0, -1.0], 0.5)
2-element Vector{Float64}:
  2.0
 -0.5

Edge cases

  • For a symmetric iterate, the center must be exactly symmetric; validate with ProximalBase.check_symmetric_parameters.
  • Exact in-place prox is supported; gradient output must be independent of its input.
  • An infinite level uses exceptional arithmetic, not a general projection rule. A zero level does not suppress every 0*Inf or 0*NaN in gradients or prox.

See squared-norm details and the numerical contract for supported precision, range recovery, restriction constants and non-finite values.

ProximalBase.QuadraticFunction — Type
QuadraticFunction(A, b = nothing, c = 0)

Quadratic function $f(x) = x^T A x/2 + b^T x + c$, with gradient A*x+b; omitted b is zero. Arguments are real, one-based vectors. A must be square and symmetric, and b must have matching length. Symmetry is a caller precondition: the constructor neither checks nor repairs it. Indefinite symmetric A is allowed.

The proximal point solves (I + γ*A)*y = x - γ*b using a cached eigendecomposition. For a negative computed minimum eigenvalue, the prox rejects a step whose rounded γ*(-λmin) is not less than one, raising DomainError before writing the output. This uses the effective step after scaling and conversion to the function's type. Near the spectral boundary, computed and exact positive definiteness can disagree.

Examples

julia> f = QuadraticFunction([2.0 0.0; 0.0 4.0], [1.0, -2.0]);

julia> f([1.0, 1.0])
2.0

julia> gradient(f, [1.0, 1.0])
2-element Vector{Float64}:
 3.0
 2.0

Edge cases

  • isconvex returns false: positive semidefiniteness is not certified. Solvers that require convexity must validate it, including after data changes.
  • A and b are retained by reference. Call reset_cache! after same-shape changes; reconstruct after dimension changes. The cached eigenbasis reads A's upper triangle, while values and gradients use A directly.

See quadratic operations and step domain for exact boundary qualifications, caching, alias rules and numerical limits.

ProximalBase.ZeroFunction — Type
ZeroFunction()

Zero function $f(x) = 0$ for an unpenalized problem. Its gradient is zero and its proximal operator is the identity. Real, one-based arrays are required; shape and output checks still apply.

Examples

julia> f = ZeroFunction();

julia> f([2.0, -1.0])
0.0

julia> prox(f, [2.0, -1.0])
2-element Vector{Float64}:
  2.0
 -1.0

Edge cases

  • Distinct matching sparse/block iterate inputs and outputs use copyto!, replacing destination activity, including stored zeros.
  • Symmetric-iterate proximal writes preserve destination activity; gradients at or into symmetric iterates are not implemented.

See zero-function operations for copying and step behavior.

ProximalBase.LinearFunction — Type
LinearFunction(c, d = 0)

Affine function $f(x) = \langle c,x\rangle+d$, with gradient c and proximal point x-γ*c. For matrices the inner product is Frobenius. Coefficients are real, one-based arrays retained by reference; size(c) must equal size(x), not just its entry count.

On a matrix SparseIterate, the value reads coefficients only at stored nonzero entries. Unstored entries and stored zeros add nothing, even against NaN or Inf. A Diagonal coefficient array visits only diagonal entries. These rules can differ from evaluating a dense copy; vector and symmetric iterates have their own rules.

Examples

julia> x = SparseIterate(2, 2); x[1, 1] = 2.0;

julia> f = LinearFunction([1.0 NaN; 1.0 1.0], 0.25);

julia> f(x)
2.25

julia> isnan(f(Matrix(x)))
true

Edge cases

  • Every oracle checks coefficient/input shape before writes.
  • For a symmetric iterate, c is an exactly symmetric p × p matrix; use ProximalBase.check_symmetric_parameters to validate it.
  • Exact in-place prox is supported; gradient output must be independent of input and coefficients. Array-step prox is not implemented.
  • Summation order is unspecified. Non-finite terms can change the result's IEEE class; extreme cancellation can exceed finite-value recovery guarantees.

See linear operations and sparse values for the summation, cost and accuracy contract.

Least-squares oracles at a supplied predictor or residual

The qualified public names below evaluate a vector-response LeastSquaresLoss, or one Scaled of it, at a linear predictor or a residual that the caller has already formed. They are not exported.

ProximalBase.value_from_predictor — Function
ProximalBase.value_from_predictor(f, z)

Evaluate the least-squares value α*sum(abs2, z-Y)/2 from a predictor z = X*β already computed by the caller. Here α = 1 for a LeastSquaresLoss, or is the factor of one Scaled wrapper. No design entries are read and no loss fields are written. Scratch is not accessed separately; z may be a view of it.

Use a vector-response loss with strided Float32 or Float64 data of one type T, and a StridedVector{T} predictor with the response's axes. Other types throw MethodError; mismatched axes throw DimensionMismatch. The result is T.

Examples

julia> f = LeastSquaresLoss([1.0], reshape([2.0], 1, 1));

julia> ProximalBase.value_from_predictor(f, [3.0])
2.0

Edge cases

  • A scale must be positive finite Float32/Float64, or an integer exactly representable as Float64; other factors throw ArgumentError.
  • A non-finite predictor gives a non-finite value; the call does not recompute X*β.
  • Finite-input value recovery has explicit rounding and overflow-boundary limits.
  • Calls write no loss fields and can share one loss across tasks while its data remain unchanged. The ordinary path allocates nothing for raw losses and Float32, Float64 or Int scales.

See predictor domains, accuracy and ownership and ProximalBase.value_from_residual.

source
ProximalBase.value_and_gradient_from_predictor! — Function
ProximalBase.value_and_gradient_from_predictor!(g, d, f, z)

Write residual d = z-Y and gradient g = α*(X'*d) from the caller's predictor z = X*β, and return α*sum(abs2, d)/2. This forms one product with X' and none with X; no loss fields or private scratch are written.

Use the domain and scale of ProximalBase.value_from_predictor, with strided vectors g, d and z of the data type. z and d have the response's axes; g has length size(X, 2) and must be one-based.

Examples

julia> f = LeastSquaresLoss([1.0], reshape([2.0], 1, 1));

julia> g = zeros(1); d = zeros(1);

julia> ProximalBase.value_and_gradient_from_predictor!(g, d, f, [3.0])
2.0

julia> (g[1], d[1])
(4.0, 2.0)

Edge cases

  • Outputs must not overlap each other, the predictor, design, response or loss scratch. Nonempty overlaps reported by Base.mightalias are rejected; undetected sharing remains the caller's responsibility. In-place d === z is not supported.
  • Length/axis, factor and overlap checks precede writes.
  • Overflow/underflow in X'*d is not recovered before applying α. Overflow in z-Y makes the value non-finite, even where the standalone predictor value can recover it. Last-bit agreement is not promised.

See predictor accuracy, failure and concurrency rules.

source
ProximalBase.value_from_residual — Function
ProximalBase.value_from_residual(f, r)

Evaluate α*sum(abs2, r)/2 from a least-squares residual already held by the caller. Either sign, r = X*β-Y or r = Y-X*β, is accepted. No design or response entries are read and no loss fields are written. Scratch is not accessed separately; r may be a view of it.

Use the loss, scale and strided floating-point domain of ProximalBase.value_from_predictor. The residual must have the response's axes (DimensionMismatch otherwise). The result type, accuracy, allocation and concurrency guarantees are the same, with non-finite residuals producing non-finite values.

Examples

julia> f = LeastSquaresLoss([1.0], reshape([2.0], 1, 1));

julia> ProximalBase.value_from_residual(f, [-2.0])
2.0

See predictor and residual operations.

ProximalBase.leastsquares_data — Function
ProximalBase.leastsquares_data(f)

Return borrowed least-squares data as (; Y, X, α). Y and X are the stored arrays themselves, with no copy or conversion. The scale is one(T) for a LeastSquaresLoss of type T, or the stored factor of one Scaled wrapper, with its original type.

Any LeastSquaresLoss is accepted, including data outside the strided domain of the predictor oracles. Other functions throw MethodError. This accessor does not validate or convert the scale; the predictor oracles can reject it or use its converted value.

Examples

julia> y = [1.0]; X = reshape([2.0], 1, 1);

julia> data = ProximalBase.leastsquares_data(LeastSquaresLoss(y, X));

julia> (data.Y === y, data.X === X, data.α)
(true, true, 1.0)

Do not mutate the borrowed arrays while the loss or any of its oracles is in use, including on another task. See ownership rules.

Entrywise ℓ₁ norm and elastic net

ProximalBase.NormL1 — Type
NormL1(λ0 = 1)
NormL1(λ0, w)

Weighted ℓ₁ penalty $f(x) = \lambda_0\sum_i w_i |x_i|$, with all weights equal to one when w is omitted. The level and weights must be nonnegative and not NaN. Weights are retained by reference and paired with entries by linear index.

prox applies entrywise soft thresholding (shrink) with threshold $\gamma\lambda_0 w_i$. The function is separable and zero-preserving; value and same-kind sparse-iterate prox calls visit only stored entries.

Examples

julia> f = NormL1(0.5, [1.0, 2.0]);

julia> f([2.0, -1.0])
2.0

julia> prox(f, [2.0, -1.0], 1.0)
2-element Vector{Float64}:
 1.5
 0.0

Edge cases

  • Use real, one-based arrays and one weight per entry.
  • On a SymmetricSparseIterate, weights have p² entries in full-matrix linear order, interpreted as an exactly symmetric p × p array. Oracles assume this; validate with ProximalBase.check_symmetric_parameters.
  • A zero weight leaves an entry unpenalized. An infinite weight fixes a finite input at zero, but can return NaN for non-finite inputs at finite level.
  • An infinite overall level fixes positive-weight entries at +0, even for non-finite inputs and zero step; zero-weight entries remain free.

See ℓ₁ endpoint rules, the numerical contract and prox! for step and alias rules.

source
ProximalBase.ElasticNet — Type
ElasticNet(λ1, λ2)
ElasticNet(λ1, λ2, w)

Elastic-net penalty $f(x) = \lambda_1\sum_i w_i|x_i|+(\lambda_2/2)\sum_i x_i^2$. The levels and weights must be nonnegative and not NaN; omitted weights are one. Weights are retained by reference, one per entry in linear order.

The proximal operator soft thresholds each entry and applies ridge shrinkage: shrink(x[i], γ*λ1*w[i]) / (1 + γ*λ2). It uses the numerical kernels of NormL1 and SqrNormL2. The function is convex, separable and zero-preserving; λ2 = 0 recovers NormL1 values and nonnegative-step proximal points bit for bit.

Examples

julia> f = ElasticNet(1.0, 2.0);

julia> f([2.0, -1.0])
8.0

julia> prox(f, [2.0, -1.0], 0.5)
2-element Vector{Float64}:
  0.75
 -0.25

Edge cases

  • Use real, one-based arrays. Symmetric-iterate weights must be exactly symmetric; validate with ProximalBase.check_symmetric_parameters.
  • Negative/NaN scalar steps fail before writes. Array-step entries and scalar prox_block steps are not checked; nonnegative steps are a caller precondition.
  • λ2 = Inf fixes every output at +0, including non-finite inputs and zero step. Infinite ℓ₁ levels and weights follow the distinct NormL1 rules.
  • Array steps with a symmetric iterate and compact-vector prox_block are unsupported.

See elastic-net details and step and endpoint rules for rounding, storage and range limits.

ℓ₂ and group ℓ₂ norms

ProximalBase.NormL2 — Type
NormL2(λ = 1)

Euclidean-norm penalty $f(x) = \lambda\lVert x\rVert_2$; for a matrix, use the Frobenius norm. The level must be nonnegative and not NaN. Its proximal operator shrinks the whole argument: $\max(1-\gamma\lambda/\lVert x\rVert_2,0)x$. Use GroupNormL2 to shrink separate groups.

Values accept real, one-based arrays and the three iterate types. Sparse and symmetric values read only stored entries; symmetric off-diagonal coordinates count twice in the squared norm. Proximal calls accept arrays of the same size, a nonnegative scalar step and exact input/output identity.

Examples

julia> f = NormL2(1.0);

julia> f([3.0, 4.0])
5.0

julia> prox(f, [3.0, 4.0], 5.0)
2-element Vector{Float64}:
 0.0
 0.0

Edge cases

  • No proximal operator is provided for SymmetricSparseIterate.
  • Invalid shapes, real types, one-based axes and negative/NaN steps are checked before writes. Other overlapping input/output buffers are unsupported.
  • λ = Inf fixes every output at +0, including at zero step and non-finite input.
  • Otherwise, zero level or zero step gives the identity. At positive finite level and step, a NaN entry makes the entire result NaN.

See ℓ₂ operations, group endpoint rules and the numerical contract for the remaining endpoints and range limits.

source
ProximalBase.GroupNormL2 — Type
GroupNormL2(λ0, groups)
GroupNormL2(λ0, groups, w)

Group-lasso penalty $f(x) = \lambda_0\sum_k w_k\lVert x[G_k]\rVert_2$, with default weights $w_k = \sqrt{|G_k|}$. Groups are nonempty, disjoint lists or ranges of positive linear indices. Their order is preserved; entries in no group are unpenalized. The nonnegative level and weights cannot be NaN. Supply one weight per group; the constructor copies groups and w.

prox shrinks each group toward zero using a nonnegative scalar step. prox_block takes a compact vector in groups[k] order; it does not update an iterate. To commit its result, use copyto!(blockview(x, k), out). See group operations for the formula and KKT screen.

Examples

julia> f = GroupNormL2(1.0, [1:2], [1.0]);

julia> f([3.0, 4.0])
5.0

julia> prox_block(f, [3.0, 4.0], 1, 5.0)
2-element Vector{Float64}:
 0.0
 0.0

Edge cases

  • Real, one-based arrays and valid shapes/groups are required. Negative or NaN steps fail before writes.
  • Exact in-place prox is supported. For compact blocks, out === u is supported; other reported overlaps are rejected, and out must not alias iterate storage.
  • Zero-weight groups stay unchanged. Infinite weights or an infinite level with positive weight fix a group at +0, including at zero step.
  • No SymmetricSparseIterate, restrict, per-group steps or compact block method under Scaled.

See group endpoint rules and the numerical contract for non-finite inputs and range limits.
