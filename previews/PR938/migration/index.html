Compatibility and migration

For terms used in the current manual, see the Glossary.

This manual describes the minimal core after merged PR #850, based on 2b373c54. The full post-#848 implementation and its documentation are preserved at eff21b6d7d33c622313122f46c6ee71693c101ee and legacy/full. Those archives are historical references, not a second live API. This development reduction is not a release announcement.

Retained and removed scope

The function library is exhaustive. Norms and group penalties other than NormL1, NormL2, NormLinf and GroupNormL2, nonconvex penalties, logistic/Poisson/robust-loss families, constraints and indicators, spectral/nuclear families, generic composition/sum wrappers, LMO, second-order frameworks and GPU extensions were removed. They have no replacement capability implied by this manual. BlockIterate retains grouped storage; the group-lasso penalty GroupNormL2 and the norm NormL2 were restored separately (#900), and the norm NormLinf separately (#946), without the other group penalties and norms.

Keep two function objects for f(x)+g(x); no generic function-object sum is retained. Compute mathematical gradient mappings in caller code. Coordinate curvatures and residual/working-set policies are algorithm responsibilities. ProximalSolvers migration is separate; this documentation does not change it.

Removed scalar-loss interface (0.6, breaking)

ProximalBase 0.6 removes the qualified-public ProximalBase.ScalarLoss and ProximalBase.Squared types and their scalar derivative interface (ProximalBase.deriv, ProximalBase.deriv2, ProximalBase.curvature, ProximalBase.value_and_deriv) (#916). No retained loss in ProximalBase used them, and the names were not exported. A qualified reference such as ProximalBase.deriv, a subtype declaration <: ProximalBase.ScalarLoss, and a qualified method definition such as ProximalBase.deriv(ℓ::MyLoss, η, y) = … raise UndefVarError. What import or using of these names reports, and what a later unqualified method definition does, depends on the Julia version and the form used. For least squares, use LeastSquaresLoss and its predictor/residual operations (ProximalBase.value_from_predictor, ProximalBase.value_and_gradient_from_predictor!, ProximalBase.value_from_residual, ProximalBase.leastsquares_data; see Least squares at a caller-held predictor or residual). For squared-norm regularization, use SqrNormL2. Code that relied on this interface can implement the operations it needs through the AbstractFunction interface, or keep its own scalar-loss types and functions.

Changed traits and proximal domains

CallBeforeNow
isconvex of QuadraticFunction, its type or an instance, and of Scaled of it (#919)truefalse, which means that convexity is not guaranteed for an arbitrary instance; f is convex when the symmetric A is positive semidefinite
prox!, prox and value_and_prox! of QuadraticFunction, directly or through Scaled, when the smallest eigenvalue λmin of the cached decomposition of A is negative and the rounded product γT·(-λmin) is not < 1 (a NaN step included), where γT is the step after the factors of any Scaled are applied, converted to the element type of the function (#919)Unchecked spectral division by 1 + γλi, which could return non-finite values or finite values that are not the proximal pointDomainError before the output is written

A symmetric A need not be positive semidefinite. The check applies to a singular positive semidefinite A whose computed λmin is slightly negative from rounding, at steps with γT·(-λmin) ≥ 1 (about γ ≥ 1/|λmin|); at those steps the earlier kernel divided by a computed denominator 1 + γT·λmin ≤ 0. A matrix with λmin ≥ 0, and a negative step, are not checked and behave as before. For a nonnegative finite γT and finite cached eigenvalues, the check accepts exactly when every computed denominator 1 + γT·λi is positive. In exact arithmetic and for γ > 0, the proximal subproblem has a unique minimizer if and only if 1 + γ λmin(A) > 0 for the true smallest eigenvalue, so near that boundary the check can accept a step for which the true I + γA is not positive definite, and reject one for which it is.

A caller that knows A ⪰ 0 and relies on convexity asserts it at its own model boundary, and does so again after changing A. A successful prox does not establish convexity.

Historical contracts

Current developer contracts are reconciled against retained methods and tests. Historical acceptance records remain available at the immutable archive, including pending requirements and measured experiments. They are not automatically current guarantees. Numerical endpoints, aliasing and decomposition caches must follow the retained numerical contract.
